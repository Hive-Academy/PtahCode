## Minimal fix and regression sequence

1. In `session-query-executor.service.ts`, preserve a structured watchdog end reason when aborting for no activity (including compaction dwell); do not rely on text surviving SDK/stream error wrapping. In `chat-stream-broadcaster.service.ts`, classify that reason ahead of generic abort, and reserve `user-stop` for an explicit `chat:abort`/tab-close or spawner stop. Route no-activity to a distinct timeout cause or at least `stream-exit`/`provider-error`; keep real user abort behavior. Update cause types/words in `session-child-outcome.ts` if adding a cause.
2. In `session-spawner.service.ts:onGraceExpired/endOutside`, signal or hold a terminal completion for unexpected child ends, once per child, before resource release; preserve the existing report and avoid duplicate turn completion. The parent should receive the outcome even when automatic succession fails.
3. Regression: start parent and child, steer the child once, simulate 180 seconds of stream silence, assert no explicit stop call, assert non-`user-stop` cause and a single parent terminal completion; resume the same SDK ID on the same tab and verify no stale grace timer ends it. Repeat with explicit Stop to assert `user-stop`, and with parent old-tab record restart/second tab to assert the child stays live. Check that a queued follow-up and a sidebar refresh do not call abort.
