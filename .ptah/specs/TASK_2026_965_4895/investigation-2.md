`NoActivityWatchdog.observeHook` stores a **root** `PreToolUse` by `tool_use_id`, deletes it on `PostToolUse`/failure, ignores nested `agent_id` (`no-activity-watchdog.ts:131–159`). The hook list is unfiltered by tool name (`:103–128`), so it is intended to cover **both MCP and Bash**; `sdk-query-options-builder.ts:2415–2428` merges these into SDK hooks, and `:1332–1340` only holds while `canUseTool` itself awaits. An approved `canUseTool` at log 31633 is therefore **not** a hold for the ensuing Bash process. `stream-transformer.ts:654–685` starts the timer and passes every yielded SDK message to `observe`; `no-activity-watchdog.ts:162–174,255–259` observes tool *results* but does not register assistant `tool_use` blocks. At expiry, only `tools`/compaction prevent firing (`:261–290`). Because it fired despite the transcript's open root call, that call was absent from its `tools` map at expiry. The available log does not expose lifecycle-hook delivery, so whether `PreToolUse` was missing, ignored, or later cleared cannot be distinguished. The direct, sufficient gap is that a visible root `tool_use` is not tracked from the stream. **Minimal fix:** in `NoActivityWatchdog.observe`, register root assistant `tool_use` blocks by ID/name before arming; keep hooks as an early signal and `tool_result`/post hooks as terminal reconciliation. This covers Bash and MCP even if a lifecycle hook is missed. Preserve nested-message exclusion and result/turn cleanup.

## 3. Stale parent status

The child record became terminal after the watchdog (`investigation.md`; log **31991, 32036–32037**). `SessionChildRegistry.markEnded` makes terminal status first-writer-wins (`session-child.registry.ts:357–380`); only failed-succession rollback clears it (`:425–443`). On resume, `SessionSpawnerService.onSessionIdResolved` merely binds the SDK ID and cancels a grace timer (`session-spawner.service.ts:1298–1312`); it does not reactivate the terminal record. `activeIdOf` can detect the newly active adapter session (`:1829–1837`), but `statusOf` returns `terminalStatus` first (`:1786–1792`). That is why `ptah_session_status` continues to say **Stopped** while the SDK works. Turn events use `liveChildForEvent`, which rejects terminal records (`:1768–1783`); `send` rejects terminal children (`:819–839`), and later settlement/completion signaling is bypassed. The parent can still receive a direct report if the report router accepts the tab, but it gets no normal child turn status, completion signal, or steering through this terminal record.

A contained fix needs an explicit **resume/reopen transition** keyed by tab and same SDK ID when the adapter starts a new query: clear terminal fields and ended-order membership, recreate runtime/resources needed for send and turn events, and update the parent-visible status before accepting further events. Merely changing `statusOf` to consult `activeIdOf` would display Working while `send` and callbacks still reject it. If terminal records are intentionally immutable, model the resumed query as a successor child record and route parent ownership/signals to that successor; that is a broader registry redesign.
