## New defects

1. **Blocking — A failed drain admits a fresh report after the owner changes.** `cli-agents/agent-report-router.service.ts:846`, `:898`, `:1099`. Hold A for P0. With P0 live, submit fresh report B and pause the send of A. Reparent the child to P1 and reject A's send. The catch restores A and returns `failed`; the caller holds B before checking the owner and acknowledges it as pending. P1 can subsequently receive B even though this attempt had to be refused. **Fix:** Validate an owner revision before every hold, including after a failed drain. Restore the older suffix and refuse the fresh report if ownership changed.
2. **Serious — An unrelated child's send can block the active parent's only flush.** `cli-agents/agent-report-router.service.ts:966`, `:1089`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-session-controls.ts:65`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-adapter.ts:1071`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-peer-queue.ts:131`, `:172`. Hold reports for children A and B in that order under different parents. Let A's Codex parent be busy when B's parent emits activity. The event now drains A first. Codex reports A's parent as active but leaves the send pending behind its busy turn. If B's parent goes idle before that send resolves, the sweep reaches B too late, and B waits for another event. **Fix:** Schedule each indexed child's drain independently, coalesce repeated activity per child, and keep the per-child admission lock.
