# Ptah Glass: component refinements

Design-only handoff for the existing Electron renderer. Apply these values under the current `data-glass='on'` gate, preserve `ptah-glass` / `ptah-glass-light`, `--b1`/`--bc` DaisyUI v4 names, `.surface-*`, all existing class names, and chat layout. No new theme or parallel token set is required. Shared control APIs are specified in [the component plan](component-system-plan.md). See [audit](existing-system-audit.md).

## Principles

1. Preserve the readable, quiet chat planes. Reserve translucency for floating chrome and overlays; keep long-form text on a local scrim. This follows the existing role split (`styles.css:2813-2817,3193-3216`).
2. Add a *small* specular top rim, inner highlight and soft shadow to controls already styled by glass v2. The [Liquid Glass UI reference](https://liquidglassdesign.com/ui) suggests translucent tint, backdrop blur/saturation, light-catching edges and gentle motion. These are visual cues, not a layout or brand replacement.
3. A highlight communicates shape; color and text communicate meaning. Preserve solid semantic success/error text and the primary action hierarchy.

For solid themes, leave `.surface-*` and DaisyUI default behavior intact.

The existing `data-glass-surface` values are already `chrome`, `bar`, `overlay`, `content`, `tile`, `plate` (`styles.css:2813-2817,3184-3216`). **Do not add a seventh tier now.** Map component scale to these values: floating chrome = `chrome`/`bar`, popups = `overlay`, reading cards = `content`, inner stat/tool tiles = `tile`, short label backing = `plate`. Tailwind's `bg-surface-*`, `border-surface-border`, `text-base-content` and `text-base-content-muted` continue mapping through `--surface-*`, `--bc` and `--bcm` (`styles.css:159-171,389-411`). DaisyUI v4 semantic classes still read `--p`, `--pc`, `--b1`, `--bc`; do not introduce v5 `--color-base-100`.

### Component recipe

For small controls, use `box-shadow: inset 0 1px 0 var(--glass-glint-control), var(--glass-shadow-control)` and a 1px border using the current line; hover changes border to `--glass-line-hover` and background to `--glass-hover`; active background uses `--glass-press` and drops the outer shadow. Apply only to existing glass-enabled selectors, never all `.btn` or `.card` across themes. Large pane `::before`/`::after` are already occupied by rim and blur; do not add another pseudo-element to them.

## Where glass lives

Glass is applied **only inside L1/L2 primitives**: button, field/control, dropdown panel and surface. Pages choose a semantic role or component; they never add per-page blur, rim, tint or glass utility classes. The existing `data-glass='on'` gate and six `data-glass-surface` roles own translucency (`styles.css:2813-2817,3184-3216`); a control inside a blurred panel gets a rim and scrim but no second `backdrop-filter`. L2 `chrome/bar/overlay` may sample the backdrop once, while `content/tile/plate` and scrolling rows stay stable (`styles.css:3134-3158,3247-3272`).

Tone changes semantic tint, not behavior.

| `ghost` | `btn btn-ghost`; transparent rest, no outer shadow; hover receives `var(--glass-hover)` and `var(--glass-line-hover)`. |

### Dropdown panel and option rows

Use `ptah-native-dropdown`/popover and `FloatingUIService` for positioning (`core-controls-reuse-map.md:40-57`). The panel alone sets `data-glass-surface='overlay'`, Daisy `dropdown-content`/`menu` or listbox anatomy, `background: var(--glass-field-scrim)` over the existing overlay fill, `border: 1px solid var(--glass-edge-control)`, `box-shadow: inset 0 1px 0 var(--glass-glint-control), var(--glass-shadow-control)`; the existing overlay role owns its single blur. A long scroll list and its rows never blur individually.

| Option state/anatomy | Exact recipe and semantics |
|---|---|
| Rest / hover | Row is transparent at rest with readable `--bc` text. Hover adds `background: var(--glass-hover)` and `border-radius: var(--glass-radius-sm)`; pointer hover alone does not change active descendant. |

| Selected | Persist `background: var(--glass-sel)` and semantic checkmark/text; `aria-selected` for listbox/select, `aria-checked` only for checkable menu item. Selected and active can coexist; keep focus edge. |
| Disabled / reason | `aria-disabled=true`, muted ink with sufficient contrast, no hover/activation; render `disabledReason` in a projected secondary slot and expose it through `aria-describedby` when focusable. |
| Group / empty / loading | Group header is nonoption text in `--bcm`, small semibold, `role=group` label association; chat grouped suggestions supply anatomy (`unified-suggestions-dropdown.component.ts:65-139`). **Fallbacks for all three families:** `prefers-reduced-transparency: reduce`, `data-glass-effects='off'`, or missing `backdrop-filter` gives panel/control `background: oklch(var(--b1) / .98)`, no backdrop filter/grain, visible 1px edge; button semantic primary/danger remain opaque. `prefers-reduced-motion: reduce` sets transition/animation duration to `0ms`, no transform; forced colors uses `Canvas`/`CanvasText`, `Highlight` for selected/active, `2px solid Highlight` focus, `ButtonText`/`GrayText` where appropriate, no shadow, grain, or translucent fill. Check composited AA text/control contrast rather than claiming token ratios (`styles.css:2928-2939`; `design.md:75-77`).

## Accessibility and performance

- WCAG AA: normal text ≥4.5:1, large text ≥3:1, control edges/focus ≥3:1. Validate against the brightest and darkest scene pixels with the **composited** scrim; raise `--glass-field-scrim` or `--glass-scrim-text` alpha locally until it passes. Do not claim a ratio from token values alone.
- `@media (prefers-reduced-transparency: reduce)` and existing `data-glass-effects='off'`: set chrome/overlay fill to `oklch(var(--b1) / .98)`, remove backdrop filters and grain, retain visible border. `@supports not (backdrop-filter: blur(1px))` already has a base fallback (`styles.css:2928-2939`); extend it to new control refinements. `@media (prefers-reduced-motion: reduce)`: duration 0ms and no transform. `@media (forced-colors: active)`: `Canvas`/`CanvasText`/`Highlight`, system outline, no shadow/grain.
- Electron Chromium: at most two stacked backdrop samplers in one viewport (outer chrome plus one overlay). Never blur scrolling list rows, cards, chat messages or tool tiles. Avoid animating `backdrop-filter`, `box-shadow` on large panes, or `will-change` left on by default. New motion changes only opacity/color/border/transform on small controls. The current glass layer already uses pseudo-element sampling (`styles.css:3134-3158`); preserve its stacking/z-index fixes (`styles.css:3247-3272`).

## Design system for Stitch

Ptah Electron renderer, DaisyUI v4. Dark theme `ptah-glass`, light theme `ptah-glass-light`; amber/gold primary from `--p`, readable ink from `--bc`, muted ink from `--bcm`, bases `--b1/--b2/--b3`. Typography: Inter UI, JetBrains Mono for code, Cinzel only decorative brand. Radii: small 10px, inner card 14px, floating pane 22px, segmented/pill 9999px. Surfaces: `chrome` or `bar` for floating shell, `overlay` for popup/dialog, `content` for reading, `tile` for nested stat/tool, `plate` for short text backing. Components: DaisyUI v4 `btn`, `input`, `textarea`, `select`, `card`, `badge`, `tabs-boxed`, `menu`, `modal-box`, `alert`, `stats`; existing Ptah `surface-1/2/3`. Motion 140ms ease on small controls; no blur animation. Accessibility: minimum text scrim, visible 2px focus, solid reduced-transparency fallback.

Stitch mapping: label each generated region with an existing role, map visual colors to DaisyUI semantic variables and existing `surface-*` utilities, then map element anatomy to the listed DaisyUI classes. Treat one-off glow, new theme names and unlabelled translucent text as deviations to review. The plain-markdown section above can be passed as design-system input to Stitch `upload_design_md` / `create_design_system_from_design_md` without inventing replacement tokens.
