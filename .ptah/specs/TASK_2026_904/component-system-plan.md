# Unified component system plan — Electron renderer

## Top-down plan (current)

`polish-map.md` governs tiers, sources, consumers, and Electron states. #1028 merged at `bcd76af07` and is the baseline. This branch predates it; inspect merged code with `git show bcd76af07:<path>` when needed.

### Contract and order

- Chat, canvas, voice, and setup are polished sources. Preserve their DOM, CSS, spacing, focus, motion, and glass roles exactly. Voice shares chat chrome; check its tab and action states. Do not adopt #1028 generic controls on these pages.
- Move markup and styles as-is into `libs/frontend/ui` where the dependency boundary fits; existing `native/`, `surfaces/`, `foundation/`, and `overlays/` placements may fit. Keep domain state and services in the feature. Shared UI remains safe for Electron and other hosts.
- Use named projection slots, `ngTemplateOutlet` and typed `TemplateRef` contexts, `hostDirectives`, and `provide*()` InjectionToken look defaults. The source gets its exact look by default. No inheritance or speculative variant matrix.
- Extract on the polished source first; its page imports the component with its default look. After a zero-pixel Electron diff, adopt on machines and reviews, then semi pages: marketplace, Thoth, tasks, Settings, analytics, apps, command center.
- Create a token or primitive only after an extraction is shared by 2+ pages. For a second look, use a slot, template context, or look default. If both looks cannot hold, leave the candidate local.
- Preserve native semantics, IME, focus, Escape return, disabled state, keyboard use, reduced motion/transparency, and glass roles. `@angular/aria` supplies headless behavior only. Keep one blur owner.

### Per-component extraction checklist

1. Choose one source and first consumer below. Record DOM/classes, styles, states, and feature behavior. Keep feature data and action policy local.
2. Capture baseline Electron screenshots of the named source states. Fix viewport, theme, glass mode, data, fonts, animation, scroll, pointer, and focus. Include shared chat/voice states. Guarded consumer routes need an eligible host.
3. Move markup and styles verbatim. Preserve DOM order, classes, events, and glass role. Add only source-needed inputs/outputs and slots/templates. Default to the source look.
4. Have the source page import the extraction with its default look and domain handlers. Check host layout, style scope, focus, and overlay placement.
5. Re-capture each named state. Require **zero changed pixels on the polished source**. Fix any difference before adoption; check behavior and accessibility too.
6. Adopt on machines or reviews where anatomy fits, then listed semi pages. Keep consumer behavior local. Re-diff the source after adding any consumer look.
7. Consider a token/primitive only after 2+ pages share the extraction. Add it to the gallery with its source reference.

### Risks and verification for implementation

- The central risk is a source-page visual regression from an added host element, scoped CSS change, inherited style, overlay repositioning, or altered glass role. The zero-pixel Electron screenshot diff on every named polished state is the gate before consumer adoption. Record baseline and result artifacts with the implementing change. Check both themes and glass modes where the source uses them; match fonts, viewport and state exactly.
- Keep source semantics and behavior alongside pixels: native button and input attributes, IME, keyboard navigation, dialog focus, Escape return, disabled state, reduced motion and transparency. Interaction checks accompany the screenshot gate; a pixel match alone cannot prove behavior.
- A poor-page consumer may have different anatomy. Skip an incompatible adoption, or add a consumer look through slots/templates/defaults while repeating the source diff. Do not alter chat, canvas, voice, or setup to make a poor page easier to migrate. Keep domain services out of `libs/frontend/ui` and preserve shared-host compatibility.
- For implementation only, run scoped `npm run verify -- -p <projects>` for touched projects, in bounded batches. This design-only revision runs no build, serve, dev, e2e, package, or verification command. Gallery inspection and type/lint checks support the work; Electron screenshot diffs decide source visual fidelity.

## Shared language (SUPERSEDED — bottom-up, rejected 2026-11-09)

One public role has one selector; a domain adapter may keep its name while composing that selector. Existing aliases remain during migration, then retire. This vocabulary is grounded in `core-controls-reuse-map.md:9-20,24-36,40-59` and `foundation-1028-assessment.md:180-219`.

| Role | Canonical selector | Replaces or composes |
|---|---|---|
| Action | `button[ptahButton]`, `a[ptahButton]` | Raw `btn` actions in machines/reviews; chat send/stop and canvas rail keep domain state |
| Field | `ptah-field` + `input[ptahInput]`, `textarea[ptahTextarea]`, `select[ptahSelect]` | PR `[ptahFieldControl]` becomes facade; local search/forms and composer skin |
| Choice overlay | `ptah-native-dropdown` shell; `ptah-select-picker`, `ptah-combobox`, `ptah-menu`, `ptah-command-palette` | Task view menu/palette, chat unified suggestions, branch/model pickers; domain data stays local |
| Surface and metric | `ptah-surface-card/section/tile`, `ptah-stat-card` | Local card/section/stat recipes, including marketplace selector collision |
| Status and feedback | `ptah-badge`, `ptah-execution-status`, `ptah-alert`, `ptah-state-panel` | Eight chips, local banners/stale notices; chat execution badge gets distinct name |
| Navigation and overlay | `ptah-list-detail`, `div[ptahListRow]`, `ptah-page-header`, `ptah-toolbar`, `ptah-native-tab-group`, `ptah-native-modal`, `ptah-native-drawer` | Local list/header/tab/dialog shells and seven confirm flows |

**Composition contract:** signal inputs cover only visual axes (`variant`, `size`, `tone`, `shape`) and genuine state (`busy`, `pressed`, `disabled`, `value`, `open`); do not expose arbitrary class strings or feature data models. Project `[leading]`, `[trailing]`, `[trigger]`, `[content]`, `[hint]`, `[error]`, `[actions]` for structure. Repeated item rendering takes `TemplateRef<PtahOptionContext<T>>`, with typed `$implicit`, `active`, `selected`, `disabled`, `index`, and optional `disabledReason`; `ngTemplateOutlet` owns rendering, while Aria owns option behavior. Compose behavior with `hostDirectives` for busy/pressed, glass role, and focus management, checking Angular Aria host eligibility after installation. `providePtahControls()` and `providePtahOverlay()` use InjectionTokens for area defaults (density, chat style, overlay motion); local explicit inputs win. No class inheritance. Chat style is a provider preset for geometry, not a separate button implementation.
