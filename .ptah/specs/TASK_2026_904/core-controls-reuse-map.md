# Core controls reuse map

Research only, 2026-11-09. Scope: Electron renderer and `libs/frontend/*`. Direction change 3 asks for one composable shared language, reuse of advanced controls, and migration from poor to polished pages (`context.md:34-46`). PR #1028 remains a proposal, not assumed merged. Keep DaisyUI/Tailwind and glass v2 in `apps/ptah-extension-webview/src/styles.css` (`component-system-plan.md:9-14`).

**Counts:** Raw counts below come from `duplication-inventory.md:5,9-11,52` and are overlapping floors, not unique elements. Shared counts are literal `<selector` opening-tag hits from `rg` across non-spec `.ts/.html` in `libs/frontend` and the webview; they may include examples in comments. Ratings judge reuse quality from source, not rendered polish. Feature gaps marked `—` were not found in inspected source.

**Reference:** extend PR `PtahButtonDirective`, taking icon geometry from canvas/chat and visible busy behavior from composer. Keep chat's queue logic local. The directive should own DaisyUI mapping; glass rim/glint is shared CSS under the existing glass gate, without another blur within a glass panel (`component-system-plan.md:14,22`). Raw `.btn` recipes become call sites.

**API sketch:** `button[ptahButton]` signal inputs `variant: solid|glass|glass-tinted|ghost|outline|link`, `tone: neutral|primary|danger|success`, `size: xs|sm|md|lg`, `shape: default|square|circle`, `busy`, `pressed`; alias PR `primary/secondary/danger` variants during migration. Native child content is label; a wrapper can project `[leading]`, `[trailing]`, `[spinner]`. `aria-pressed` for toggle, accessible name for icon-only, `aria-busy`, guarded activation and spinner are common. `providePtahControls({buttonDefaults})` sets look; a `ptahButtonState` hostDirective may let domain buttons share state styling. Retain native `<button>` behavior.

**Reference:** keep PR `[ptahFieldControl]` as compatibility facade delegating to one native skin. Reuse `ptah-field` for ordinary labeled forms. Extract composer autosize/combobox as opt-in behavior, not baseline textarea. Native select serves simple options; advanced choices use dropdown family.

**API sketch:** `input[ptahInput]`, `textarea[ptahTextarea]`, `select[ptahSelect]` share `ptahControlSkin` hostDirective or the extended `[ptahFieldControl]`: signal `size: xs|sm|md|lg`, `variant: bordered|plain|glass`, `tone: neutral|error|success|warning`, `shape: default|pill`. `ptah-field` projects `[control]`, `[prefix]`, `[suffix]`, `[hint]`, `[error]`, wires label/`aria-describedby`/invalid. `ptah-search-field` composes leading icon, clear action, optional loading. `textarea[ptahComposerInput]` opts into autosize/combobox bindings. `providePtahControls({fieldDefaults})` changes look only. Preserve value/type/autocomplete/disabled/readonly/IME.

**Reference:** compose native dropdown/popover and `FloatingUIService` (`ui/src/lib/native/shared/floating-ui.service.ts:30,86,182-196`) with native autocomplete/keyboard service. CDK overlay source explicitly notes VS Code webview portal issues (`ui/src/lib/overlays/dropdown/dropdown.component.ts:18`; `overlays/popover/popover.component.ts:24`). Take group headings from chat suggestions, disabled reasons/ranking from task palette, and domain data from existing pickers. Menus need `role=menu/menuitem` keyboard behavior, not a relabeled listbox. No inspected shared component demonstrates virtual scroll or multi-select; defer those as opt-ins. `@angular/aria`/`ngOption` from PR #1028 can supply headless list behavior but does not replace Electron-safe positioning.

**API sketch:** retain `<ptah-native-dropdown [isOpen] [placement] [panelRole]>` and `<ptah-native-popover>` as overlay shells with `[trigger]`/`[content]`. Compose `<ptah-select-picker [options] [value]>`, `<ptah-combobox [options] [query] [loading]>` and `<ptah-menu>` with `ng-template #option let-option let-active="active" let-selected="selected" let-index="index"`, plus `[empty]`, `[loading]`, `[header]`, `[footer]` slots. Signal inputs `size: xs|sm|md|lg`, `tone: neutral|primary|danger`, `variant: plain|glass`; use Floating UI placement values. `providePtahOverlay({surfaceRole:'overlay', motion})` sets look. Menu/listbox hostDirectives own keyboard and ARIA. Overlay panel owns the single `data-glass-surface="overlay"` blur. Shared code owns Escape, return focus, outside click, active-descendant linkage, stale async update and reduced motion. PR #1028 has no dropdown equivalent to replace.

## Migration order

1. **Poor:** machines `machines-ui/src/lib/components/add-machine-pane/add-machine-pane.component.ts:108,167,209-234`; reviews `review-runs-ui/src/lib/components/review-settings-drawer.component.html:22-36,65-149`, plus `review-repositories-editor.component.ts` and `review-bot-identity.component.ts`. Start with shared button/field skin.
2. **Semi:** marketplace `marketplace/src/lib/ui/provider-filters.component.ts:56,74,94-131`; tasks view menu `tasks-ui/src/lib/components/filter/task-view-menu.component.ts:140-463` and palette `tasks-ui/src/lib/components/palette/task-command-palette.component.ts:77-207`; Thoth shell/task toolbar raw controls after local selector audit. Keep palette ranking/keyboard behavior.
3. **Polished last:** setup `setup-wizard/src/lib/components/generation-model-picker.component.ts:12-49`; canvas rail `canvas/src/lib/canvas-rail/canvas-rail.component.ts:121-317`; voice controls; chat composer `chat-input.component.ts:293-520`, grouped suggestions `unified-suggestions-dropdown.component.ts:52-139`, model/peer pickers and autopilot popover. Demand visual and interaction parity before changing chat.

Implementation validation should cover keyboard/focus, busy activation, native forms/IME, Electron overlay clipping/scroll and dark/light glass. No tests or render checks ran for this read-only research. Skill invocation was unavailable in this lane; Ptah tools were discoverable, but targeted `rg` was used for exact literal call-site evidence.
