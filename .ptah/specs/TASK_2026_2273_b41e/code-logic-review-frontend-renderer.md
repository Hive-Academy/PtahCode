# Code Logic Review: frontend graph renderer (memory-curator-ui)

Scope read in full: `renderer/graph-renderer.token.ts`, `renderer/graph-renderer.port.ts`, `renderer/sigma-renderer.adapter.ts`, `memory-graph-canvas.component.ts`, `model/build-graph-model.ts`, `model/keyboard-nav.ts`, `assert-eager-bundle.mjs` (FORBIDDEN_MARKERS). Nothing was executed (per instructions); all claims come from reading source.
Paths below are relative to `libs/frontend/memory-curator-ui/src/lib/components/graph/`.

## Score: 6.5/10. Verdict: APPROVE WITH FIXES

## What was verified as correct

- Lazy loading: the only non-spec importers of `sigma`, `graphology`, `graphology-layout-forceatlas2` are in `renderer/sigma-renderer.adapter.ts:1-4`. The adapter is reached only by `import()` at `renderer/graph-renderer.token.ts:8`. A grep for `sigma-renderer.adapter|SIGMA_ADAPTER` outside specs shows no static importer. The marker `ptah-sigma-adapter` is a runtime string (`adapter:8,48`), so it survives minification, and it is in `FORBIDDEN_MARKERS` (`assert-eager-bundle.mjs:40`).
- Destroy vs lazy import race: `canvas:176-180` sets `destroyed`, unsubscribes, then destroys the port. `mount()` checks `destroyed` after the awaited factory (`canvas:207-210`) and destroys the late renderer. Sigma and the ResizeObserver are released in `adapter destroy()`. `destroy()` is idempotent.
- Load failure is caught (`canvas:197-206`) and reported through `rendererError` plus an `alert` banner.
- Selection, highlight and labels do not rebuild the graph: `setSelection/Highlight/LabelsVisible` only call `applyAppearance()` (merge attributes). `setModel` diffs nodes and edges with keyed drop, upsert and `replaceNodeAttributes`, and keeps existing positions (`adapter upsertNode`).

## Findings

| # | Severity | File:line | Problem | Evidence | Fix |
|---|---|---|---|---|---|
| 1 | Serious | `memory-graph-canvas.component.ts:45` (host `(keydown)`) with `:250-286` | The host keydown handler swallows keys from the zoom buttons inside it. | The buttons are children of the host (`<button type="button" (click)="zoom(1)">`, template ~l.67+). Enter on a focused button bubbles to `onKeydown`, which emits `nodeSelect` for `focusedId ?? nodes[0]` and calls `preventDefault()` (`:268-270`, `:286`). This cancels the button click. Keyboard users cannot activate the toolbar buttons, and an unintended node select occurs. | Return early unless `event.target === event.currentTarget` (or the target is not a button/input). |
| 2 | Serious | `renderer/sigma-renderer.adapter.ts:44-45` (`new Sigma(this.graph, container)`) | If the container has zero height/width at mount, Sigma throws. The error is terminal and there is no retry. | `mount` is called from `afterNextRender` (`canvas:158-160`). Sigma's constructor rejects a container with no size unless `allowInvalidContainer` is set (not set here; only `renderLabels:false` is set at `:67`). A canvas inside a collapsed or hidden tab or accordion at first render gives the generic error banner and `rendererError`, and never recovers when the container later gets a size. The ResizeObserver is created after `new Sigma`, so it never runs. | Pass `allowInvalidContainer: true`, or defer `mount` until the ResizeObserver reports a non-zero size. Add a test with a zero-size container. Verify the option name against the installed sigma version. |
| 3 | Moderate | `memory-graph-canvas.component.ts:264,269,272` | Stale or invisible focus target. `focusedId` is never validated against the current model. | After a filter or model change removes the focused node, `nearestInDirection` returns `null` when the origin is missing (`model/keyboard-nav.ts:7`), so arrow keys do nothing indefinitely. Enter emits `nodeSelect` with the dead id. Without any focus, Enter silently selects `nodes[0]` (alphabetically first id) that the user never focused and that was never announced. | Reset `focusedId` in an effect on `model()` if the node is gone. On first Enter or arrow with no focus, focus `nodes[0]` and announce it instead of selecting. |
| 4 | Moderate | `memory-graph-canvas.component.ts:289-300` and `adapter focus()` | There is no visible keyboard-focus indicator. `focusNode` only pans the camera (`port.focus`) and sets live-region text. The adapter draws nothing for the focused node (`applyAppearance` knows only selected and highlighted). | Sighted keyboard users cannot see which node is focused. This is the stated keyboard-navigation requirement. | Add a `setFocus(id)` port method that enlarges or rings the node, kept separate from selection. |
| 5 | Moderate | `memory-graph-canvas.component.ts:250-286` | Modifier keys are not checked. | Ctrl/Cmd+`-`, Ctrl/Cmd+`=` and Ctrl/Cmd+`0` (app/browser zoom shortcuts) hit `:282-284` and get `preventDefault()` while the canvas is focused. The shortcuts are hijacked and zoom the graph instead. | Return early if `event.ctrlKey || event.metaKey || event.altKey`. Keep Shift only for Enter. |
| 6 | Moderate (needs runtime check) | `canvas:260-267` with `model/keyboard-nav.ts:11-14` | Arrow direction is computed on raw graph coordinates (`dy<0` means up). | Sigma maps graph y to the screen through its camera/viewport matrix, and the code never converts through `graphToViewport`. If graph y is up on screen, Up/Down are inverted. Camera zoom/rotation is also ignored. | Compute positions in viewport space (e.g. a port method returning `graphToViewport` coordinates), or confirm and unit-test the orientation. |
| 7 | Moderate | `adapter:44-65`, `:150-158` | `setModel` always restarts layout, even when only color, size or label changed (for example a `colorBy` change). It also runs when the parent emits a new model object with identical topology. | `setModel` calls `stopLayout()` then `startLayout()` whenever `!frozen && order>0`, with no topology check. Nodes drift and re-run FA2 for 4 s on every recolor. With reduced motion, `forceAtlas2.assign(... iterations:80)` runs synchronously on the main thread each time (1,500 nodes and 9,000 edges is a visible jank risk). | Track whether node or edge ids changed in the diff and relayout only then. Run the sync layout in chunks or cap its iterations. |
| 8 | Moderate | `canvas:199,233` | Both catch blocks discard the original error. | `catch {}` then a fixed message. There is no log, and `rendererError` carries only the generic string. A chunk-load failure, a WebGL-unavailable error and finding 2 are indistinguishable. No retry affordance exists either. | Log the error (the project Logger/console policy) and pass a code or detail through `rendererError`. Offer a retry that re-calls the factory. |
| 9 | Moderate | `canvas:241-248` with `adapter:110`, `:98-114` | Per-event cost grows with graph size. | `refreshMinimap` runs on every `viewportChange` (camera animation frames, resize, layout start/stop). It builds the full 1,500-entry map and array and sets two signals each time. During the 4 s worker layout the minimap is not refreshed (only `layoutState` start/stop triggers it), so it shows stale positions while nodes move. | Throttle with `requestAnimationFrame`. Refresh positions on a timer while `layoutState.running`. |
| 10 | Minor | `canvas:294-298` and `:274-279` | `edges()` is used for the link count and for `[`/`]` navigation. The model drops edges with missing endpoints (`build-graph-model.ts:14`). If `edges()` is the unfiltered wire input, the announced count can exceed the visible links, and `nextLinked` can set `focusedId` to a node absent from the model. The announcement is then skipped (`:292-293`) and focus gets stuck on an invisible node. | Use `this.model().edges` for both. |
| 11 | Minor | `canvas:129,277` | The shared `linkedIndex` is never reset when focus moves by arrow keys or click, so the first `]` on a new node starts at an arbitrary offset. | Reset it in `focusNode` when called outside the bracket path. |
| 12 | Minor | `canvas:161-175`, `adapter applyAppearance` | At mount, five effects each fire. `applyAppearance` is an O(N+E) full merge pass (about 10,500 attribute merges at target size) and runs 4 times. | Batch through one effect or a single `applyState()` call. |

## Failure-mode notes

- Silent failure: findings 3 and 8 (a stale-id Enter select, and discarded errors).
- Unverified, not reported as a defect: the FA2 worker layout (`this.layout ??=` at `adapter:144`) is created once and reused after the graph is mutated and nodes are dropped (`setModel`). Whether the installed `graphology-layout-forceatlas2/worker` re-syncs matrices on graph events, and whether a late worker message after `dropNode` can throw, was not verified from the package source. Both specs use fakes (`fake-graph-renderer`), so a real-adapter test with node churn is advisable.
- Performance target: no 1,500/9,000 benchmark or test was examined. The main-thread risks are the sync layout under reduced motion (finding 7) and the per-frame minimap rebuild (finding 9).

## Verdict

APPROVE WITH FIXES. The lazy-load boundary, the destroy race and the setModel diff design are sound. Fix findings 1, 2, 3 and 5 before merge, and 4, 6, 7 and 8 soon after.
