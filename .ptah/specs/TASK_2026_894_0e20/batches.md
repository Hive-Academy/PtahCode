# Settings redesign: implementation batches

Batch 1 (backend removal of the two approved Codex numeric keys) is done; see `batch-1-report.md`. Start UI work at Batch 2. All paths below are workspace-relative. Each file has one owning batch. Where a later batch mounts an earlier component or consumes its output, the dependency is explicit. Executors write production code and tests; the team leader verifies the result on disk. Electron is the first visual host; its renderer is `apps/ptah-extension-webview`.

For every later batch, run only `npm run verify -- -p <changed projects>` and tail the output (`| Select-Object -Last 60` in PowerShell). Never run workspace-wide verification. These commands belong to implementation lanes, not this decomposition.
