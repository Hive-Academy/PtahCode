# Settings design specification

Target: Electron renderer (`apps/ptah-extension-webview`), Angular 22 Settings. [Prototype](prototype/index.html) is static and uses realistic mock data.

## Design system applied

Use the existing Ptah glass and DaisyUI semantic system. Dark defaults to `data-theme="ptah-glass" data-theme-mode="dark" data-glass="on"` (`apps/ptah-extension-webview/src/index.html:2`); the theme boot code selects its light counterpart (`apps/ptah-extension-webview/src/index.html:78-80`). Reuse `--ptah-gold` and `--ptah-gold-strong` (`styles.css:58-61`), their light override (`styles.css:127-145`), and semantic `--b1/--b2/--b3/--bc` surfaces (`styles.css:148-155`). Use `data-glass-surface="content"`/`"tile"` (`ptah-ai/cli-orchestration-matrix.component.ts:182-215`), `border-base-content/10`, `text-base-content-muted` (`advanced/advanced-settings-group.component.ts:83-98`), `badge badge-sm border-base-300 bg-base-200` (`providers/providers-settings.component.ts:243-249`), and DaisyUI `btn btn-outline btn-sm` without the Providers `CONTROL` constant's hover underline (`providers/providers-settings.component.ts:88`). The prototype hex colors are visual placeholders. Its --line is decorative only; --control-border models border-base-content/60. Inputs, selects, popover triggers and radio cards use input-bordered or select-bordered plus border-base-content/60 (or stronger) on the light card surface; verify a computed boundary contrast of at least 3:1 in both active themes against the actual card background. Wrap small toggles and checkboxes in labels with 40px targets.

Use the existing Settings host `mx-auto w-full max-w-screen-2xl space-y-8 px-3 py-3 md:px-6 lg:px-8` (`settings.component.html:19`). Sections use `data-glass-surface="content"` and the existing glass padding; do not add a second fill/border on top. Tiles use the existing `data-glass-surface="tile"`. Heading `text-base font-semibold`; helper `text-xs text-base-content-muted`; body `text-sm`; rhythm 8/16/24/32px. Focus: 2px visible outline with `var(--ptah-gold-strong)` (light override at `styles.css:133`).

The heading and inherited state occupy the first region; Permission and Network use `grid grid-cols-2 gap-3` (one column only below 480px of content), labels above `select select-bordered select-sm w-full max-w-xs min-w-[9rem]`. Instance header: `flex flex-wrap items-start justify-between gap-3`, name/provider/status left; `btn btn-outline btn-sm` Tiers and Test, `btn btn-ghost btn-sm` More right. Capability strip `flex flex-wrap gap-1.5`; chips `inline-flex whitespace-nowrap` wrap only between chips. Show three concise chips, with all capabilities in a top-layer Show capabilities popover that leaves the instance card size unchanged. Details `grid grid-cols-1 gap-5` and `@container (min-width:761px)` for two columns: direct model, effort, last test; three tier slots. No underlined link styling for action buttons.

## CLI agents and custom instances provider cards

Keep the existing toolbar, order and concurrency controls. The provider grid is owned by the matrix content component. Its component CSS sets `container-type: inline-size` on the content host and `@container (min-width: 560px)` for two columns and `@container (min-width: 860px)` for three. Below 560px use one column. Never render a fourth column. Use `repeat(n,minmax(0,1fr))` tracks and a fixed 548px card height, identical for every card at each width. The 560/860px thresholds are provisional until the Electron renderer's actual Settings content width is measured; preserve approximately 270px minimum width in two and three column modes. Use component CSS, following `chat-input.component.css`; no Tailwind container-query classes or new dependency. If a scroll gutter is retained, use `[scrollbar-gutter:stable]`.

Each card has a compact header with a truncated name and full name in `title`, a fixed-width status badge slot, and one of Installed, Needs key, Not installed, Running, or Test failed. Next show two capability chips and a `btn btn-ghost btn-xs` All capabilities trigger. A fixed body holds provider, model, effort, safety, **Current CLI mode**, and lane defaults. Only Cursor shows a Credentials row; other agents use that space for the test status line. The defaults caption shows saved override or Auto (default) / built-in. Its two selects are labeled **Lane default** (permission) and Network. Show unsupported pair, Permission/Network unavailable reasons and Cursor unavailable modes in a bounded explanation region with full text in an Info popover and `title`. Put Reset to default in the defaults popover. The Codex sandbox note occupies no reserved blank region on other cards.

Reserve a fixed-height `aria-live="polite"` test status line on every card for last result, Running, or Test failed. Truncate failed text visually and expose full text via `title` and Info popover. Test keeps a fixed width when busy. Footer contains Test and More; More reaches Tiers, Install guide, Edit and Delete for the appropriate agent. All popovers use the existing `ptah-native-popover`; reuse the current model/effort editor and Cursor credential popover components. The card body has at least 4px padding on every side. Normal, unsupported, unavailable, running and failed states must fit without body scrolling. Measure each rendered card state's `scrollHeight <= clientHeight`; if it fails, shorten fixed copy or move detail into a popover while preserving the 548px outer height. The card's one-line rows and absent empty Codex note reduce wasted height.

The capability, model, effort, permission, credentials, Info and More triggers expose `aria-expanded` and `aria-controls`. On open, focus the first control. Escape closes and restores focus to the trigger. Only one popover may be open. Long text is truncated with a full accessible label. The prototype uses native browser popovers to illustrate the same top-layer behavior; production uses `ptah-native-popover`.

## Routing and capability evidence

Resolve `pc-*` against configured Ptah CLI instances, `subagent:code-logic-reviewer` to “Code logic reviewer”, and `research|research` to “Research · research”. If unresolved, show “Unknown executor” and expose raw ID in an accessible details element. Stored IDs remain unchanged.

Name resolution is frontend-only. Extract a small `RoutingDisplayNamesStore` using `inject(ProvidersSettingsStateService)` and `computed()` over `state.cliAgents().data` (`agent-orchestration-config.component.ts:350,366`; `cli-matrix-rows.ts:342,417-430`). Index `PtahCliSummary.id → name`; while `cliAgents()` loads, show “Loading executor…”; missing/deleted IDs show “Unknown executor” with raw ID in `<details>`. Export the existing private `SYSTEM_CLIS` labels through a pure helper (`cli-matrix-rows.ts:230-253,350-352`); unknown system IDs are title-cased. `subagent:<slug>` has no registry: split hyphens, title-case words, and retain raw slug in detail. Split route key on `|`, map known task kinds (`plan`, `implement`, `review`, `research`, `tests`, `docs`) to display labels and title-case unknown segments; keep both segments. For capability models, use the existing `cliModelDisplay()` parser for `id<TAB>display name` (`cli-matrix-rows.ts:307-322`); prefer its display-name part, otherwise saved `ProvidersCliModels` label from `state.cliModels()` if available, otherwise show the raw model ID with `overflow-wrap:anywhere` in its own cell. Do not fabricate model names. Rotation and capability components inject the same store; neither reads a sibling component's private signal. The RPC itself contains only IDs and raw model strings (`lane-rotation-setting.component.ts:79-88`; `capability-matrix-setting.component.ts:153-201`). `lastPicksUnavailable` renders “Recent picks unavailable” with Retry; empty list says “No recent picks yet”.

Capability matrix: real `<table>` with `<thead>`, one `<tbody>` per family, `<th scope="rowgroup">` family header and `<th scope="row">` model label. Native family toggle button has `aria-expanded` and `aria-controls` wired to its model rows; families default collapsed except the first. `*` means “All models”. Columns are Plan, Implement, Review, Research, Tests, Docs. Each cell shows score `/100`, `h-1.5` bar sized to score%, source badge (`seed`, `user` or `local`), sample count `n=5`, and Stale badge when true. `asOf`, `sourceRef`, and `note` remain in a keyboard-accessible cell detail disclosure. Unrated uses muted “— Unrated”, no bar, never zero. At 900px, table `min-w-[780px] overflow-x-auto` and sticky model label. At 1200px all task columns fit; at 1600px increase cell padding. Show `Loading executor...` in the evidence table while an executor is resolving. Loading `role=status`, error `role=alert` plus Retry, empty state explains evidence appears after runs; a wholly unrated family still shows six unrated cells. Source and stale stay visible without hover.

## States and accessibility

Both themes use semantic surface/content colors and theme-aware gold. Require 4.5:1 text contrast and 3:1 control boundaries in each active theme. Interactive targets ≥32px, ≥44px in narrow card mode. Keyboard order matches visual order. Popover triggers expose aria-expanded and aria-controls; capability evidence details open in a popover, so a table row never grows. Family headers use scope=rowgroup; numeric text accompanies bars. Errors and disabled states retain existing feedback. Honor reduced motion; existing motion token is `--ptah-motion-out:180ms` (`styles.css:43`).

## Full-access confirmation and instance ownership

Use the shared native modal `<dialog>` for a full-access proposal from either a card Lane default select or the shared defaults. Keep the select at its committed value while the dialog is open; Confirm commits, Cancel and Escape leave it unchanged. Focus the dialog heading or first action on open and return focus to the initiating select on close.

The Ptah CLI instance section owns tier slots, Last test and Key set for each instance. The grid card owns the concise instance summary and reaches Tiers, Edit and Delete through More. Instance-section cards are content-sized and are outside the grid equal-size rule.

## Lane-introduced constraints

- Prototype is static and contained in this task folder; no product code or RPC is changed.
- Electron's sidebar makes content width smaller than window width; use container queries.
- Implementation retains existing safety confirmation, state feedback, and all non-approved capabilities.
