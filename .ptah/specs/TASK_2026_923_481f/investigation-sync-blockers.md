# Electron MAIN synchronous blocker investigation

## A

**Short answer.** Release watchdog logs prove repeated 9–23 s MAIN event-loop stalls while `ptah_task_create` is in flight. They do not identify the executing stack. The direct path does cross-worktree ID discovery, creates a carrier, and rebuilds the entire local task index. The writer notification and file watcher can rebuild **twice** per create. The synchronous parse/validation and better-sqlite3 replacement transaction are the leading suspects; their duration remains inference.

**Rank:** (1) whole-index SQLite replacement; (2) whole-index synchronous parsing; (3) inline Windows Git process spawn **if** the optional off-thread spawner is absent. Git watcher startup is a concurrent lower-ranked lead, not a proven create callback.

## C

**Short answer.** Preserve task creation and data safety. Coalesce repeated rebuilds, bound synchronous work, and measure phases before assigning the 10–25 s duration to one function.

1. `libs/backend/task-specs/src/lib/task-index.service.ts:303-309,566-575,597-603` — writer notification and watcher echo each request a full rebuild. **Fix:** coalesce for same root/folder; retain one serial rebuild and one `tasks:changed` push. **Unit test:** one create plus echo yields one committed rebuild, all rows correct; an external edit still rebuilds.
2. `libs/backend/task-specs/src/lib/task-index.service.ts:621-656`; `libs/backend/task-specs/src/lib/task-index.store.ts:274-286` — full scan plus synchronous delete/reinsert runs on MAIN. **Fix:** update only changed-folder row for known-folder events, preserving initial full scan; move full replacement to existing SQLite worker or use bounded batches with event-loop yields while preserving atomic visibility. **Unit test:** create/update/delete, invalid carriers, and concurrent watcher events yield exact rows; a timer advances during large operation.
3. `libs/backend/task-specs/src/lib/task-scanner.service.ts:140-155,219-232` — async reads feed synchronous per-carrier parsing. **Fix:** yield between bounded parse batches or use an existing worker, preserving order and validation. **Unit test:** many-carrier scan matches existing summaries and permits timer ticks before completion.
4. `libs/backend/task-specs/src/lib/task-index.service.ts:615-656`; `libs/backend/task-specs/src/lib/git-task-folder-visibility.service.ts:324-325` — instrument scan, parse, transaction, watcher echo, Git spawn, and sibling scan; report selected spawner type without paths or content. **Unit test:** injected slow phases report separate durations and do not leak carrier text.
