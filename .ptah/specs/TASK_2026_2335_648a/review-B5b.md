# B5b logic review

**Verdict: REVISE** · **Score: 5/10**

The five basic states and write rollback work for a stable workspace. The score reflects two lifecycle defects that can leave the gate wrong or save a preference against the wrong workspace. The core RPC and rendering path is in place.

## Defects

1. **Serious · The workspace can change while the component still uses the previous workspace's status.** `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:438`, `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:445`, `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:506`, `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:547`. The read stores a single status, and the write resolves the active workspace afresh. With a generated prompt in A, switch the scope to B while the view is mounted. B can have no content and still receive an enable write because the gate uses A's status. The backend persists that preference (`libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:809`). The test at `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:362` currently expects a write immediately after a scope switch without verifying the new scope's status. Fix by keying status and pending reads to the workspace, invalidating the gate on scope changes, dropping obsolete responses, and binding saves and Undo to their originating workspace. Test A-with-content to B-without-content and a late A response.
2. **Moderate · A generation completed outside the drawer's observed completion path leaves the mounted toggle stale.** `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:314`, `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:438`, `libs/frontend/chat/src/lib/settings/pro-features/system-prompt-drawer.component.ts:486`, `libs/frontend/chat/src/lib/settings/pro-features/system-prompt-drawer.component.ts:582`. Ordinary successful drawer regeneration emits `changed` and refreshes the parent. Generation elsewhere can leave an already mounted no-content toggle disabled. Even opening Details and seeing the generated prompt does not update the row, because the drawer's reopen read updates only its own status. There is also a delayed drawer case. If the RPC settles before the host finishes and the drawer closes, reconciliation stops while closed. Reopening after completion reads the new status only in the drawer. The test at `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:864` calls the protected loader directly and never exercises the output or a missing-to-generated transition. Fix by wiring workspace-scoped generation completion to status invalidation and propagating a newly observed status on drawer reopen. Exercise the real output or shared invalidation and assert the mounted row becomes enabled and checked for an on-by-default response.
3. **Moderate · Screen-reader text contradicts the session scope.** `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:178` renders “Active for all sessions” in an `sr-only` status, alongside the hint that says “Applies to new sessions.” `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:522` locks in the conflicting text. Fix by aligning the hidden status with the new-session copy or removing the redundant phrase and updating the spec.
4. **Minor · Keyboard blocking and focus behavior lack a direct regression assertion.** `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:207` and `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:244` exercise clicks. The order assertion at `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:803` verifies placement. The shared directive in `libs/frontend/chat/src/lib/settings/feedback/busy-disabled.directive.ts:52` and `:61` lets Tab through, preserves focusability and cancels activation in capture phase. The toggle links the hint at `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:206`. Add a disabled-switch test that checks Space cancellation, unchecked state, no write, and that Tab remains available.

## Five logic questions

1. **How does it fail silently?** The row presents a definite mode after a workspace switch or after a generation it missed. The cached read includes no workspace key or generation invalidation. See defects 1 and 2.
2. **What user action produces unexpected behavior?** Switching workspace while the section remains mounted can use A's state to enable B. Reopening Details after a delayed generation can show a generated prompt while the row retains its old state. See defects 1 and 2.
3. **What input data produces a wrong answer?** A's `{hasGeneratedPrompt: true, enabled: false}` is valid but becomes an invalid gate for B with no content. In the correct workspace, `{hasGeneratedPrompt: false, enabled: true}` correctly renders off and disabled. See `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:350` and `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.spec.ts:231`.
4. **What happens when a dependency fails?** Failure, rejection and embedded host errors on the initial read produce an alert and Retry, and the switch stays off and disabled. Failed or rejected saves restore the checkbox to the saved state and show an alert. If only read-back fails, the component preserves the acknowledged write and shows a load error. The loader handles `data.error` and catches exceptions but relies on the typed RPC for the two boolean fields. See `libs/frontend/chat/src/lib/settings/pro-features/agent-behaviour-section.component.ts:443`, `:502` and `:544`.
5. **What is missing from the requirements?** The workspace ownership of stored status and Undo, and the handling of overlapping reads across scope changes, need explicit tests. See defect 1.

## Decisions

- Treated `enabled` from the backend as authoritative when generated content exists. A first-generation default and an explicit saved off choice both use the same switch. B5a owns default persistence, so a renderer override would overwrite the meaning of a saved off state. This is reversible at the renderer boundary if the contract changes.
- Kept focusability through the existing busy-disabled directive in the review criteria. Native disabling would remove the switch from the tab order. The existing directive announces the disabled state, keeps the hint reachable and blocks activation.
