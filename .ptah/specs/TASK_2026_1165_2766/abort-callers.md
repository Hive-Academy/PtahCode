## Other close and host paths

- `TabManager.closeTab()` only closes a tab in the active partition (`tab-manager.service.ts:1497-1500`, `:1527-1532`). UI close, keyboard shortcut (`keyboard-shortcuts.service.ts:77`), session-row action (`session-row-actions.service.ts:139`), delete-original flow (`chat-view.component.ts:2186-2189`), task-prompt failure, and handoff can call it. Busy or dirty tabs normally require confirmation (`tab-manager.service.ts:1502-1524`). Handoff passes `skipConfirmation=true` after its own blocker check (`:1647-1654`).
- Cross-partition close requires an expected session binding (`tab-manager.service.ts:1621-1625`), refuses busy/dirty background tabs (`tab-cross-partition-close.ts:48-51`), then emits `kind: close` (`:62-67`). Handoff's background path can allow a stopped predecessor in `awaiting-background` or `sleeping` state (`tab-manager.service.ts:1657-1663`, `tab-cross-partition-close.ts:50`).
- Pop-out uses `forceCloseTab()` (`app-shell.component.ts:407`), which clears the abort controller and emits `forceClose`; the closed-tab ender filters that kind. `resetTabToFresh()` emits `reset`, also filtered by the ender, but its live AbortSignal can still dispatch through MessageSender.
- `chat-rpc.handlers.ts:363-367` routes host `chat:abort` to `ChatSessionService.abortSession`. I found no direct non-spec `chat:abort` call in `apps/ptah-electron`; the worker driver above is the backend-origin caller. A host-initiated renderer event may still reach the renderer paths listed here.

## Watcher clue

`git-dock-scope.store.ts:87-90,340-345` tracks changes including active tab. Its `readInputs()` takes active and open sessions (`:522-548`); `reconcile()` leases the selected worktree and open-session roots (`:557-585`). `GitRootWatchLeaseService.update()` waits 300 ms before `git:watchRoots` (`git-root-watch-lease.service.ts:73-82`). Thus the later `GitRootWatcherPool` stop/start is consistent with active-tab change, tab close, session-root change, or workspace change. It does **not** establish workspace removal, and it occurs after the interrupt. Plain workspace switch does not itself call `chat:abort`.

## Most probable false-stop paths and smallest fixes

1. **Programmatic close of a child or predecessor tab.** Handoff may close a tab without user action (`auto-handoff-source-closer.service.ts:65-95`, `tab-manager.service.ts:1647-1663`); then the close event or AbortSignal sends `chat:abort` (`closed-tab-session-ender.service.ts:49-59`, `message-sender.service.ts:438-454`). If the tab binding points to the child or a newly rebound session, the child stops. Small fix: pass the expected session ID and close source through the close event and abort listener; require the backend live record to match the expected tab/session pair. Log source in `chat:abort`.
2. **Carry-over late resolution classified as abandoned.** Async paths send abort for `realSessionId` (`provider-carry-over.service.ts:380-412,450-492`) without closing any tab. A race with a child tab re-attach or session-id rebind could make the classification stale. Small fix: defer the abort until a fresh global ownership check after the binding settles; attach `source: carry-over-skip` and request ID to the RPC/log.
3. **Streaming tab reset or stale tab-ID fallback.** `resetTabToFresh()` aborts its controller (`tab-manager.service.ts:1679-1684`); MessageSender reads only active tabs and otherwise passes tab ID (`message-sender.service.ts:447-454`). Small fix: capture the original session ID when wiring the signal, look up across workspaces on abort, and reject if the tab's current binding or turn generation changed. Give reset its own abort reason.
4. **Workspace folder removal.** `removeFolder()` ends all sessions it thinks belong solely to the removed folder (`electron-layout.service.ts:434-473,722-737`). It needs an explicit folder removal, so the watcher clue alone is weak. Small fix: recheck live ownership immediately before abort and log `source: workspace-remove`, workspace path, and session ID.
5. **Apps late start or worker lifecycle.** Both can abort without a chat Stop (`apps-session.service.ts:265-270`, `session-driver.ts:453-468,529-550`), but they are less likely for a child tab created by `ptah_session_start`. Small fix: add distinct abort source values (`apps-unowned-start`, `worker-shutdown`, `worker-log-failure`, `worker-orphan`) to make the next incident attributable.

The most useful shared change is an optional `source` field in `ChatAbortParams` (`rpc-chat.types.ts:303`) and an info-level log at `ChatSessionService.abortSession()` (`chat-session.service.ts:2495-2501`) with source, session ID, tab ID, and caller window ID. Keep the SDK cause `user-stop` only when that source represents an actual Stop action; otherwise use a distinct internal cause if the SDK contract permits it.
