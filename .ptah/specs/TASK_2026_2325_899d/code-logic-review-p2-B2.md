## Five logic questions

1. **How does this fail silently?**
   - `ProjectSkillDraftComponent.create` (`libs/frontend/onboarding/src/lib/analyze/project-skill-draft.component.ts:92-95`) turns a missing or whitespace `skillPath` receipt into a `"Created: ..."` status and drops edits.
   - `StackSkillStore.applyRecommendationResult` (`libs/frontend/onboarding/src/lib/proposal/stack-skill.store.ts:569-612`) leaves prior-run item search results and retained keys active after a Re-run, silently distorting coverage and selection totals.
   - Clicking `"Write a skill by hand"` on a Build-only, No-skill, or Not-judged item after a manual skill was already created (`libs/frontend/onboarding/src/lib/proposal/stack-skill-review.component.html:201-207,227-233`, `:360-371`) silently does nothing on an enabled button.
2. **What user action produces unexpected behaviour?**
   - Confirming `"Discard edits"` on `"Try again"` and having generation fail again resurrects the edited text with `dirty: false` (`libs/frontend/onboarding/src/lib/proposal/stack-skill.store.ts:842-853,889-923`), so a later Cancel drops it without confirmation.
   - Toggling any skill card checkbox while the coverage strip is expanded collapses the strip back to two lines (`libs/frontend/onboarding/src/lib/proposal/stack-coverage-strip.component.ts:92-101`).
   - Clicking a per-item `"Search for <name>"` button while a draft is open closes the draft and triggers `afterRenderEffect` (`libs/frontend/onboarding/src/lib/proposal/stack-skill-review.component.ts:315-323`), moving focus back to the closed draft's opener rather than leaving it on the search action.
3. **What input data produces a wrong answer rather than an error?**
   - Leading or trailing whitespace in draft `name` or `description` produces Preview SKILL.md bytes (`libs/frontend/onboarding/src/lib/proposal/skill-draft-preview.component.ts:159`) that do not match the trimmed bytes written on Create (`libs/frontend/onboarding/src/lib/proposal/stack-skill.store.ts:998-999`).
   - A whitespace-only `skillPath` (`"   "`) in `ProjectSkillDraftComponent` (`libs/frontend/onboarding/src/lib/analyze/project-skill-draft.component.ts:92-95`) renders `"Created:    "` as a success state.
4. **What happens when a dependency fails, times out, or returns a shape it should not?**
   - Draft generation failures/rejections enter edit mode with evidence fallback, and stale `revision`/`previewRequestSeq` responses are dropped (`stack-skill.store.ts:925-982`), except for the dirty-retry fallback defect in Finding 2.
   - `harness:create-skill` failures/rejections preserve edits and clear `busy` in both `StackSkillStore` (`:1038-1048`) and `ProjectSkillDraftComponent` (`:88-102`), and `StackSkillStore.completeCreateDraft` (`:1020-1027`) now guards missing/blank `skillPath`, whereas `ProjectSkillDraftComponent` (`:92-95`) does not.
   - If `StackSkillReviewComponent` were ever remounted while a proposal draft with a retryable error remained in the root `StackSkillStore`, `this.previewParams` (`stack-skill-review.component.ts:223,399`) would be `null` and `"Try again"` would no-op.
5. **What is missing that the requirements never mentioned?**
   - Clearing per-item and retained search state inside `applyRecommendationResult` on Re-run (Finding 1), and testing a failed generation retry after confirming dirty-edit discard (Finding 2).
   - Preserving coverage-strip expansion state across selection updates that do not change the detected stack item list (Finding 6).
