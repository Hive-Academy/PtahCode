## Five logic questions

1. **Silent failure.** A non-success harness terminal resolves a typed RPC with missing data. A retry pair write can fail after a successful completion event and therefore contradict it.
2. **Unexpected user action.** Starting or regenerating guidance with an invalid Setup model shows generic retry copy. Changing the model before retry can expose the previous pair in a terminal-run lookup.
3. **Wrong answer from input.** Registry descriptions about deprecated APIs can still silently remove valid candidates. ID suffix collisions and duplicate `no-skill` outcomes now have regression coverage.
4. **Dependency failure.** A thrown Setup resolver releases the reservation, and SDK errors skip post-processing. The late manifest-write error is translated to a retry failure after the broadcast. The JSON scan recovers from a balanced invalid fragment while the draft and judge schemas still validate the extracted object.
5. **Missing contract.** The retry spec checks call counts and a thrown Setup refusal. It does not hold the pair write and inspect terminal ordering, inject a write failure, or exercise submit arriving during retry preparation. The Setup and harness specs stop before the affected view and RPC boundaries.
