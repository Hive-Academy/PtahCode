## Findings

1. **Moderate — Unconstrained intervening-word wildcard in `EXPLICIT_SKILL_DEPRECATION` falsely rejects migration skills phrased with `"This skill is ... deprecated <noun>"` (and alternate negators).**
   - **Location:** [`skill-judge.service.ts:63-72`](../../../libs/backend/rpc-handlers/src/lib/skills-sh/services/skill-judge.service.ts#L63-L72)
   - **Mechanism:** `EXPLICIT_SKILL_DEPRECATION` now permits any 0–2 alphabetic words between `is|was|has been` and `deprecated` except `not`, `never`, and `no` (`(?:\s+(?!not\b|never\b|no\b)[a-z]+){0,2}?`), and `hasSkillDeprecationNotice` (line 69) returns `true` immediately without consulting `DEPRECATED_OTHER_NOUN` (line 71).
   - **Verified false positives** (previously eligible before this edit):
     - `"This skill is for deprecated React APIs."` → `true` (ineligible)
     - `"This skill is for migrating deprecated React APIs."` → `true` (ineligible)
     - `"This skill is replacing deprecated React hooks."` → `true` (ineligible)
     - `"This skill is detecting deprecated methods."` → `true` (ineligible)
     - `"This skill was built for deprecated APIs."` → `true` (ineligible)
     - `"This skill is neither deprecated nor unmaintained."` → `true` (ineligible)
   - **Impact:** A legitimate migration/codemod candidate using one of those phrasings is marked `eligible: false` (`"Marked deprecated by its description"`), omitted from `normalInput` ([`skill-judge.service.ts:189`](../../../libs/backend/rpc-handlers/src/lib/skills-sh/services/skill-judge.service.ts#L189)), and rejected from Decision install ([`skill-judge.service.ts:486`](../../../libs/backend/rpc-handlers/src/lib/skills-sh/services/skill-judge.service.ts#L486)) in both judge and heuristic fallback paths ([`skill-recommendation.service.ts:217`](../../../libs/backend/rpc-handlers/src/lib/skills-sh/services/skill-recommendation.service.ts#L217)). Rated Moderate (rather than Serious) because registry descriptions typically lead with an action verb (`"Migrate..."`, `"Guide..."`) rather than `"This skill is for..."`.
   - **Recommendation:** Either restrict the intervening tokens to deprecation adverbs/modifiers (e.g. `now|officially|permanently|effectively|currently|considered|marked|as|being|hereby|largely|fully|completely`) instead of any `[a-z]+`, and/or apply `!DEPRECATED_OTHER_NOUN.test(description)` to the `this skill ...` clause while keeping `[deprecated]` and `deprecated:` unconditional.

2. **Minor — `PROVIDER_LABELS` omits several real stored Setup provider selectors, rendering lowercased raw IDs in `model-missing` copy.**
   - **Location:** [`safe-failure-copy.ts:59-77`](../../../libs/frontend/setup-wizard/src/lib/utils/safe-failure-copy.ts#L59-L77), [`workspace-llm-resolver.ts:335-343`](../../../libs/backend/auth-providers/src/lib/auth/workspace-llm-resolver.ts#L335-L343), [`workspace-llm-resolver.ts:366-398`](../../../libs/backend/auth-providers/src/lib/auth/workspace-llm-resolver.ts#L366-L398), [`provider-registry.ts:260-274`](../../../libs/shared/src/lib/providers/provider-registry.ts#L260-L274)
   - **Mechanism:** Pre-existing `PROVIDER_LABELS` maps 8 keys (`anthropic`, `claude`, `codex`, `google`, `kimi`, `ollama`, `openai`, `openrouter`) and falls back to `provider` (already lowercased on line 74). Now that `model-missing` interpolates `${label}`, valid stored Setup selectors such as `claudeCli`, `apiKey`, `kimi-code`, `z-ai`, `lm-studio`, and `ollama-cloud` render as `"The Setup model for claudecli is not set..."` / `"for apikey"` / `"for kimi-code"`. No raw error prose or secrets leak (`SETUP_REFUSAL` only captures `provider=([a-z0-9][a-z0-9._-]{0,63})` before the `: raw` suffix, and [`enhanced-prompts-rpc.handlers.ts:804-808`](../../../libs/backend/rpc-handlers/src/lib/handlers/enhanced-prompts-rpc.handlers.ts#L804-L808) emits only validated `resolution.provider`).
   - **Recommendation:** Align `PROVIDER_LABELS` with the canonical built-in provider/selector IDs (or reuse `getAnthropicProvider` from `@ptah-extension/shared`, matching [`analyze-skills.page.ts:92-96`](../../../libs/frontend/onboarding/src/lib/analyze/analyze-skills.page.ts#L92-L96)).

## Five Logic Questions (Bounded Scope)

1. **How does this fail silently?** No silent false-success install verdict remains for the canonical explicit-deprecation forms (`is/was/has been [now|officially|marked] deprecated`). A 3-word modifier (`"This skill is now marked as deprecated."`) still falls outside `{0,2}` and stays eligible (unlikely edge case).
2. **What user action produces unexpected behaviour?** Guidance start/regenerate with only a provider saved now names the provider and asks only for a model ([`safe-failure-copy.ts:83-84`](../../../libs/frontend/setup-wizard/src/lib/utils/safe-failure-copy.ts#L83-L84)); with only a model saved, it identifies the missing provider ([`safe-failure-copy.ts:85-86`](../../../libs/frontend/setup-wizard/src/lib/utils/safe-failure-copy.ts#L85-L86)). When the saved selector is `claudeCli` or `apiKey`, the message displays `claudecli` / `apikey` (Finding 2).
3. **What input data makes this produce a wrong answer?** Descriptions matching `"This skill is for [migrating] deprecated <API/hook/method>"` or `"This skill is neither deprecated nor ..."` are falsely marked ineligible (Finding 1). Case-insensitive negations (`NOT`, `NEVER`, `not yet`, `no longer`, `still not`), `"This skill is no longer maintained."`, all 4 React API examples, and `"Deprecated Playwright helper"` all classify accurately.
4. **What happens when a dependency fails?** `enhanced-prompts-rpc.handlers.ts:809-820` and `wizard-rpc.service.ts:67-85` keep `SETUP_MODEL_INVALID` structured; raw backend text after `:` never enters `setupModelCopy` output, and malformed `SETUP_MODEL_INVALID` strings fall back to fixed `KIND_COPY['setup-model']`.
5. **What is missing that the requirements never mentioned?** `setupModelCopy` always says `"The Setup model..."` even when Setup is unset and the resolver returned `source: 'workspace'` with `cause: 'model-missing'` ([`workspace-llm-resolver.ts:271-279`](../../../libs/backend/auth-providers/src/lib/auth/workspace-llm-resolver.ts#L271-L279)); out of scope for this bounded correction because `SETUP_REFUSAL` carries only `reason` and `provider` across all reasons.
