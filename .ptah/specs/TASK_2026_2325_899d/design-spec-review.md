## Findings

1. **Make Setup a coherent pair and round trip.** `task-description.md:161`, `task-description.md:187`, `design-spec.md:18`, `prototype/index.html:193`, `:279`, `:312`, `:542`, `:553`, `:567`. The fixture mixes screen state with stored value. A provider change flips to the hardcoded Half fixture, Undo sets a state without restoring the previous pair, screen switches default A2 back to Unset, and Set up OpenRouter toggles the picker. Define atomic commit plus Undo, retain the pair across screens, show invalid name/part including a model-only storage case, route readiness to the existing action, and show the Analyze guard for invalid cases. The plan must name durable storage scope and carry the restart proof. **Impact:** The principal Setup interaction and recovery cannot be followed, and stateful QA could confuse an invalid pair with the workspace default.
2. **Design precedence, snapshots and actual model reporting.** `task-description.md:167`, `:181`, `:185`, `:191`, `design-spec.md:29`, `:32`, `:126`, `:132`, `prototype/index.html:359`, `:386`. Write the four-operation precedence and boundary-test handoff from D6/D7, distinguish the Decision role, and specify a fresh snapshot for resumed skills requests and immutable accepted calls. Draw the run pill and an actual result with per-stage pairs. Render attempted/used pairs conditionally and distinguish current setting from pair used. Place named-provider analysis, agent-generation and guidance failures in their existing error surfaces and use the judge degradation path for judging. **Impact:** The UI can misattribute work/cost, and the handoff omits authoritative selection and resume behavior.
3. **Represent valid multi-outcome verdicts and candidate identity.** `task-description.md:205`–`:224`, `design-spec.md:38`, `:40`, `:134`, `prototype/index.html:203`, `:397`, `:401`, `:414`. One scalar `verdict`/`v` and one `candidate` cannot represent Install + Build, multiple Install candidates, or one canonical Install covering several items consistently.
