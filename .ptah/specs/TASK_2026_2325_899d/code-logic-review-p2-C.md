## Five logic questions

1. **How does it fail silently?** A successful write can leave the old invalid Setup state displayed, and a post-result confirmation can discard the wrong draft while a normal result renders. Findings 1 and 3.
2. **What user action produces unexpected behavior?** Opening consent immediately after Re-run can produce an empty or interrupted dialog. Returning focus during a Setup clear can leave Start blocked. Findings 2 and 3.
3. **What input data produces a wrong answer?** A stale configured pair whose initial read has yet to settle is treated as eligible to start. A refresh containing the previous invalid pair can win over a newer clear receipt. Findings 3 and 4.
4. **What happens when a dependency fails?** Preview and Create use fixed fallback messages, and typed recommendation failures reach the retry panel. A failed initial Analyze Setup read leaves the card absent and Start enabled. Finding 4.
5. **What is missing that the requirements never mentioned?** The separate asynchronous operations need an ownership rule for consent during Setup preflight and a settlement rule for focus reads during a configuration write. Findings 2 and 3.
