## Five logic questions

1. **Where can a failure look like success?** An older successful list response can replace newer results with a normal-looking stale saved list. The view gives no indication which response won.
2. **What user action causes an unexpected result?** Opening B's draft and then filtering to A can offer Show all for B's sole candidate while that card is already visible.
3. **What input silently gives the wrong answer?** A single canonical candidate ID rejected on A and installed on pinned B is counted as hidden even though B's Install card is rendered. Different casing does not change this result.
4. **What happens when a dependency fails, times out, or returns an unexpected shape?** Setup read failure surfaces a Retry alert and keeps runs blocked; a cancelled guidance navigation now displays its failure while the page remains usable. In the e2e driver, blank or non-string pair fields fall back to the next source or seed. A resolver that throws still escapes the fake listener; the new internal resolution makes Setup get and clear additional call sites for that fixture failure.
5. **What did the requirements leave unspecified?** They did not specify response ordering for the two saved-list reads or whether a pinned draft row participates in the hidden count. The renderer already makes the latter row visible, so the count should use that same visibility.

## Decisions

- Reviewed the chosen stop-recovery repair path in place. Reissuing cancellation was CodeRabbit's other suggested option. The current approach preserves the existing meaning of Retry and gives the user both Setup repair and the original recovery actions. The rendering choice is reversible.
- Accepted hiding the inert legacy manual draft opener over adding a new legacy editor. The only legacy caller binds search and has no drafting handler, and judged and not-judged review rows still have working draft entry points. The visibility change is reversible.
