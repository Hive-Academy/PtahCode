# Electron visual review

## Setup

- Built `ptah-electron:build-dev` and `ptah-electron:copy-renderer-dev` through `scripts/verify.mjs --exec`. Both exited 0. The dev build copied the WASM assets. Captures cover the bundle copied at 15:44 UTC. The review did not pick up later worktree edits. [Build log](../../tmp/visual/build.log)
- Launched the built desktop app through Playwright `_electron` and the repository's `launchPtah` helper. The home, Electron profile, SQLite database and sample workspace were isolated. `UiDriver` supplied fixture replies through Electron IPC and pushed view changes. No AI provider handled the fixture requests. The picker save, Undo and Create hit mock RPC handlers. The window manager capped the native client area at 982 px high, so Playwright set the Electron renderer viewport to exactly 1000 px high for the comparison.
- Reused the Settings and onboarding Analyze fixtures, supplemented the judge fixture to eight Install selections and three Build proposals, and seeded a generated SKILL.md with a deliberate duplicate slug. Normalized the judge fixture's IDs to the backend's canonical `source/skillId` format. The Ptah Glass run uses the dark and light themes named in the design spec.
- Compared the Electron render with the approved PNGs for Settings unset and stale picker, Analyze default and stale, judged Skills at both widths, draft preview and editor, and the not-judged and empty states. Used F22–F32 from the design spec where they supersede the approved PNGs. [Prototype PNGs](prototype/screenshots/) · [Render and interaction log](../../tmp/visual/observations.log) · [Save, Undo and disabled-state log](../../tmp/visual/setup-observations.log)

## Verdict

**REVISE**

The collapsed method and compact Install disclosures render their detail bodies. The Skills route is also constrained by the outer onboarding shell at 1440 px. Together the layout misses the R22/F22 density and grid targets.

## Defects

1. **High · Skills review · Collapsed disclosures render their contents.** The method banner shows stage rows while its button reads Details, and compact Install cards display their full description, reason and coverage alongside the compact lines while the button reads More. The likely owners are `libs/frontend/onboarding/src/lib/proposal/skill-method-banner.component.ts:71` and `libs/frontend/onboarding/src/lib/proposal/skill-pick-card.component.html:90`. Both nodes have a hidden binding and a flex display class. The collapsed control state and visible contents disagree.
2. **High · Skills review · Wide layout and density miss R22/F22.** The onboarding shell caps the wide renderer at 1120 px including its padding. The Install grid displays three columns at 1100 and four at 1440, one fewer than the binding spec at each width. Likely owners are `libs/frontend/onboarding/src/lib/onboarding.routes.ts:73`, `libs/frontend/onboarding/src/lib/shell/onboarding-shell.component.ts:38` and `libs/frontend/onboarding/src/lib/proposal/stack-skill-review.component.css:102`.
3. **Medium · Settings · Stale-pair warning is squeezed into a narrow text column.** The two inline recovery actions take most of the warning width. The error breaks the model identifier across several lines at 1100 px. The approved stale picker keeps the warning above its actions. At the same width the Unset cell also ellipsizes the effective model in the default glass theme. The full summary is available on hover and in the accessible label. Likely owner is `libs/frontend/chat/src/lib/settings/providers/provider-consumer-assignments.component.ts:354`.

4. **Medium · Analyze · Stale Start button looks enabled.** Start analysis uses the same bright primary treatment when the page says a valid Setup model is required. The enabled and blocked states should be distinguishable before the user attempts the action. Likely owners are `libs/frontend/onboarding/src/lib/analyze/analyze-workspace.page.ts:443` and `libs/frontend/ui/src/lib/extracted/setup-action/setup-action.directive.ts:6`. [Side-by-side crop](../../tmp/visual/analyze-actions.jpg)
5. **Low · Skills empty state · Unavailable-judge message accompanies an empty result.** With zero items, candidates or proposals, the page says “AI review is unavailable — showing registry order” above the empty panel even though there is no registry order to show. The approved empty state omits the method banner. Likely owner is `libs/frontend/onboarding/src/lib/proposal/stack-skill-review.component.html:56`.

## Keyboard, contrast and scroll

- Tab and Shift+Tab reached the method disclosure, coverage disclosure, Install More, selected-list disclosure, Preview draft and Create. Each of the 24 focus samples had a visible 2px outline and an unobscured control center. Enter activated the disclosure and Preview actions. Cancel restored focus to Preview draft.
- The Skills document showed 0 px horizontal overflow in all four configurations. Opening coverage preserved the Skills container’s top position and moved the content below it down by the added chip rows. Method and Install toggles changed the labels and expanded attributes while the detail heights stayed the same, as described in defect 1.
- Axe reported zero definitive text contrast violations across the Setup row, Analyze card and Skills review at both widths and themes. Glass compositing and pseudo-content left manual-review items in every scan. Screenshot inspection covered representative copy and the light and dark focus rings. Full contrast conformance remains unverified.

## Not checked

The shell’s unrelated errors for CLI models, Enhancement and Decision came from fixture coverage gaps and were excluded. The review used fixture persistence and skill creation. Provider sign-in, real model calls, restart persistence, remaining R13 recovery variants and other hosts are outside the captured evidence. The CLI skill loader was unavailable for this lane. A fixture-backed Create was used to reach the in-run duplicate slug warning.
