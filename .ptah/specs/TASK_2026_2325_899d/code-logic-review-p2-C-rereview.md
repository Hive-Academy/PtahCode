## New findings

1. **[Minor]** `libs/frontend/onboarding/src/lib/analyze/analyze-workspace.page.ts:740-747` (template `:272-274`) — **Stuck `setupActionError` alert after recovering Setup via Settings.** Commit `99c47c0c3` removed `this.setupActionError.set(null)` from `refreshSetupModel()` so a queued focus refresh after a failed `useWorkspaceModel()` clear preserves the write error. However, `setupActionError` is now only cleared inside `useWorkspaceModel()` (`:783`). Failure scenario: Setup is invalid (`source: 'setup'`), the user clicks "Use workspace model" and `wizard:set-setup-model` fails (`setupActionError` becomes `"Could not switch to the workspace model. Try again."`), and the user then fixes Setup in Settings (or externally) and returns to onboarding. `refreshSetupModel()` succeeds with `state.kind === 'set'` or `'unset'`, `setupIssue()` becomes `null` (removing the "Use workspace model" button at `:238-271`), yet `<p role="alert">{{ actionError }}</p>` (`:272-274`) stays permanently visible on the healthy Setup card with no way to clear or dismiss it. Suggested fix: clear `this.setupActionError.set(null)` in `refreshSetupModel()` whenever `response.isSuccess()` resolves to a valid state (`kind === 'set' || kind === 'unset'`) — or pass a `preserveActionError` flag set only when draining `setupRefreshQueued` after a failed `useWorkspaceModel()`.

2. **[Minor]** `libs/frontend/onboarding/src/lib/analyze/analyze-workspace.page.ts:844-860,866-877` — **Deferred `?rerun=1` stays armed after explicitly choosing a saved analysis.** When `/onboarding/analyze?rerun=1` opens with an invalid Setup pair, `ngOnInit()` leaves `this.pendingRerun = true` and returns early (`:699-704`). Because `AnalysisStepStore` is root-scoped (`libs/frontend/onboarding/src/lib/analyze/analysis-step.store.ts:42`), previously listed saved analyses can still render under "Saved analyses" (`:467-514`). Failure scenario: the user changes their mind and clicks `Use` on a saved analysis (`useSaved()` at `:844-860`), which loads that analysis and merges `{ analysis: filename }` without clearing `this.pendingRerun` or `rerun: null`. When Setup later becomes valid (via Settings return or window focus), `refreshSetupModel()` invokes `startPendingRerun()` (`:757,866-877`), which calls `startFresh()`, clears the chosen selection (`store.clearSelection()`), and starts an unrequested fresh analysis. Suggested fix: disarm `this.pendingRerun = false` in `useSaved()` (and pass `rerun: null` alongside `analysis: filename` in `router.navigate`) when the user explicitly selects a saved analysis.
