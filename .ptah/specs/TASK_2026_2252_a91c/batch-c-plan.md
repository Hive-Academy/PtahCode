## Worker and lifetime

Verified: the worker is generated source evaluated by `new Worker` (`off-thread-process-spawner-source.ts:17-22,107-109`; `spawn-worker-pool.ts:175-188`). It cannot resolve a bundled package by name (`off-thread-process-spawner-source.ts:77-82`). Resolve the absolute `.node` path in Electron composition using the packed and development layout in `electron-windows-job-assigner.ts:25-35`. Pass the path and enabled policy in the typed spawn message. Worker `require`s the absolute binary and assigns the live PID before posting `spawned` (`off-thread-process-spawner-source.ts:293-313`). Do not place the path in the child environment or import Electron into `agent-sdk`.

The worker owns the handle for a worker spawn. Keep it on per-child worker state, not in a local variable. Close on root `exit`, explicit `kill`, and worker release/dispose. Worker loss already triggers direct tree stop (`off-thread-process-spawner.ts:426-434,663-672`) and pool termination (`spawn-worker-pool.ts:183-188,361-367`). Retain snapshot cleanup on worker loss because native finalization timing on thread termination is not a safe guarantee. Killing the root on worker loss is acceptable: its stdio bridge is lost, and the host already ends its process handle abnormally. Host exit closes OS handles; keep the existing host exit tree sweep until a live test proves the job path. Do not duplicate a job handle into main.

For inline spawns, store the handle on `InlineProcess`. For inline `crossSpawn`, store it in the returned wrapper or in closures retained by its listeners. Close on root exit, explicit stop, and dispose; leave an exit listener until actual exit. The handle's close is idempotent. Run snapshot cleanup even after successful assignment: this retains protection for children created in the accepted gap and avoids a new cleanup-state branch. Existing worker and inline exit scans are `off-thread-process-spawner.ts:509-513,740-749`; CLI inline scan is `cli-adapter.utils.ts:338-349`. The extra scan is bounded.

## Switch, failure, and logs

Propose `ptah.agentOrchestration.windowsJobs`, default `false`, with Electron local override `PTAH_WINDOWS_JOBS=1`. Require Windows x64, enabled switch, and explicit `job` policy. Read the setting at each spawn. An established boolean read is `apps/ptah-electron/src/di/phase-2-libraries.ts:219-223`; Electron routes registered dotted keys to file settings (`electron-workspace-provider.ts:94-105`; `platform-core/src/file-settings-keys.ts:110`). The SDK already uses a `=1` environment override (`off-thread-process-spawner.ts:132-133,960-962`). For a local test, set `PTAH_WINDOWS_JOBS=1` before starting Electron, then launch a managed root. Register the key in the file settings allowlist and shared advanced settings catalogue if exposing it in UI. Avoid caching the setting at container construction.

Success debug line: `[WindowsJob] assigned pid=<pid> root=<kind>`. Fallback error line: `[WindowsJob] assignment failed pid=<pid> root=<kind>; snapshot cleanup active`, with the real `Error` object passed to `logger.error`. Do not log binary paths or environment values. Catch native load and assignment errors at the spawn site. Keep snapshot and tree-stop paths after every error. Never start a second root. A missing PID follows the existing spawn-error path; it must not be marked job-owned or disable cleanup. The native adapter throws for unsupported architecture (`electron-windows-job-assigner.ts:19-35`).
