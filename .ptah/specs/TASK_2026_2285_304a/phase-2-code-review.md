## Blocking

1. **A partially successful group save loses Undo.** `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-config.component.ts:552` captures the successful IDs and supplies an inverse write, but the partial-failure result goes through `libs/frontend/chat/src/lib/settings/feedback/settings-save-feedback.service.ts:174`, which drops that inverse. Turning on six tools with two rejected writes leaves four saved changes and no Undo. The test at `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-config.component.spec.ts:855` explicitly expects this. A-27 requires group Undo for the rows that saved. Preserve a single partial-result toast with an Undo action whenever confirmed changes remain, and assert that Undo writes only those IDs. Cover the case where the recovery read also fails.
2. **The membership warning loses its live announcement.** `libs/frontend/chat/src/lib/settings/license/license-status-card.component.ts:179` replaces an assertive alert with the regular hint paragraph rendered by `libs/frontend/ui/src/lib/patterns/setting-row/setting-row.component.ts:41`. When the license status changes to expired while focus is elsewhere, the key verification warning and recovery instruction are available only by navigating back to the row. M-9 merges the warning and the trigger visually. Preserve the A-10 announcement by giving the hint a live region or announcing the transition through a persistent, screen-reader-only region. Keep the single visible key trigger and its description.

## Serious

1. **Group writes and Undo can update a destroyed view while the current view shows stale settings.** `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-config.component.ts:552` registers page-level write and Undo closures bound to the current card's local signals. The Advanced card is recreated on tab navigation (`libs/frontend/chat/src/lib/settings/settings.component.html:133`), while the save service and toast live on the Settings shell (`libs/frontend/chat/src/lib/settings/settings.component.ts:146`, `libs/frontend/chat/src/lib/settings/settings.component.html:194`). Start a group write, visit Providers, and return before the last request completes. The new card can load an intermediate snapshot and continue showing it when the toast reports success. Undo after re-entering Advanced can likewise change storage without changing the mounted card. Keep the catalog and write reconciliation in a Settings-scoped owner, or invalidate and reload the mounted card when a write or Undo settles. Test navigation during a held write and Undo after remount.
2. **A timeout can make the group toast declare a saved change unsaved.** `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-config.component.ts:606` re-reads state after an uncertain response but always returns failure. If the host committed an item and the response was lost, the recovery read can show that item in the requested state while `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-config.component.ts:631` excludes it from the successful IDs. The toast's count then contradicts the switches and the rollback set is incomplete. Distinguish explicitly rejected writes from uncertain delivery. Reconcile the latter against verified state and describe any still-unknown outcomes as unconfirmed. Add a case where the write commits and the transport rejects.
3. **The aggregate control's mixed state is exposed as off to assistive technology.** `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-group.component.ts:59` combines `role="switch"` with the `mixed` value returned at line 111. This follows the literal Phase 2 contract, but WAI-ARIA requires user agents to treat mixed on a switch as false. The current tests assert the DOM string and therefore miss the accessibility failure. Resolve the contract with the coordinator and use tri-state checkbox semantics for the group control while keeping individual rows as switches. [WAI-ARIA 1.2 switch role](https://www.w3.org/TR/wai-aria-1.2/#switch)
4. **The unverified response discards the catalog that the contract shows read-only.** `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-config.component.ts:693` returns before applying the lists, and the exclusive error branch at line 162 suppresses every row. The RPC still returns the catalog and stored opt-ins alongside `policyStatus` (`libs/backend/rpc-handlers/src/lib/handlers/agent-rpc.handlers.ts:584`). Preserve the distinct unverified message and Retry, render the returned catalog as read-only, and continue refusing every write until verification succeeds. Update the spec to distinguish this from the read-failure case with no rows. This is a gap against plan 2.9 and the design spec. Existing fail-closed write behavior should be preserved.
5. **Valid synced skill names can generate duplicate accessibility IDs.** `libs/frontend/chat/src/lib/settings/pro-features/claude-builtins-row.component.ts:17` maps every unsupported ID character to an underscore. The synced catalog accepts both dots and underscores (`libs/backend/agent-sdk/src/lib/helpers/synced-claude-skills.reader.ts:54`), so skills named `release.notes` and `release_notes` produce the same name ID at row line 87. The second switch can be announced with the first skill's name. Use the qualified ID directly in the IDREF or encode it without collisions. Test two rows whose names differ only by dot versus underscore.

Keep the button name “Advanced” and expose the warning as its accessible description while retaining the mark's tooltip. Assert the computed button name and description in the expired-license case.

### Five logic questions

1. **Silent failure.** A group write can report a change unsaved after storage accepted it, and a completed write can leave a remounted view displaying the intermediate state. See Serious 1–2.
2. **Unexpected user action.** Activating an expanded filtered group's disclosure has no effect. Leaving and re-entering Advanced during the batch can produce a stale view. See Minor 1 and Serious 1.
3. **Input that produces a wrong answer.** Dots and underscores are both legal in synced skill names and can collapse to one accessibility ID. See Serious 5.
4. **Dependency failure.** A write rejection triggers a recovery read. If that read fails, the batch stops and Retry is available. If some earlier writes succeeded, the generic error toast loses their inverse. An unverified response also stops writes, but drops the read-only display. See Blocking 1 and Serious 2 and 4.
5. **Missing requirement.** The plan does not specify which view owns state when an in-flight batch or its Undo outlives the Advanced tab, or how to represent mixed state with conforming accessibility semantics. See Serious 1 and 3.

### Decisions

- **Score 5/10.** The primary operations and editor guards are wired, and the redesign can be corrected within the existing architecture. Loss of Undo and the announcement, the remount race and the mixed-state contract keep it below the sound band. Severity follows the parity contract and the demonstrated user impact.
- Prefer an aggregate checkbox with indeterminate state over retaining the switch role with a separate textual state. The checkbox exposes the native mixed state and preserves the group's on/off action and visual design. This is a reversible frontend change that needs the coordinator's decision because the approved spec names a switch.
