# Phase 3 code logic review

**4/10 | REVISE**

The grouped table, recovery row, and modal shell have working entry points, and the reorder write and Undo round-trip on a complete read is covered. A move can still overwrite saved IDs after a failed read, and two pieces of lane information became unreachable. Those regressions require another pass. The existing write, read-back, and modal contracts give the fixes a local scope.

## Blocking

1. **Reorder can replace the saved order with a partial list.** `libs/frontend/chat/src/lib/settings/ptah-ai/cli-orchestration-matrix.component.ts:345` checks only review context and save-in-progress. When `agent:getConfig` fails while `ptahCli:list` succeeds, the matrix can show two or more instance rows and enable moves. The write then uses `[]` as the base. A partial response with `missingFields: ['preferredAgentOrder']` takes the same path after normalization at `libs/frontend/core/src/lib/services/providers-orchestration-schema.ts:92`. The full replacement at `libs/frontend/core/src/lib/services/providers-commit.service.ts:180` drops saved system, strip, or deleted-instance IDs. Undo snapshots the same incomplete read at `libs/frontend/chat/src/lib/settings/ptah-ai/preferred-agent-order-save.ts:12`, so it cannot recover them. **Fix** Disable starting Reorder and requesting moves until there is a ready, complete preferred-order read. Enforce the same guard at the write boundary and snapshot that verified base for Undo. Keep Done operable during reads and saves. Cover a failed orchestration read with a usable instance list and a successful response that omits the order field.

2. **The full CLI version is no longer available for most system lanes (P-42).** `libs/frontend/chat/src/lib/settings/ptah-ai/lane-row-identity.component.ts:155` uses the shortened `versionLabel` for both the tooltip and the second line. Moving the Version fact out of detail removed the only full-version tooltip for lanes such as Copilot, whose raw line and display label are distinct. The live-shape check at `libs/frontend/webview-e2e-harness/src/lib/scenarios/settings/settings-visual.e2e.spec.ts:1428` still requires the deleted Version fact and its title. **Fix** Keep the normalized second line and move its full single-line version tooltip to the identity. Keep the existing process-output normalization for banner and multiline output. Assert the short name and full title against the identity locator in the live-shape test.

3. **Short native behavior notes can be clipped with no way to expand them (P-43).** `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table-detail.component.html:42` clamps every note to one line, but renders More only when `nativeIsLong` returns true. `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table-detail.component.ts:155` uses a 72-character threshold. Even on the two-column tier, each fact grid allocates up to 9rem to its label at `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table-detail.component.css:36`. The Codex note ending in “with full access” can wrap below that width, and the previous popover exposed the full note. **Fix** Allow notes without a More button to wrap, or measure overflow and offer More whenever the text is clipped. Keep the full note accessible by keyboard and pointer.

## Serious

4. **An in-flight drag can reorder a different lane after a refresh.** `libs/frontend/chat/src/lib/settings/ptah-ai/lane-order-drag.ts:50` stores the starting numeric index, and `libs/frontend/chat/src/lib/settings/ptah-ai/lane-order-drag.ts:77` applies that index to the latest ID list. For example, start dragging B from `[A, B, C, D]` and let a pending detection refresh insert X ahead of B before dropping. The request can move X. The `dataTransfer` ID never participates in resolving the move. **Fix** Record the dragged ID and either invalidate drag state when the ID sequence changes or resolve both source and destination by ID on drop. Cover an insertion during a drag.

5. **Move settlement can read the old child input and skip the position announcement.** `libs/frontend/chat/src/lib/settings/ptah-ai/cli-orchestration-matrix.component.ts:353` calls the grid immediately after the save resolves. The matrix still has to render to propagate its new rows through the grid to the table. At `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.ts:402`, only the focus lookup waits for render. `libs/frontend/chat/src/lib/settings/ptah-ai/lane-order-drag.ts:100` consumes the pending move immediately, so if the binding has yet to update it compares the old position with itself. The table test pre-applies the input and forces a render before settlement at `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.spec.ts:908`. **Fix** Settle both announcement and focus after child inputs render, or pass the confirmed rank explicitly. Propagate the save outcome so a failed move restores focus without announcing a move. Test through the matrix with an asynchronous read-back.

6. **Install-guide Re-detect treats a missing row as positive installation evidence.** `libs/frontend/chat/src/lib/settings/ptah-ai/cli-orchestration-matrix.component.ts:501` closes and schedules focus whenever the ID leaves the uninstalled array. `libs/frontend/core/src/lib/services/providers-settings-state.service.ts:830` returns true once the detection RPC succeeds, even if the following orchestration read fails or drops an invalid detection row. The lane can then disappear without an installed checkbox to receive focus. The guide busy flag also clears when the detection RPC settles, before its read-backs finish, so a second request can supersede those reads. **Fix** Keep the guide action pending through the read-backs. Require a positively installed row before closing and focusing it, distinguish an incomplete read from a confirmed still-missing lane, and use a stable section control as a focus fallback when the guide disappears or the toggle is disabled.

7. **One Delete action mounts two live confirmation groups.** `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.html:344` renders a confirmation under Status, and `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.html:596` renders the same confirmation in expanded detail. The footer is the only Delete opener. Both copies expose Confirm/Cancel, and both schedule Cancel focus in `libs/frontend/ui/src/lib/patterns/inline-confirm/inline-confirm.component.ts:62`. The tests at `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.spec.ts:587` query the first matching controls or check only the focus text. **Fix** Render a single group next to the footer Delete control, clear the pending confirmation if that detail is dismissed, and assert the exact footer Cancel receives focus. Keep the existing focus handoff to the next rendered row on confirmed removal.

8. **A failed initial read can leave the table in a permanent Loading state.** At `libs/frontend/chat/src/lib/settings/ptah-ai/cli-orchestration-matrix.component.ts:396`, the busy condition is the absence of data. With both source requests failed, both values can be null and the new table gives the skeleton priority over its own error and Retry at `libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.html:71`. The host can project separate errors, but the table still announces ongoing work, and a standalone matrix omits its inline recovery control. Conversely, a partial error with zero table rows can show the matrix's “No CLI agent installed yet” copy at `libs/frontend/chat/src/lib/settings/ptah-ai/cli-orchestration-matrix.component.ts:189`. **Fix** Derive loading from the source statuses, render the terminal error and Retry when no rows are readable, and show true empty copy only from a confirmed read.

9. **The reachability harness still looks for the removed instance card and asserts focus on an out-of-scope Tiers button.** `libs/frontend/webview-e2e-harness/src/lib/scenarios/settings/settings-cli-matrix.entries.ts:253` requires `data-kind` and `cli-instances`; the current row uses `data-lane-kind` and sits in the same tbody as `lanes-group-ptah` (`libs/frontend/chat/src/lib/settings/ptah-ai/lanes-table.component.html:129`, `:178`). At `libs/frontend/webview-e2e-harness/src/lib/scenarios/settings/settings-cli-matrix.entries.ts:699`, the Tiers locator is scoped to the primary row. The fallback can open from the sibling detail, but cleanup at line 746 asserts focus against the original primary-row locator. The shared helper at line 65 also retains its fallback to the removed kebab Details item. **Fix** Assert instance membership under the group tbody, reuse the detail-footer Tiers locator for opening and focus return, and use the expander as the single table-detail entry point.

## Minor

10. **Reorder is offered when there are fewer than two numbered lanes.** `libs/frontend/chat/src/lib/settings/ptah-ai/cli-orchestration-matrix.component.ts:142` disables entry only for a pending save or a missing write context. The zero-lane case can hide Add more while the empty text still points below it, and with one numbered lane all movement commands are unavailable. **Fix** Include numbered lane count in the entry guard and leave Done available if the count drops during Reorder.

## Five logic questions

1. **How does this fail silently?** A partial config read allows a successful whole-order overwrite with an incomplete Undo snapshot. The backup used for Undo is built from the same frontend read (finding 1).
2. **What user action produces unexpected behavior?** Dropping after a list refresh can move a different lane. Delete can focus the second of two confirmation groups (findings 4 and 7).
3. **What input data produces a wrong answer?** An absent or malformed `preferredAgentOrder` is normalized to an array and treated as a trustworthy base. A native note that wraps before 73 characters loses its visible tail (findings 1 and 3).
4. **What happens when a dependency fails?** Save feedback reports write and verification errors. Detection success followed by read-back failure can still take the installed branch, and a terminal initial failure can be rendered as loading (findings 6 and 8).
5. **What case is missing from the stated interactions?** Detection or another settings read can change ordering while a drag is active. A save can also settle before its child view observes the new order (findings 4 and 5).
