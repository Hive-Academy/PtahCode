Verdict: REVISE

## Findings

1. **Blocking — D2 can report stale coverage after a watcher write or delete.** A census snapshots a fingerprint, yields, and later replays it. If a watcher reindex commits first, the replay receives the higher sequence number and can overwrite the watcher's outcome in coverage. A delete can likewise leave a replayed analyzed result with no rows. The existing write path holds the file lock through outcome recording and checks tombstones, while purge excludes tombstones and preserves `keptPaths` from actual writes. See `code-symbol-indexer.service.ts:658`, `:887`, `:949`, `:985`, `:1289`, `:1373`, and `:1607`. Move skip validation and outcome recording under the same lock. Revalidate the current record or its generation after acquiring it, and reject the discovery fingerprint if a newer write or delete invalidated it. A skip must neither clear a tombstone nor add a kept path. Define how a successful delete removes any coverage already replayed. Test both commit orders, delete and recreate, and a purge while a census is in flight.

2. **Blocking — Vec recovery can be bypassed by an all-skip census or invalidate its loaded map mid-run.** Today recovery runs on vector-aware operations, and the writable store shortcuts the check after its first successful reconciliation. Reading the new table alone can accept fingerprints from a vec-disabled boot, then a search or a later replacement can wipe the vectors and records. A second host can also mark the shared DB stale after the first host warmed that shortcut. See `code-symbol.store.ts:410`, `:430`, `:479`, `:545`, Electron `phase-2-libraries.ts:450`, and CLI `register-thoth-libraries.ts:64`. Reconcile before trusting a skip or fetching a reusable vector, including on an all-skip run. Define how a database-wide wipe or a marker written by another connection invalidates loaded records. Check marker and donor data in a consistent SQLite snapshot. Clear records with the vector wipe and the marker in the same transaction. Specify recovery for vec-disabled writes, including zero-symbol replacements, and test outage and recovery with two connections.

3. **Serious — D2 does not define which outcomes are durable or what the all-error guard means after skipping.** Unreadable/oversized discoveries and hard read/parse errors bypass the replacement transaction. Recovered parses can write partial rows and increment errors, unsupported syntax can write partial rows with a failed outcome, and unknown parse quality is unchecked. A cached recovered result can therefore turn a formerly all-error census into a success with a purge. A mixed run can also hit “all files errored” when every actual parse fails while many files remain verified. See `code-symbol-indexer.service.ts:344`, `:1129`, `:1193`, `:1447`, and `:1623`. Start with successful, fully analyzed replacements, including empty results, as the only cacheable outcomes. Retry transient and incomplete results and report their real coverage. Define the guard against this policy, including all hits, mixed hits plus hard errors, recovered-only runs, and all discovery-stat failures. State whether valid hits count as sufficient evidence to allow destructive purge. Look up valid hits before the runtime gate if completely verified cached coverage should work without tree-sitter. Any eligible miss blocked by the runtime still makes the census incomplete and prevents purge.

4. **Serious — File records need their own deletion enumeration and invalidation rules.** `purgeMissing` enumerates paths only from symbols, and stale-root maintenance enumerates roots and terminates batches on symbol rows. A zero-symbol record survives both by construction unless those selectors change. The plan omits `purgeJunk` and `insertBatch`, which already change persisted rows outside the replacement path. See `code-symbol.store.ts:280`, `:324`, `:653`, `:719`, `:765`, `:1404`, `:1473`, and `memory-rpc.handlers.ts:677`. Enumerate both tables, delete records even when the symbol count is zero, and preserve bounded, abortable stale-root maintenance. Select rowids inside the delete transaction after async root validation. Invalidate all affected keys in alternate writers, including old and new paths on a subject conflict. Define omitted or null record arguments as invalidation and delete previous records on a committed replacement with missing vectors. Add file-only root, file-only path, junk purge, legacy insertion, and rollback specs.

5. **Serious — D4 leaves direct reindex free to index an arbitrary nested checkout.** Full discovery probes `.git` ancestors and the watcher has its own nested detection. Direct `reindexFile` currently tests only basename patterns, and D1 adds only globs and root ignores. A manual reindex of `vendor-wt/src/a.ts` can still write under the parent root and a concurrent census can preserve it through `keptPaths`. The audit's unconditional “no row” and the plan's “no production change” therefore overstate the guarantee. See `workspace-indexer.service.ts:645`, `:733`, `workspace-index-lifecycle.ts:156`, `code-symbol-indexer.service.ts:985`, `:1306`, and `code-namespace.builder.ts:494`. Validate containment and normalize the path, then share the nested ancestor check up to but excluding the requested workspace root. Specify how unknown probe results affect the guarantee and test direct calls against both a nested checkout and that checkout opened as its own root.

6. **Serious — D1 can disagree across the scan and watcher, and broad globs settle an open product choice.** The stream applies caller excludes after discovery and before stat/yield. It calls `compilePatternSet` without `dot: true`, while the watcher and proposed direct matcher enable it. Explicit dot segments can match, but additional hidden ancestors can change whether the globstar reaches them. See `workspace-indexer.service.ts:233`, `:429`, `:444`, `pattern-matcher.service.ts:292`, `:328`, and `workspace-change-coalescer.ts:185`. Use one normalized predicate or equivalent matcher options for every symbol path and prove parity with nested hidden parents, Windows separators, and root-relative paths. Decide the intended directory scope explicitly. `**/.claude/**` also excludes `src/.claude/example.ts`; the listed test for `libs/claude/x.ts` does not cover it. Root-anchor workspace harness directories if approval covers only workspace-level folders. Add the public workspace-intelligence barrel export to B1 (`src/index.ts:56`).

7. **Serious — D3 must protect hash–vector provenance on every write.** An indexed hash joined to a reused rowid can read a different symbol's old embedding after an outage. Even with vec available, legacy `insertBatch` can update text on the same rowid while preserving the old hash, and it deletes the old vec only when its new embedding is valid. See `code-symbol.store.ts:410`, `:545`, `:615`, and `:765`. Update or clear the hash on every writer, clear stale vectors even on an invalid replacement, and gate donors on recovery per finding 2. Use the full 64-character SHA-256 hex digest, or explicitly specify truncation. Dimension alone cannot distinguish two models of the same width. The current worker pins a model (`embedder-worker-client.ts:60`), so specify invalidation on embedding model or input-format changes across releases as well as runtime changes.

8. **Serious — The plan's proposed measurement cannot substantiate G6 or the embedding half of G7.** The current measurement design counts through an in-memory sink without SQLite or an embedder (`context.md:19`; `implementation-plan.md:189`). It can show avoided parse and replacement calls, but it cannot show actual embedder inputs, vec query cost, or reuse across roots. Keep that census measurement and add a temporary SQLite/vec0 store run with an instrumented embedder. Capture second unchanged pass, changed-file pass, and a second root with identical embedded text. Report parse attempts, actual embedding inputs, hits/misses, and lookup time. Explain the migration warm-up because legacy hash values are NULL.

9. **Moderate — Force needs an explicit contract while another census is running.** RPC start already forwards `params.force` and schedules a fresh attempt after joining an existing census. Resume supplies no force, and the reindex tool declines a second start while one is active. See `indexing-rpc.handlers.ts:178`, `:201`, `:232`, `:305`, `indexing-control.service.ts:1236`, and `code-namespace.builder.ts:512`. Thread the RPC parameter independently from governor admission. Define G5 as applying to accepted fresh requests and preserve the tool's busy result, or schedule a forced follow-up and expand the contract and specs. State whether resume ever needs to preserve a paused force. Present code restarts discovery without force. Test the RPC wrapper's fresh follow-up and verify boot/watch, task-end, lazy, and CLI remain non-forced.

10. **Moderate — mtime and ignore-cache invalidation need a defined consistency model.** Discovery stats can predate the locked read by several batches. The proposed cache keys an earlier stat to a later read and can outlive ignore-file replacement, recreation, or concurrent refresh. See `workspace-indexer.service.ts:450`, `code-symbol-indexer.service.ts:1099`, `:985`, `:1447`, and `ignore-pattern-resolver.service.ts:189`. Define the file key as a heuristic with known-metadata misses and a conservative pre/post-read check before persisting a key. Consider ctime where trusted. Share the ignore filename list and matcher, and specify creation/deletion, non-ENOENT errors, bounded per-root lifetime and refresh, and same-timestamp edits. Put the direct policy decision in the file-write path and give full runs a clear ignore snapshot policy. A first implementation can compile on debounced per-file calls or reuse a watcher-invalidated root snapshot after measuring it. Add a gitignored test outside every static exclude, since `.codex/c.js` cannot prove ignore handling.

11. **Moderate — D3 leaves the hot-path SQL and asynchronous boundary unspecified.** Use an indexed symbol lookup followed by a vec0 equality point lookup, or prove the proposed join uses those access paths on the pinned extension. SQLite-vec supports point reads of vector bytes by rowid, but join order and cost need measurement. Prepare once per connection as appropriate, deduplicate lookups and misses per replacement, and validate an owned BLOB of exactly `4 * dim` bytes. Capture the bytes before old rows can be deleted and before awaiting misses. Keep embedding outside the synchronous replace transaction and keep final vec, symbol, FTS and file-state changes atomic. Never retain a donor rowid across the await and resolve it afterward. Cover absent/bad blobs, nonzero Buffer offsets, prior rows from the same file, and a donor deleted during embedding. See `package.json:140`, `0013_code_symbols.ts:54`, and `code-symbol.store.ts:545`, `:584`, `:633`. [sqlite-vec 0.1.9 point-query implementation](https://github.com/asg017/sqlite-vec/blob/v0.1.9/sqlite-vec.c#L6914)

12. **Moderate — All-hit runs can leave lazy freshness permanently stale.** The namespace judges freshness by newest symbol-row timestamp and treats zero symbols as stale. An unchanged census will leave those signals unchanged, and the process-local throttle only limits how often it retries. See `code-symbol.store.ts:850` and `code-namespace.builder.ts:246`, `:314`. Define a root-scoped successful-validation time distinct from row-write time, including zero-symbol workspaces. Advance it only on a qualifying census. Specify that skipped files count as processed, `symbolsIndexed` still counts rows written this run, and coverage supplies the analyzed count. Add specs for lazy freshness after an all-hit census and stats persistence/display.

13. **Moderate — The migration batch misses other hard-coded latest-version assertions.** `migrations/index.ts:525` and `0076_cron_job_creator.spec.ts:42` confirm the current version. Older specs also assert 76, including `0038_gateway_message_turn_state.spec.ts:92`, `0070_indexing_last_run.spec.ts:30`, and `0075_phase_grade_keys.spec.ts:48`. Expand B2 to cover all affected assertions, preferably replacing old latest checks with assertions about each migration's registration and ordering. Test an upgrade from 0076 with existing FTS/vec data, a vec-disabled open, and the intended rollout when Electron and CLI share a DB.

## Answers

1. **Audit claims.** A1's cost finding holds for eligible files that reach a successful write with vec available. Stat/size checks and missing parser runtime bypass that work (`code-symbol-indexer.service.ts:1129`; `code-symbol.store.ts:545`). Watcher deletes take the delete path, and RPC resume calls `resume` before `start` (`workspace-index-lifecycle.ts:342`; `indexing-rpc.handlers.ts:305`; `indexing-control.service.ts:1236`). The forced RPC's follow-up already exists (`indexing-rpc.handlers.ts:201`). Coverage counts both unwritten selected files and explicitly unchecked writes (`code-symbol-indexer.service.ts:674`, `:686`). The JS recognition-only mechanism is correct (`javascript.language.ts:298`; `language-registry.ts:410)); the static code does not establish the audit's exact totals.

   A2's pipeline is correct, including how deferred discovery and basename skips work, but “shared” means shared defaults, not equivalent filtering (`workspace-indexer.service.ts:429`, `:645`; `code-symbol-indexer.service.ts:115`, `:127`, `:1054`). The five root ignore files and limited pattern semantics are supported (`ignore-pattern-resolver.service.ts:189`, `:406`). The cited live-sync lines show globs and segment rules rather than ignore-file matching (`folder-index-live-sync.ts:101`, `:145`). The example `tools/perf/out/**` is already covered by `**/out/**` (`workspace-default-excludes.ts:24`). An ignored path disappears only after a successful uncapped census whose snapshot excludes it and whose concurrent writes did not keep it. A4 can promise preservation of existing shared-walker behavior only. Root ignores already name `.claude/*` and `.codex/**` (`.gitignore:155`, `:201`), and grep has its own ignore policy (`index-audit.md:95`).

   A3 is correct for successful full discovery and watcher filtering, with the manual/probe exceptions in finding 5. Rows stay root-scoped, and vector reuse is for exact embedded text, which includes a relative path and line ranges (`0013_code_symbols.ts:25`; `code-symbol-indexer.service.ts:1523`). Linked worktrees with the same package identity share a fingerprint. Worktrees on branches that change or remove it can derive a different key, so “every” is too broad. Main uses the git key when an origin is readable. HEAD lookup fails on a gitfile as described (`workspace-fingerprint.ts:34`, `:50`, `:84`). The six-hour maintenance throttle is per store instance and successful pass, and removal also requires a readable parent (`code-symbol.store.ts:246`, `:285`). The audit's mechanism claims are traceable from source. A5 and its numbers were outside this review.

2. **Skip unchanged.** A per-file table is justified by clean zero-symbol files. A per-row column avoids separately purging file-only records but cannot represent those files. Treat the file state as proof of a committed result, condition skip on current state under the lock, and handle the mutation and outage cases in findings 1–4. Preserve the cap before skip selection, `omittedByCap`, and no purge on truncated, discovery-failed, runtime-blocked or aborted runs. Completed file commits can survive abort and qualify on retry. Check abort after any new awaited lookup/lock and preserve the existing final-batch and pre-purge checks (`code-symbol-indexer.service.ts:1099`, `:1120`, `:1180`, `:1212`).

3. **Vector reuse.** The rowid join is a viable query shape once the pinned planner and raw BLOB behavior are confirmed and the store guarantees rowid provenance. A hash-indexed candidate lookup plus a vec0 point read gives a bounded path per candidate. Capture the donor bytes synchronously, await embedding only for unique misses, and retain the current synchronous transaction for the final writes. See findings 2, 7 and 11.

4. **Excludes.** The caller filter affects yielded paths and thus purge membership. It does not prune the underlying walk. Purge can remove old excluded rows after a successful complete census, subject to tombstone and kept-path handling. An mtime-only ignore cache is a heuristic. Electron and platform-cli both expose millisecond mtimes, but the CLI full walk currently omits hidden entries by default where Electron explicitly includes them (`electron-file-system-provider.ts:80`, `:240`; `cli-file-system-provider.ts:82`, `:240`). Test hidden eligible paths in both hosts to pin the intended parity, particularly if they index the same root and database. No host-specific API is needed for the shared predicate, and the existing watcher wire list limit accommodates these globs (`workspace-watch-protocol.ts:42`, `:82`). The any-depth `.claude` policy still needs a scope choice.

5. **Force.** RPC force comes from `params.force`. `userInitiated` controls governor admission. Resume has no force by current contract. A manual tool reindex can explicitly request force when starting a census, while file-specific reindex remains unconditional after scope checks. Lazy calls use the background path (`code-namespace.builder.ts:314`, `:494`), task-end supplies its own background deps (`task-end-hook-composition.ts:283`), and Electron boot plus CLI subscribe through the shared lifecycle (`boot-thoth-runtime.ts:518`; `cli-workspace-index.ts:124`; `workspace-index-lifecycle.ts:365`). No force wiring is needed in those background callers. Add contract specs for the busy and resume cases.

6. **Gaps and simpler design.** Implement a committed analyzed-only file cache, start with a live indexed lookup under the existing lock, and add bulk lookup only with a measured need and a defined invalidation protocol. Use an explicit vector point query unless the join is proven efficient. Add specs for zero-symbol files and roots, cached/failing mixtures, incomplete parses, runtime outage, cap and abort, concurrent delete/reindex, ignore mutation, vec recovery across connections, malformed embeddings, migration and actual embed inputs. The silent failure is stale coverage or a vector attached to the wrong text. The surprising actions are manual reindex while boot is active or reindexing a nested file directly. Ordinary inputs that expose wrong results include empty files and same-size edits at an identical mtime. Dependency failures should cause a retry or incomplete census where appropriate, while preserving FTS on an embedder failure. The missing contract is what an unchanged verification means for freshness, purge admission, and recovery across hosts.

## Decisions

- Retain the per-file schema as the preferred design over the earlier per-row column, conditional on transaction and invalidation changes. It represents verified zero-symbol results without inventing symbol rows. Start by caching successful analyzed outcomes only. This policy can be broadened later with explicit failure semantics.
- Keep RPC force tied to the request parameter and leave resume and background callers incremental. The alternatives are making all user-admitted calls force or persisting force on pause. This is reversible in the call-site contract and preserves existing resume behavior.
- Leave the breadth of harness-folder exclusions and any worktree control-state key change with the existing approval process. Root-anchored harness exclusions are the narrower default if the intended scope is workspace configuration. D3 can retain root-scoped symbol rows with vector reuse once the lookup and invalidation contracts are specified.
- Review scope was static source and document inspection at `467a1ddb6`. No tests or builds ran. The dedicated `ptah_read_symbol` and `ptah_grep` tools were absent from the connected tool list. I used Ptah file reads for source ranges and native `rg` for text searches. No host skill loader or orchestrator skill discovery was exposed.
