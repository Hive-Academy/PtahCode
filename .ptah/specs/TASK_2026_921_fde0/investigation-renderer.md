# Renderer startup freeze investigation

## 1. ClaudeRpcService RPC timing

- Renderer service: `libs/frontend/core/src/lib/services/claude-rpc.service.ts:109`. Default timeout 30,000 ms (`:23-24`); `chat:start`, `chat:continue`, `chat:resume` default to `CHAT_ADMISSION_RPC_TIMEOUT_MS`, while `options.timeout` overrides both (`:26-41`, `:150-155`).
- `call()` installs a timer, registers correlation ID, then posts RPC (`libs/frontend/core/src/lib/services/claude-rpc.service.ts:174-188`, `:220-224`). Timer deletes the pending resolver and returns a failed result without error code (`:174-185`). Response handler calls the resolver only if still pending (`:260-264`), and the resolver clears the timer (`:188-203`). Thus a queued response **can win** after a 34 s block if its handler runs before the timer callback; timer-first discards the later response. The code cannot establish which ran first in the incident. There is no retry in `call()` (`:145-225`).

## 2. RendererFrame reporting

- Installed by initializer at `apps/ptah-extension-webview/src/app/app.config.ts:253-254`; observes `long-animation-frame`, or `longtask` fallback, with >200 ms threshold and 10 s log spacing (`libs/frontend/core/src/lib/services/renderer-frame-monitor.service.ts:74-83`). Logs rounded duration, entry type, blocking duration, and optionally longest script (`:84-99`).
- It reads script `duration`, `invoker`, `sourceFunctionName`, `sourceURL` (`libs/frontend/core/src/lib/services/renderer-frame-monitor.service.ts:41-60`), truncates text/path (`:4-5`, `:19-38`), but does **not** read `invokerType` or `forcedStyleAndLayoutDuration` (`:41-49`, `:86-95`). Missing `script` in supplied entry means no script attribution was emitted (`:53-60`, `:93-94`).
- `LoggingService.warn` keeps in-memory history and writes console warning (`libs/frontend/core/src/lib/services/logging.service.ts:171-175`, `:230-251`, `:274-275`). Electron forwards renderer warning/error `console-message` events to persistent logger (`apps/ptah-electron/src/services/diagnostics/process-lifecycle-recorder.ts:189-190`, `:199-206`, `:233-242`), with a 20-line window limit and bounded text (`:59`, `:215-227`).

## 3. Startup main-thread blockers

- `main.ts` dynamically imports Angular and bootstraps `App` (`apps/ptah-extension-webview/src/main.ts:36-49`). App initializers construct attention/frame monitor/adoption/route services (`apps/ptah-extension-webview/src/app/app.config.ts:250-254`, `:295-304`). Chat lifecycle kicks off session list and CLI restore asynchronously (`libs/frontend/chat/src/lib/services/chat-store/chat-lifecycle.service.ts:23-24`, `:56-64`). These overlap startup RPCs.
- **Ranked hypotheses, none established:** (1) a later synchronous state bridge read blocked behind a busy main process: renderer `getState()` calls `ipcRenderer.sendSync('get-state')` (`apps/ptah-electron/src/preload.ts:24-25`; `libs/frontend/core/src/lib/services/vscode.service.ts:226-237`), and ~34 s of main-process stall would block renderer. Preload's `get-startup-config` and the head theme read also use sync IPC (`apps/ptah-electron/src/preload.ts:18-19`; `apps/ptah-extension-webview/src/index.html:37-44`), **but both precede frame-monitor construction** (`apps/ptah-extension-webview/src/app/app.config.ts:253-254`), so they cannot directly be the observed frame. (2) restored tabs/transcripts rendered with markdown/layout; 30 s would require unusually many mounted messages or huge markdown/code blocks (`libs/frontend/chat/src/lib/services/chat-store/chat-lifecycle.service.ts:56-64`; `libs/frontend/chat/src/lib/components/molecules/lane-event/lane-event-row.component.html:106`). (3) huge IPC payload clone/dispatch and signal effects; preload dispatches received object into synchronous `MessageEvent` (`apps/ptah-electron/src/preload.ts:68-69`), but payload size is unknown. (4) full-list loops or virtual scroll measurement; 30 s would require a very large list, whereas RecentSessionsStore itself merges at most six rows (`libs/frontend/chat/src/lib/services/session-list/recent-sessions.store.ts:59-74`, `:138-154`).
- RPC transport is async `ipcRenderer.send('rpc')` (`apps/ptah-electron/src/preload.ts:20-23`). The identified sync IPCs are startup config and state (`:18-29`); targeted search found no synchronous XHR in the inspected renderer/Electron trees. Source alone does not show a 34 s loop or payload.

## 4. RecentSessionsStore session-list failure

- Log site is `libs/frontend/chat/src/lib/services/session-list/recent-sessions.store.ts:77-82`. `load()` sends two parallel `session:list` RPCs, pinned true/false, each limit 3, offset 0, lastActive sort (`:45-74`). It accepts and records any string, including `""` (`:45-55`). Vitals source filters `null` but not empty string (`libs/frontend/chat/src/lib/services/vitals/chat-vitals.store.ts:53-56`, `:103-114`).
- Empty path is invalid: session backend checks authorization (`libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts:543-564`), and helper returns false for empty path (`libs/backend/rpc-handlers/src/lib/utils/workspace-authorization.ts:45-52`). Undefined error codes fit timeout results, which carry an error string but no code (`libs/frontend/core/src/lib/services/claude-rpc.service.ts:174-185`), although the log omits result errors so cannot prove timeout (`libs/frontend/chat/src/lib/services/session-list/recent-sessions.store.ts:77-82`).
- The store waits in `Promise.all` without a 60 s timer (`libs/frontend/chat/src/lib/services/session-list/recent-sessions.store.ts:58-75`); each call normally has a 30 s timeout (`libs/frontend/core/src/lib/services/claude-rpc.service.ts:23-24`, `:151-155`). The ~59 s gap could mean these requests started ~30 s after the burst or callbacks were delayed. Two parallel 30 s timers do not sum to 60 s.

## 5. Root-cause conclusion and instrumentation

- **Root cause is unproven.** The 34.4 s frame can delay both IPC handlers and timeout callbacks (`libs/frontend/core/src/lib/services/renderer-frame-monitor.service.ts:79-96`; `libs/frontend/core/src/lib/services/claude-rpc.service.ts:174-203`; `apps/ptah-electron/src/preload.ts:68-69`), but neither culprit nor IPC arrival order is recorded. Missing script attribution is not evidence of no JS work (`libs/frontend/core/src/lib/services/renderer-frame-monitor.service.ts:53-60`, `:90-96`).
- Next occurrence: capture a renderer CPU profile spanning startup plus Chromium Performance trace; add monotonic send/receive/timeout timestamps, correlation ID, method and payload sizes at `libs/frontend/core/src/lib/services/claude-rpc.service.ts:145-155`, `:174-224`, `:260-264`; time sync bridge and main handlers at `apps/ptah-electron/src/preload.ts:18-29`; record frame scripts, invoker type, forced-layout duration at `libs/frontend/core/src/lib/services/renderer-frame-monitor.service.ts:41-49`, `:90-96`; record restored tabs/messages and IPC payload sizes. Existing asynchronous CPU-profile bridge is `apps/ptah-electron/src/preload.ts:55-64`; initiate capture before freeze rather than from frozen DevTools.
