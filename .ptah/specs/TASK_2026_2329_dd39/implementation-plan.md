## Shared overlay contract

- Use CDK as the shared overlay backend in `@ptah-extension/ui`. Move rich-select lists and settings popovers onto one connected-overlay positioning policy based on the existing position maps. Use CDK Dialog for the existing modal and drawer shells, with center and side layouts. Keep selectors, bindings, projection slots and close/reopen semantics stable so the settings consumers can adopt the change in place. Preserve plain and scrolling shell layouts, action slots, theme tokens and legitimate repositions.
- Portals must escape scrolling containers and share a predictable stack with their parent dialog/drawer. Put the topmost layer in charge of Escape and outside/backdrop handling. Restore child focus to its trigger, then restore parent focus on parent close. Handle a focusable search field in an open child alongside dialog focus containment. Apply viewport margins, preferred and fallback placements, bounded width/height and a scrollable options region. Match the select to its field width within viewport bounds. Reposition for registered scroll containers and viewport changes while open. Dispose listeners, portals and scroll locks on close and destroy. Check theme inheritance and Electron pointer interaction for portal content.
- Use open-layer template refs or its panel reference for focus and test queries. Element queries rooted at the outer component host can miss portaled content, for example `provider-consumer-assignments.component.ts:881–889`, `main-agent-reassign-popover.component.ts:682–696` and `cli-tier-mapping-modal.component.ts:311`. Retain registered trigger IDs, accessibility names, keyboard navigation, selected values and CVA behavior. Shared caller checks include the chat UI and existing renderer overlay CSS.

## Settings behavior

- **Lanes.** Give Network controls and the model/effort group explicit shrinkable cell layouts. Use the existing width tiers (640px model threshold and 950px table collapse) and keep headers, colgroups and row spans aligned. In a wide row, keep the Model label bounded to its own cell. Use the existing compact fallback at narrower widths. Put the editable Ptah-wide defaults in one labeled Defaults action beside the group identity, with Permission, Network and Reset inside. Expanded instance rows retain read-only inherited values in their labeled details. Move the lane access confirmation from the direct `<dialog>` at `cli-lane-default-cell.component.ts:414` onto the shared shell.
- **Subforms.** Give the provider drawer a compact title, current step, one scrolling field body and a pinned action row. Keep one primary action per step, including Done after save. Preserve discard review, verification, scope selection, error/retry and keyboard navigation. In add/edit instance use one real submit button in the footer associated with the body form, keep errors by their fields and keep save/cancel visible while scrolling. Validate the tier dialog and connection detail drawer against the same shell.
- **Background models.** In the settings host, pass the resolved provider identity and auth label from the selected workspace’s effective route to the picker separately from its draft selection. Resolve catalog provider in order: fixed provider, explicit draft provider, then supported resolved route provider for an inherited draft. Treat loading, unresolved and unsupported routes explicitly and skip catalog fetches until an eligible ID exists. Key the load, retry, saved-list notice and errors to the effective provider and discard stale results after provider/workspace changes or close. Keep the existing behavior of the shared loader port for callers outside this settings flow. Enable the shared rich-select controls for the settings picker, including searchable model options, and keep labels, manual IDs and inline feedback within the available pane width.
- **Model semantics.** Show the explicit saved/pending model ID first, including IDs absent from the catalog. An empty Memory curator model means the effective provider’s Haiku tier (`libs/backend/agent-sdk/src/lib/curator-llm-adapter/sdk-internal-query.curator-llm.ts:367–388`); Enhancement’s `inherit` also resolves through a role tier (`libs/backend/skill-synthesis/src/lib/skill-enhancer.service.ts:1023–1047`). Use a concrete model only when a provider/tier mapping is known, otherwise label the effective provider and role tier. The route’s main-chat model is useful context where explicitly labeled. Keep the blank provider/model and Enhancement `inherit` sentinels on write. Reset the draft model on a user-selected provider change using existing behavior. Keep Setup’s pair semantics and Decision’s independent picker, and preserve scoped review and save/read-back.
- **Evidence.** Derive a signal-based view from the existing response. Summarize each CLI with catalog status/freshness and measured-model count. Show compact per-model summaries and only sampled task/effort chips (`sampleCount > 0`). Use native disclosures for per-model detail, including labeled score and sample count, outcomes, provenance and the existing funnel metrics. Distinguish family-default evidence and historical models, with one compact empty state per CLI and an optional disclosure for catalog-only models. Count measured cells or models in summaries so overlapping effort aggregates are never summed as independent outcomes. Keep decision-model outcomes, loading, retry, unknown scores and empty results visible and understandable. Use existing Angular UI tokens, readable labels independent of color, wrapping layouts and no per-row observers.

## Decisions

| Decision | Options and evidence | Reversible |
| --- | --- | --- |
| Adopt CDK in the existing UI shells | Reuse the public shells and CDK position maps, or create parallel settings components. Existing settings, chat UI and shared hosts already import the shells, and the renderer loads CDK CSS. Reusing them preserves one contract and avoids per-surface z-index tuning. | Yes, internal implementation behind the same inputs, outputs and slots. |
| Resolve catalog context in the settings view | Pass the explicit effective provider from the existing route read, or change the generic RPC fallback. The view knows inheritance, role readiness and workspace context. | Yes, with the saved schema and RPC contract intact. |
| Use sampled chips and disclosure for evidence | Chips or a dense matrix fit the sparse response. Chips wrap in the Electron sidebar and expose counts as text. | Yes, presentation-only. |
