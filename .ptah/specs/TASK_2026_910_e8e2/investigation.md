# Token budget and handoff investigation

Scope: main checkout source and Electron logs, read-only. No tests run.

## Defect 1 — findings

1. **Symptom:** 3M budget stops CLI lanes. **Root cause:** `agentBudget.stopWeightedTokens` defaults to 3,000,000; `AgentBudgetPolicy.assess` stops at `max(raw, weighted) >= limit`; telemetry calls the stop callback and process manager calls `stop`, discarding queued messages. This contradicts the older agent-lanes skill. **Evidence:** `libs/shared/src/lib/types/advanced-settings.types.ts:165-175`; `libs/shared/src/lib/utils/agent-budget-policy.ts:95-106`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/lane-budget-telemetry.ts:78-95`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/agent-process-manager.service.ts:1601-1631`; `.claude/skills/agent-lanes/SKILL.md:276-279`. **Confidence: high.**

2. **Symptom:** a short lane exceeds 3M. **Root cause:** raw usage adds all per-turn input and output, including cached input at full raw weight. Weighted usage is `max(raw, model catalog cost / $0.000003)`, falling back to raw if pricing is unavailable. Thus class weights vary by model price divided by the fixed $3/M input reference; there are no fixed lane weights. Nov 10 line 3279 reports Glm lane `780e65f6` at 4,034,723 input, 3,900,160 cached, 4,075,542 total after one turn. **Evidence:** `libs/shared/src/lib/utils/agent-budget-policy.ts:6-8,76-88,115-140`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/codex/codex-lane-events.ts:284-299`; `C:\Users\abdal\AppData\Roaming\Ptah\logs\Ptah Electron-2026-11-10.log:3279`. **Confidence: high.**

3. **Symptom:** resumed Codex lane inherits usage. **Root cause:** budget ledger is per CLI session lifetime. `rebindRecord` adds prior ledger and keeps earliest start; `accept` deduplicates normalized turn IDs (last 256 retained). Codex stores intermediate usage snapshots and emits once at terminal; its `turn.completed` is a sum of requests within one turn. Nov 10 log line 3220 gives first lane 1,313,635; line 3725 gives resumed total 3,911,448, exactly first plus new turn 2,597,813. No confirmed vendor cumulative snapshot double count on this path. **Evidence:** `libs/backend/cli-agent-runtime/src/lib/cli-agents/agent-budget-coordinator.ts:16-33,64-82,92-107`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/codex/codex-lane-events.ts:216-245`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/codex/codex-rollout-usage.reader.ts:9-17`; Nov 10 log lines 3220,3725. **Confidence: high.** Other adapters reporting cumulative totals as turns remain a hypothesis.

4. **Symptom:** warning appears only in stop message. **Root cause:** warning threshold is 0.85, with predictive largest-turn check, but accounting occurs on completed turns. When one turn crosses warn and stop together, dispatch skips warning; completion envelope appends it after stop. Queue-only adapters deliver warnings next turn, and stop discards pending messages. **Evidence:** `libs/shared/src/lib/types/advanced-settings.types.ts:165-168`; `libs/shared/src/lib/utils/agent-budget-policy.ts:95-106,130-140`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/lane-budget-telemetry.ts:7-31,84-95`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/lane-completion-envelope.ts:34-50`; Nov 10 log lines 2873-2874,3279. **Confidence: high.**

5. **Symptom:** resume refused after budget stop. **Root cause:** `LaneResumeGate.evaluate` explicitly returns `fresh` for budget stop, near limit or expired duration. This is a Ptah policy; no vendor technical refusal was found in this path. Budget stop calls process kill rather than vendor compaction or a handoff grace turn. **Evidence:** `libs/backend/cli-agent-runtime/src/lib/cli-agents/lane-resume-gate.ts:117-140`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/agent-process-manager.service.ts:1601-1631,3691-3731`; `libs/backend/cli-agent-runtime/src/lib/cli-agents/lane-completion-envelope.ts:105-106`. **Confidence: high** for policy and stop; **medium** for absence of any compaction path across every adapter.

## Defect 2 — findings

1. **Symptom:** configured 30M sessions reach limit without automatic handoff. **Root cause:** source default is 50M, but host log confirms 30M configured. Automatic handoff is a separate opt-in setting defaulting to false; backend exports that flag and renderer requires `budget.autoHandoff === true`. Saved flag value for these sessions is unverified, so default-off is the strongest code-supported cause, not a proven runtime setting. **Evidence:** `libs/shared/src/lib/types/session-budget.types.ts:153-173,228-232`; `libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget-config.provider.ts:36,128-130`; `libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget.service.ts:536,569`; `libs/frontend/chat/src/lib/services/session-auto-handoff-coordinator.service.ts:305-319`; Nov 9 log lines 27937-27938 (30,022,298/30M), 30215 (31,151,153/30M). **Confidence: high** for gate/default, **medium** as explanation of this user's case.

2. **Symptom:** banner offers handoff but no automatic command. **Root cause:** manual button and auto coordinator are separate. Root coordinator watches mounted tabs, requires matching session ID, limit stage, opt-in, skill availability, no pending permission or resume, and no prior claim/cancel/manual wrap-up. It uses `sendOrQueueMessage` for `/session-handoff`; missing skill suppresses auto for session, failed send retries. Skill is responsible for HANDOFF.md and `ptah_session_handoff`. **Evidence:** `libs/frontend/chat/src/lib/services/session-budget-actions.service.ts:41-59`; `libs/frontend/chat/src/lib/services/chat.store.ts:107`; `libs/frontend/chat/src/lib/services/session-auto-handoff-coordinator.service.ts:108-145,149-203,305-319`; `.claude/skills/session-handoff/SKILL.md:2-9,52`. **Confidence: high.**

3. **Symptom:** threshold does fire in accounting. **Root cause:** token mode uses session snapshot `tokenCount` (sum of input, output, cache-read, cache-creation) against configured tokens; >=100% gives `limit`. Budget service accepts live and loaded snapshots, records compactions per session; in-turn estimate is display-only. Backend computes stage; renderer alone initiates automatic command. **Evidence:** `libs/backend/agent-sdk/src/lib/session-stats/session-usage-aggregator.ts:435-453`; `libs/backend/agent-sdk/src/lib/session-stats/session-stats-owner.service.ts:1352-1363`; `libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget-stage.ts:74-90,123-137`; `libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget.service.ts:170-205,273-283`; Nov 9 log line 27938 (`compactions:3`). **Confidence: high** for live/compaction, **medium** for restart persistence.

4. **Symptom:** one real handoff tool call failed. **Root cause:** Nov 10 log records approved `ptah_session_handoff` refused because `C:\Users\abdal\.ptah-session-master\HANDOFF.md` was outside an open workspace. Whether automatic is unknown. **Evidence:** Nov 10 log lines 6-8. **Confidence: high** for refusal, **low** for auto connection.

5. **Shared code?** No common accumulator or weighting: lane uses `AgentBudgetCoordinator`/`AgentBudgetPolicy` with raw floor plus catalog-price normalization; chat uses `SessionStatsOwnerService`/`SessionBudgetService` with raw token count in token mode. Fixed session fallback weights are input 1, cache creation 1.25, cache read 0.1, output 5, applied only in cost mode when unpriced. **Evidence:** `libs/backend/cli-agent-runtime/src/lib/cli-agents/agent-budget-coordinator.ts:16-33`; `libs/shared/src/lib/utils/agent-budget-policy.ts:115-140`; `libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget-stage.ts:74-111`; `libs/backend/agent-sdk/src/lib/helpers/session-budget/weighted-tokens.ts:1-34`. **Confidence: high.**
