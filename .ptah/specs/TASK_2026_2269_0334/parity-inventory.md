## Observed UI problems

Code-supported structural findings; no claims about measured rendering, contrast, screenshots, or usability testing.

1. **Repeated title in analysis.** Page h1 and embedded review h2 both say “Review skills”, separated by summary/draft content (`analyze-skills.page.ts:23`; `stack-skill-review.component.html:3`). This repeats the label within one page.
2. **Unbounded content precedes the main choice.** Detected items, failures, and unmatched items are unrestricted loops; every unmatched framework/pattern adds a full editor before review (`analyze-skills.page.ts:27`, :35, :40; `analyze/project-skill-draft.component.ts:16`). There is no local collapse/pagination for these regions.
3. **Dense stacked card metadata.** Name/key/description/evidence/score all occupy block spans inside one label; there is no separate metadata grouping or length cap. The identity, evidence and score share small muted styling (`stack-skill-review.component.html:39` through :52). Search cards use a different information subset (:102).
4. **Uneven long-text handling.** Keys explicitly break-all, while names, descriptions and evidence have no analogous wrapping/line-clamp utility (`stack-skill-review.component.html:40` through :52). This is a code-level styling difference; overflow was not rendered or measured.
5. **Overlapping zero-selection actions.** “Skip skills” and “Continue without skills” are adjacent and invoke the same next destination in both hosts when nothing is selected (`stack-skill-review.component.html:182`; `team-builder-start.page.ts:273`; `analyze-skills.page.ts:178`).
6. **Multiple primary actions can coexist in analysis.** Each unmatched draft exposes primary Create before review's primary Continue; no single page-wide action group coordinates them (`analyze-skills.page.ts:42`; `analyze/project-skill-draft.component.ts:21`; `stack-skill-review.component.html:193`).
7. **Narrow-width footer limitation.** Outer review footer wraps, but the inner Skip/primary pair is `flex gap-2` without flex-wrap, while the primary label grows with selection count (`stack-skill-review.component.html:172`, :182, :198). Consent footer likewise has no wrap (:72). No rendered overflow claim.
8. **Busy coverage differs by host/control.** Review navigation and owner decisions respect busy, but search field/button and skill checkboxes lack a busy lock (`stack-skill-review.component.html:32`, :71, :80, :95, :137). Team installing adds inert around review; analysis does not and passes only leaving as review busy (`team-builder-start.page.html:98`; `analyze-skills.page.ts:50`). Analysis consent covers installing, but underlying review controls remain locally enabled.
9. **Manual zero results has no explanatory state.** Search results are a loop without empty-result message, query echo or result count; only recommendation emptiness has a state panel (`stack-skill-review.component.html:22`, :85, :91`). No-results and not-yet-searched share the absence of result cards.
10. **Consent exposes full hashes prominently but hides file lists behind disclosures.** Hash is always shown in text-xs mono; scripts and all files require opening details (`stack-skill-consent.component.html:25`, :32, :45`). This is the present information hierarchy.
11. **Busy/modal feedback is asymmetric.** Team has an installing live status plus modal label change; analysis only changes modal button to Installing…, without a dedicated installing live region (`team-builder-start.page.html:95`; `analyze-skills.page.ts:57`; `stack-skill-consent.component.html:88`).
12. **Existing spec has a stale action-text matcher.** Busy-navigation test matches “Back to intent”, while actual review label is “Back”; its filtered every() assertion therefore does not pin this button (`team-builder-skill-review.component.spec.ts:40`; `stack-skill-review.component.html:180`).
