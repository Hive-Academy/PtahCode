# Electron skills capture repair

Status: capture repaired; all five Electron capture cases passed. Product layout limitations are recorded below.

## Root causes
The renderer never received a durable workspace root. `AnalyzeSkillsPage` loads recommendations only when both runId and root exist (`libs/frontend/onboarding/src/lib/analyze/analyze-skills.page.ts:158-170`). The original fake RPC listener returned a generic object for unmocked methods (`apps/ptah-electron-e2e/src/support/ui-driver.ts:158-165`). `workspace:getInfo` consequently had no folders, and `ElectronLayoutService` cleared the workspace (`libs/frontend/core/src/lib/services/electron-layout.service.ts:910`, `:954-959`). Seeding preload startup config alone was insufficient: capture attempt 1 still showed “No folder open” and no recommendation call.

The docs fixture already launches a disposable sample repository (`apps/ptah-electron-e2e/src/docs-screenshots/_harness/docs-fixtures.ts:54-73`); the real repository was never opened as a workspace. The repair follows the existing mocked workspace pattern in `apps/ptah-electron-e2e/src/docs-screenshots/v2-surfaces.shot.ts:10-11`, plus the supported `UiDriver.seedStartupConfig` API (`support/ui-driver.ts:182`).
