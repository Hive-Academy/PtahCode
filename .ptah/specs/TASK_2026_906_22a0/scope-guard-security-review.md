# Scope guard security review — d879c5178

**Verdict: REVISE.** Electron child RPC authorization has exploitable gaps. Source review only; no tests, builds, lint, or `nx` commands were run. No matching security review skill was available in the discovered skills.

## Findings

1. **High — A scoped child can cancel a commit in another repository.** `apps/ptah-electron/src/windows/git-window-scope-guard.ts:23-26` treats `git:cancelOperation` as unscoped. The handler at `libs/backend/rpc-handlers/src/lib/handlers/git-workflow-rpc.handlers.ts:135-149` calls the global `gitInfo.cancelOperation(operationId)` without a root. **Bypass request:** `git:cancelOperation`, `{ "operationId": "<ID of an in-flight commit in repo B>" }` while the child is scoped to repo A. IDs can be obtained from the unfiltered `GIT_OPERATION_OUTPUT` push (finding 2), or a caller that already knows one can use it directly. **Smallest correction:** bind operation IDs to their repository when registered and require the current acknowledged `repoRoot` to match before cancellation; remove this method from the unscoped list.

2. **High — Mirrored pushes expose events from all repositories.** `apps/ptah-electron/src/windows/child-window-registry.ts:139-149` checks only event type, and `apps/ptah-electron/src/ipc/ipc-bridge.ts:252-253` forwards before any scope filter. `apps/ptah-electron/src/windows/git-window.ts:47-50` includes Git status, file change, operation output, and worktree change events. **Bypass request:** with child scope `{ repoRoot: "A", workspaceRoot: "A" }`, cause any host `sendToRenderer({ type: MESSAGE_TYPES.GIT_STATUS_UPDATE, payload: { workspaceRoot: "B", files: [...] } })` or `GIT_OPERATION_OUTPUT` for B; the child receives it despite having no B authorization. Status reveals B's paths/branch; operation output can contain hook or remote output and operation IDs. File change and worktree events also leak B path metadata. **Smallest correction:** route only pushes whose canonical repository identity matches the current child scope; add an explicit trusted root to push payloads that lack one, and drop unidentifiable events rather than mirroring them.

3. **High — Lexical file authorization can follow a symlink into another registered repository.** `apps/ptah-electron/src/windows/git-window-scope-guard.ts:53-60,138-146` checks the request path lexically. The backend file policy (`libs/backend/rpc-handlers/src/lib/handlers/file-link-root-policy.ts:449-480`) accepts real targets under *any* registered workspace or worktree. **Bypass request:** with A and B registered, and `A/link.txt` a symlink to `B/secret.txt`, call `file:viewContent`, `{ "path": "A/link.txt", "workspaceRoot": "A" }` from the child scoped to A. The guard accepts A/link.txt, and the backend accepts its real target in B. The same path shape reaches `file:saveContent` (with valid `content` and `expectedSha256`) and `editor:openFile` (with a valid `target`). **Smallest correction:** for child file/editor RPCs, resolve the actual target and compare against the child scope's canonical roots immediately before use, or pass scoped roots into the backend file policy so its final realpath check enforces the child scope.

4. **Medium — Worktree creation accepts an arbitrary absolute destination.** `apps/ptah-electron/src/windows/git-window-scope-guard.ts:105-110` checks only `workspaceRoot` for `git:addWorktree`; `libs/backend/vscode-core/src/utils/worktree-path.ts:43-51` deliberately accepts an absolute `path` outside that root. **Bypass request:** `git:addWorktree`, `{ "workspaceRoot": "A", "branch": "feature", "path": "B/new-worktree", "createBranch": true }` from a child scoped to A. It creates files under B (if the destination is vacant), outside the acknowledged roots. **Smallest correction:** for child calls, require the resolved destination to be inside an approved worktree creation area for A. Keep the main window's existing absolute path behavior.

## Items examined without another demonstrated bypass

- **Other allowlisted parameters:** `git:reviewFile`/`git:diffFile`/`git:applyHunks` paths and `git:stage`/`git:unstage`/`git:discard` `paths[]` are not checked by the guard. The Git handlers resolve the named root; Git pathspecs cannot select a second repository, and the diff worktree read checks physical containment. `git:removeWorktree.path` is passed to Git for the selected repository, which rejects a path that is not one of that repository's worktrees. No separate other-repository bypass was established for these fields. `settings:*` and editor target choices do not select a Git repository.
- **Path forms:** `path.resolve` normalizes `..` and trailing separators; win32 keys fold drive-letter and UNC path case. No direct lexical `..`, drive-case, separator, or UNC alias bypass was found. Relative `workspaceRoot` is normalized by the guard, but the Git root resolver requires a registered root or confirmed worktree, so no executable other-repository alias was established. Symlinks are the exception in finding 3.
- **`observeResult` worktree list:** `apps/ptah-electron/src/windows/git-window-scope-guard.ts:114-135` records only a successful host `git:worktrees` result for a scope root and resets when scope roots change. The child cannot supply `response.data` directly or poison the list through the IPC request; no independent poisoning bypass was found. Its trust in host Git results does not cure the file symlink issue.
- **Authorization timing:** `apps/ptah-electron/src/ipc/ipc-bridge.ts:568-594` authorizes immediately before handler dispatch, and the handler re-resolves Git roots. No child-controlled scope change between these steps was found. Filesystem symlink replacement between a guard check and file use is covered by finding 3; enforcing at the backend read/write boundary is needed.
- **Main window:** the `role === 'main'` branch at `apps/ptah-electron/src/ipc/ipc-bridge.ts:568` skips `childWindows.refusal`; its unrestricted Git RPC behavior remains intact.
