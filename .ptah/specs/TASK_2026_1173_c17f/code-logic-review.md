## Acceptance items

- **(a) Same-agent re-emit updates the card — PASS.** Runtime state is keyed by `agentThreadId`, and `cardToolCallId` stays the first activity id (`codex-context.ts:668-690`). The live projector emits `tool_start` and `agent_start` only for `started` and the first sighting (`codex-chat-events.ts` `nativeStarts`). The store key is `parentToolUseId`. The reducer ignores older cycles and same-cycle replays. The tree keeps one node per `toolCallId`.
- **(b) A terminal stays terminal and a replay cannot reopen it — PASS in the store and tree, PARTIAL live.** `native-codex-status.reducer.ts` returns null for lower ordinals, for a same-cycle non-terminal after a terminal, and for a history-settled card with no ordinal. `agent-node.fn.ts` applies the same rule. Live, a terminal that happens after the parent turn is never delivered (F3).
- **(c) Same session and cycle identity after resume or reload — PARTIAL.** `cycleId = ${agentThreadId}:${ordinal}` on all three sides, and the ordinal increments only on `started` and `interacted`. The card id is the first `started` activity id on both the runtime and history sides. Gaps: F2, F5, F6. Session linkage uses `knownSessionId(event.sessionId)`, which is the session passed to `CodexChatEvents`. The resolver that supplies it is out of scope and was not reviewed.
- **(d) Terminal dedup across follow-up turns and reload; failed overrides completed only within a cycle — PARTIAL.**
  - Dedup is correct. The runtime uses `lastTerminalKey`, the projector uses `nativeTerminals`, and the reducer uses `nativeLastTerminalKey`. The activity `completed` is followed by the child terminal in the same cycle and is suppressed (the `startsWith` prefix check at `:797`). `failed` overrides `completed` within a cycle (reducer, `agent-node.fn.ts`) and not across cycles.
  - Defects: F1 (a dropped terminal) and F2 (interrupted shown as completed).
- **(e) No lifecycle from prose, no fabricated usage/cost/duration, no fake lane or background events — PASS.** Status comes only from `subAgentActivity.kind` and structured child `terminal.status` or `error`. The record carries no usage, cost or duration for native cards. No `background_agent_*` events are emitted, and the lane `context` is nulled for native cards. Exception: F2 reports interrupted as completed, which is a mapping error of structured data, not an inference from prose.
- **(f) Controls disabled with a reason for native records only — PASS with a caveat.** `onStop`, `canSendMessage`, `canBackground`, the send toggle and the stop button are gated. The reason string is visible (inline bubble and lane). `onStop` is guarded for native records, so no Claude RPC is called with a thread id. SDK and Claude records are unchanged: they have a `taskId`, or an `agentType` other than `codex`. Caveat F4: v1 Codex also matches.
- **(g) Silent failures, races, boundaries — FAIL on F1/F5.**
  - Silent drops without a log: F1, F5. Also `seenActivityKeys`/`activityItems` duplicates (benign).
  - Race, child before link: buffered, but its terminal is lost (F1). Ordering: F7.
  - Orphan drop at turn end: `dropUnlinkedOrphans` correctly filters by `!childTools.has`. A child that is linked or seeded is kept, so an already-linked child is not dropped. One residual issue: `finishActiveTurn` calls `childTools.clear()` first (`:866` follows the clear), so at the moment of the drop `childTools` is empty and every buffered orphan is dropped. That includes a native child that is in `nativeChildren` but not yet re-linked. This is bounded by the notification-path relink, but it is worth a test.
  - Boundaries: Zod accepts the native variant strictly (`frames.ts`, `native: z.undefined().optional()` on the SDK arm). The machines-ui validator requires `taskId` for SDK status events (`hasAgentStatusVariant`), so the SDK `taskId` requirement is retained.
  - The per-child orphan cap is 128 (`MAX_ORPHAN_EVENTS_PER_CHILD`).
- **(h) Permissions unchanged — PASS.** No permission, approval-bridge or `codex-execution-profile` file is in the diff. The out-of-scope files (`ptah-api-builder.service.ts`, `codex-chat-host-ports.ts`, `codex-chat-adapter.ts`) are not touched.
