# Native Codex subagent visibility: code trace

Question: how can native Codex children appear in the existing Claude subagent surfaces? Options: project native thread identity through the shared Task/agent events, or create synthetic lane records. This report supports the former. Source facts below are verified in this worktree; any attribution to the reported run is explicitly an inference. No capture of that run was available.

## Root causes

1. **RC1, verified structural gap:** A single spawn can yield several child `agent_start` events (codex-chat-events.ts:484-510; test codex-chat-events.spec.ts:29-40), while `AgentMonitorStore.onAgentStart` stores one record keyed by `toolCallId` (libs/frontend/chat-streaming/src/lib/agent-monitor.store.ts:2512-2579), and the tree picks the first match then breaks (libs/frontend/chat-execution-tree/src/lib/builders/tool-node.fn.ts:94-120). Multi-receiver children cannot each have their own card.
2. **RC2, verified lifecycle gap:** Translator drops `agentsStates` values, retaining only IDs (codex-event-translator.ts:685-707). Projection delays one spawn result until all receiver terminals (codex-chat-events.ts:390-398); monitor settles from Task `tool_result` (libs/frontend/chat-streaming/src/lib/accumulator-core.service.ts:428-469). Per-child pending/running/interrupted/errored/shutdown states cannot render independently. A missing child terminal leaves the held result until timeout/flush (libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:508-514; codex-chat-events.ts:147-156).
3. **RC3, verified background panel gap:** The background store is populated by `background_agent_started` (accumulator-core.service.ts:601-603; libs/frontend/chat-streaming/src/lib/background-agent.store.ts:313-336). Native Codex mapper emits Task start, agent start and result, but no background start (codex-chat-events.ts:349-403,483-510). Monitor/inline and background panel therefore differ even if the basic mapping works.
4. **RC4, verified reload limits; symptom inference:** Descendant discovery can partially fail while root history survives (codex-session-history.ts:223-276); projector requires receiver/parent linkage for attachment (codex-history-projector.ts:74-98). Live early child buffer drops unlinked deltas and can overflow (codex-context.ts:628-650). These can explain missing transcript or reload state. No supplied notification capture proves they caused the reported complete absence.
5. **RC5, verified control mismatch:** Claude UI sends through `AgentMonitorStore.sendMessageToAgent` and stop needs SDK `taskId` (libs/frontend/chat/src/lib/components/organisms/execution/inline-agent-bubble.component.ts:1129-1158; libs/frontend/chat-streaming/src/lib/agent-monitor.store.ts:3119-3161). Native `agent_start` has a Codex thread `agentId`, no SDK `taskId` (codex-chat-events.ts:499-508). This is a control risk, not a card visibility cause.

**Symptom-level uncertainty:** The current worktree already implements native Task/`agent_start` mapping and unit coverage (codex-chat-events.spec.ts:29-40; codex-history-projector.spec.ts:173-250). The original “nothing showed” might describe an earlier build or a failed receiver/link/session/history step. Capture the failed run's collab item start/completion, child `thread/started`, child turn events, and emitted flat events before asserting a single cause.

## Unsupported controls/metrics and limitations

- Real child usage is possible: the child budget tap attributes accepted usage by child thread/turn (libs/backend/codex-runtime/src/lib/codex-child-budget-tap.ts:42-57,89-105). Chat projection emits token usage only when real input/output values exist (libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:405-416,465-478); monitor groups child message usage by parent tool and message ID (libs/frontend/chat-streaming/src/lib/agent-monitor.store.ts:2828-2859). Missing token, cost, context, cache, duration and tool-count values must read “unknown”; never copy parent totals. History projector returns `stats: null` (codex-history-projector.ts:148).
- Claude messaging uses `ClaudeRpcService`; stop needs SDK task ID (agent-monitor.store.ts:3119-3161). For native children, disable send/stop/background with “Native Codex child control is unavailable in this UI” until backed by a native operation. Open transcript only if child history is available; otherwise show “Child transcript unavailable; descendant history was not loaded.”
- Native live session ID is a thread ID; `resolveLiveSessionId` maps a unique Ptah tab ID to it, and rejects unknown/closed/ambiguous callers (libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-adapter.ts:210-224). This Phase B owned code is a dependency, not a proposed edit.
- No Jest/build/UI run was performed in this read-only trace. Existing unit tests do not prove the observed Electron view.

## Decisions

- **Recommendation, reversible:** reuse flat events and current subagent UI, preserving true native thread IDs. Evidence: existing native Task and `agent_start` projection (codex-chat-events.ts:349-370,483-510) and shared tree consumer (tool-node.fn.ts:53-120). Synthetic lane records have no supporting native lifecycle.
- **Recommendation, reversible:** unknown metrics stay unknown; SDK-only controls stay disabled until native APIs are wired. Evidence: accepted child usage path (codex-child-budget-tap.ts:42-57) versus SDK-specific UI operations (agent-monitor.store.ts:3119-3161).
