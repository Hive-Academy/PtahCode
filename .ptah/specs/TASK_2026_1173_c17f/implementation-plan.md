## Identity and lifecycle model

- Agent identity is agentThreadId; card toolCallId is the first started activity.id; tree node id remains agent:<toolCallId> (agent-node.fn.ts:44-99). Label is the final nonempty agentPath segment, agentType is codex. Later interacted events update this original card, even when emitted in a later parent turn. The monitor keys its record by the canonical tool id (agent-monitor.store.ts:647-667,2512-2579).
- All native flat events carry sessionId equal to the parent session/thread id. This is already the live value: codex-chat-turn-stream.ts:331 constructs CodexChatEvents(session.id), and codex-chat-events.ts:181 reuses this.sessionId; history uses the parent id at codex-history-projector.ts:172. No base sessionId code change. The monitor derives parentSessionId through knownSessionId(event.sessionId) (agent-monitor.store.ts:2739-2740); exact tab matching is at 1227-1248. Tests lock both live and history paths against accidentally using child thread id.
- Per-agent runtime state: childThreadId -> {cardToolCallId, parentThreadId, agentPath, cycleOrdinal, cycleId, lastTerminalKey, lastActivityKey, turnCycleByTurnId}. History seeding constructs this state from parent thread/read in deterministic turn/item order. cycleOrdinal increments for each distinct started/interacted occurrence for that child; cycleId is childThreadId plus ordinal (no timestamp). An equal/older ordinal is idempotent. The wire activity.id is retained separately as activityId and may recur. Cross-turn history/live replay compares the persisted ordinal and terminal key. Within one parent turn live window, (parentThreadId,parentTurnId,activity.id,kind) suppresses item/started versus item/completed notifications; it is not a cross-turn dedup key.
- A child turn binds to the current cycle when its first child notification/start is observed; store turnId -> cycleId. A terminal applies only to that bound cycle. A terminal for an older bound turn cannot settle a newer interacted cycle; an unbound child turn terminal cannot settle a card. lastTerminalKey is (agentThreadId,cycleId,terminalKind,childTurnId if applicable), seeded from history. Replayed completion produces no second terminal. Structured failed child turn may override completed only for the same cycle; an older-cycle failure cannot do so. interrupted maps to paused, completed to completed, and later interacted to running. Parent turn completion, prose and collaboration.wait_agent output carry no lifecycle authority.
- Orphan child notifications before canonical started are buffered per child, capped at 128 events. On link, flush in original order with canonical parentToolUseId and parent session id. On parent turn end, drop remaining orphans with a safe diagnostic log (thread IDs and count only); never self-link them to a fake Task. A v1 pending spawn link remains authoritative for v1 events.

## Unsupported controls/metrics and limitations

Claude send/stop routes by SDK taskId (agent-monitor.store.ts:3119-3161). Native children have no SDK taskId, so both surfaces disable those controls with the shared visible reason; never pass child thread id to Claude RPC. Native usage may display only real child thread token usage (codex-child-budget-tap.ts:42-57); absent usage, cost, cache/context, tool count and duration remain unknown. History currently has stats:null (codex-history-projector.ts:148). If descendant thread/list/read fails (codex-session-history.ts:223-276), keep the parent card and show missing transcript as unavailable, with no fabricated child text.
