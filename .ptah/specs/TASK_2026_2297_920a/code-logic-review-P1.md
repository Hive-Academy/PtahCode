# P1 code logic review

**Score 4/10**  
**Verdict REVISE**

The budget monitor no longer calls the stop dispatcher, and the exercised-by-inspection pause branches return `interrupt: false`. The score reflects a supported foreground launch where neither admission hook enforces the ceiling, plus gaps in live notice delivery and terminal-state correlation.

## Findings

1. **Blocking — Foreground agents can cross the ceiling with neither admission hook enforcing it.** A foreground `SubagentStart` without a tool-call ID is explicitly held until its Agent/Task result reveals the agent ID. The monitor cannot enact a latched ask or pause without a registry agent ID. Its fallback assumes an SDK task ID can be used as an agent ID, and the live tool decision checks only the already-created gate. A foreground agent in this ordering can get no ask and keep running new tools until it returns. The previous executor spec for an unregistered subagent was removed and the replacement pause specs start with a registry binding. **Fix:** bind the live SDK agent identity to the spawning execution through a trusted correlation available before the next tool. Have both admission surfaces reconcile pending state on that binding. Restore an integration case with an unbound foreground start and a tool attempt before the Agent result. Evidence: `libs/backend/agent-sdk/src/lib/helpers/subagent-hook-handler.ts:359`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:693`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:787`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1540`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.spec.ts:1205`.

2. **Serious — The pause and overdue notices depend on the parent making progress.** Both notices go exclusively to a queue drained by the next main-thread PostToolUse. A parent blocked on the foreground Agent call cannot receive either notice while that call is blocked, and a quiet background parent may never receive them. The agent's ask has a related delivery gap: the queue drains on its next successful tool result, so a paused agent that gets only tool denials may never see the ask. **Fix:** send live pause and overdue events through a parent-facing path that works without a parent tool result, with execution-keyed deduplication. Deliver the agent instruction at its first available model-facing hook, including a complete instruction in the ceiling deny. Test observed delivery while the parent is blocked, rather than only calls to the queue mock. Evidence: `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:715`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:763`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:835`, `libs/backend/agent-sdk/src/lib/helpers/post-tool-use-hook-handler.ts:97`, `libs/backend/agent-sdk/src/lib/helpers/post-tool-use-hook-handler.ts:227`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.spec.ts:1171`.

3. **Serious — The explicit-stop spec preloads a status the task-stop route does not set.** The unchanged RPC invokes `Query.stopTask`. The dispatcher documents a stopped task notification, and the transformer handles that as the explicit stop signal. The monitor receives `task_started` but has no case for that terminal notification. If the SDK emits only the stopped notification, a warned gate and its timer can survive in the open parent session and continue to describe a stopped execution as live. If a stop hook is observed before a trusted terminal outcome is available, the monitor checks only the registry's current status and can build a normal-return handoff. The spec exercises neither ordering because it injects `interrupted` before calling the finalizer. **Fix:** consume the existing SDK task terminal outcome in the monitor, clear admissions on stopped or failed executions, and require a positive normal-return signal before publishing a completed handoff. Exercise both event orders using the existing explicit stop route and leave the RPC unchanged. Evidence: `libs/backend/rpc-handlers/src/lib/handlers/subagent-rpc.handlers.ts:465`, `libs/backend/agent-sdk/src/lib/helpers/subagent-message-dispatcher.ts:263`, `libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:628`, `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:294`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:908`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.spec.ts:1157`.

4. **Serious — An earlier finalizer can settle a later invocation.** A different task ID resets admission on the same state object but keeps the finalization flags, accounting and start time. If this arrives during the old invocation's awaited record preparation, the old finalizer can mark the shared state `stopFired` and update the reused registry key to completed. The new invocation then short-circuits admission. Its cleanup can also remove a gate keyed by the same SDK agent ID. **Fix:** bind gate and finalization ownership to an invocation generation, validate ownership after each await that precedes a state commit, and prevent old cleanup from touching the new gate. Preserve cumulative usage only where resume policy calls for it. Add a deferred-write test that injects the new task start during finalization. Evidence: `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:880`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:894`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:924`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:957`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1038`.

5. **Serious — SendMessage treats an asked agent as unavailable and a completed one as still paused.** The live state reports `stopped` from the legacy stop flags, which remain clear after cooperative completion. That live match shadows the finalized snapshot until session release. A previously paused agent therefore gets the “execution remains live” refusal after returning. The finalizer's in-flight flag produces the opposite error during the write, and a warned running agent can also get a resume refusal while still in the ask-only phase. Paused refusal copy guesses between context and weighted use, which misattributes raw, duration and telemetry pauses. **Fix:** expose the actual invocation lifecycle and its latched reason, distinguish live asked, live paused, finalizing and settled, and use the settled record pointer immediately after normal return. Test the same target through all four states. Evidence: `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:959`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1104`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1115`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-resume-advice.ts:12`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-resume-advice.ts:40`.

6. **Serious — Repeated SDK blocks can falsely trigger the latched ceiling.** Usage deduplication includes a task ID that can change from the spawning tool ID to the SDK task ID during the same assistant request. When the request is repeated across that join, the first turn key differs from the second and both are charged. Missing-usage deduplication tracks only the last missing ID, so a sequence of missing blocks A, B, A reaches the three-turn ceiling with two distinct requests. A later valid block cannot undo a pause. The late-task-ID spec asserts a second ask for the same invocation rather than checking stable accounting. **Fix:** deduplicate on an invocation-stable request key across deferred identity binding, track unique unresolved requests, and reconcile later usage samples before counting a request as missing. Test both orderings and assert one ask. Evidence: `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:606`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:665`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1535`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-request-accounting.ts:20`, `libs/shared/src/lib/utils/agent-budget-policy.ts:183`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.spec.ts:561`.

7. **Serious — A final scrub or publication failure loses the handoff entirely.** Record-write failures have an inline fallback. The later scrub and ownership checks instead return before storing or delivering a result, while the enclosing hook still permits the agent to exit and removes its gate. The parent sees a completed tool result with no handoff pointer or explanation. **Fix:** continue to withhold unsafe files, but deliver the record-unavailable notice with a sanitized inline report or existing transcript pointer. Prove delivery after a failed final scrub and after a failed publication check. Evidence: `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:947`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1552`, `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.spec.ts:836`.

8. **Serious — The session disposition gate exempts tools that can stop live tasks.** The paused-session decision exempts the permission prompt's `SAFE_TOOLS` list, which includes `TaskStop`, `KillShell`, `TaskCreate` and `TaskUpdate`. Once a host supplies a paused disposition, these calls can run even on the same path that blocks new work. This is a defect in the P1 gate contract. The default runtime feed supplies no pause state yet. **Fix:** give admission its own explicit read-only and coordination allowlist. Assert that both hooks deny task-stopping tools in a paused session with the Ptah reason. Preserve explicit user stop RPCs. Evidence: `libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:216`, `libs/backend/agent-sdk/src/lib/permission/permission-tool-classifier.ts:13`, `libs/backend/agent-sdk/src/lib/helpers/sdk-query-options-builder.ts:1482`, `libs/backend/cli-agent-runtime/src/lib/di/register.ts:164`.

9. **Minor — Some host-origin denials still omit Ptah attribution or lose the actual refusal reason.** Immediate unattended policy denials return unlabeled copy, including the zero-window path. Failed prompt delivery uses the same teardown origin as an actual host cancellation and changes the test to expect generic cancellation instead of a delivery explanation. These branches correctly avoid interruption. **Fix:** use the Ptah host formatter for immediate policy denials and keep a distinct delivery-failed reason in model-facing text. Assert both attribution and cause in the unattended spec. Evidence: `libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:459`, `libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:1049`, `libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:1107`, `libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:1186`, `libs/backend/agent-sdk/src/lib/sdk-permission-handler.unattended.spec.ts:386`.

10. **Minor — Retired stop plumbing still appears wired for live use.** DI constructs and injects the budget-stop callback registry, but the monitor has no producer and lane outcomes removed its subscriber. The stop hook also binds a method that always returns undefined and which no budget hook calls. **Fix:** retire these live registrations and bindings where callers have migrated, while retaining historical record decoding. ## Five logic questions

1. **How does it fail silently?** A foreground agent can run past the ceiling with both hooks returning normal admission. A failed final scrub can leave a normal tool result with no handoff. See findings 1 and 7.
2. **What user action produces unexpected behaviour?** Stopping an already warned task can leave a stale gate. Sending new work to an agent that handed off can produce a live-pause refusal. See findings 3 and 5.
3. **What input produces a wrong answer?** Repeated usage blocks spanning a late task ID, or missing-usage IDs in A, B, A order, can produce a false ceiling. See finding 6.
4. **What happens when a dependency fails?** A failed record write has bounded retry and inline fallback. Failure in the later scrub or publication step bypasses that fallback. A failed permission delivery denies without interruption but loses the concrete cause. See findings 7 and 9.
5. **What necessary case is missing?** Live notice delivery while the parent is blocked, and ownership checks when a later invocation starts during finalization. See findings 2 and 4.

## Decisions and verification

- Treated the existing SDK task-terminal signal as in scope for subagent admission cleanup. The alternatives were relying on the stop hook alone or waiting for P2's session-wide cause propagation. The existing task notification distinguishes stopped and failed tasks, and P1 batch 21 requires explicit stop and normal return to be distinguishable. This is a reversible implementation judgment.
- Reviewed the uncommitted diff, the listed untracked sources and specs, and the relevant caller paths. `git diff --check` passed. Confirmed no source diff in the explicit stop RPC or the handoff-ack tool. No automatic stop call remains in the monitor. Existing session watchdog behavior and batch 22 cause propagation are P2 scope.
- Verification was static. I did not run Jest or project diagnostics while the existing test run was active. The SDK event-order scenarios are source traces and were not exercised against a live SDK.
