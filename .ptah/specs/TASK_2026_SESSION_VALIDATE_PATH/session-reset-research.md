# Session reset after subagent budget stop

## Decision served

Choose between fixing transcript directory resolution, changing session identity after the handoff, or treating transcript staging as the cause. The evidence supports fixing directory resolution first. This report makes no product design decision.

## Verified findings

1. **The resolver cannot exactly match this Claude project directory.** `session:validate` reads metadata and calls `resolveTranscriptDirectory(metadata?.workingDirectory, workspacePath, sessionId)`, then calls `findSessionFile` under a per-session lock ([session-rpc.handlers.ts:1354-1376](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts)). `resolveTranscriptDirectory` returns `workspacePath` when metadata has no working directory or the two paths match ([session-rpc.handlers.ts:2196-2212](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts)). `resolveSessionsDir` replaces only `:`, slash and backslash with `-`; its case and `[-_]` fallback also leave dots intact, then it guesses the **first** directory containing the workspace basename ([session-rpc.handlers.ts:2033-2072](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts)). For this workspace, its computed name is `D--projects-ptah-extension-.claude-worktrees-subagent-budget-stop-path-.ptah-live-test-ws`; the actual Claude directory is `D--projects-ptah-extension--claude-worktrees-subagent-budget-stop-path--ptah-live-test-ws`. Both dots are folded to hyphens by Claude's non-alphanumeric encoding. This is the specific mismatch; no underscore is needed to trigger it.

2. **The fallback chooses the wrong directory on this machine.** A read-only Node reproduction of lines 2048-2069 against the current `~/.claude/projects` listing returned `C--Users-abdal-AppData-Local-Temp-ptah-live-test-ws-claude` as the first basename match; that directory does not contain `5be04e99-5956-4fdd-beb4-e1f8821a66f7.jsonl`. The correctly encoded directory does contain it. `findSessionFile` checks only the one selected directory and returns null after `fs.access` fails ([session-rpc.handlers.ts:1991-2015](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts)). Thus the observed false negative follows from code and current filesystem state. A transcript row in that actual file has `cwd` equal to the supplied workspace path and `sessionId` equal to the validated UUID; this corroborates the path and ID, though it does **not** independently reveal Ptah's persisted `metadata.workingDirectory` value.

3. **The live sequence matches the false negative.** Dev log `C:\Users\abdal\AppData\Roaming\Ptah Dev\logs\Ptah Electron-2026-11-08.log:14236-14243` records validation of that UUID and workspace, `session file NOT found`, renderer warning, then `chat:start`. The renderer's `runContinueConversation` validates the session, detaches the tab on `exists:false`, and calls `startNewConversation` ([message-sender.service.ts:850-895](../../../libs/frontend/chat/src/lib/services/message-sender.service.ts)). The earlier warning at log line 5115 is the same symptom in another worktree.

4. **The validated ID is the canonical SDK ID, not the tab ID.** Dev log lines 13810-13811 bind tab `351d3063-6cef-4eb0-a1c3-291a4b0976dd` to real session `5be04e99-5956-4fdd-beb4-e1f8821a66f7`; lines 14047-14055 show the budget callback logged with the tab ID, `pushParentMessage` with the real ID, metadata saved for the real ID, and the same binding announced again. `pushParentMessage` finds the existing query and sends a user message with `session_id: sessionId`; it does not create or replace a session ([subagent-message-dispatcher.ts:190-228](../../../libs/backend/agent-sdk/src/lib/helpers/subagent-message-dispatcher.ts)). The renderer reads `targetTab.claudeSessionId` for the next send ([message-sender.service.ts:535-551](../../../libs/frontend/chat/src/lib/services/message-sender.service.ts)); the validation log confirms it supplied the real ID. The executor's SDK setup uses `resumeSessionId` for a resumed query and resolves UI routing from `rec.realSessionId` ([session-query-executor.service.ts:1822-1868](../../../libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts)). There is no observed ID switch at handoff.

5. **Staging is not the cause of this occurrence.** `recoverStaged` operates in the selected directory and is enabled when metadata still exists ([session-rpc.handlers.ts:1369-1376](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts), [session-rpc.handlers.ts:1996-2009](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts)). Its function restores staged files and logs failures ([session-rpc.handlers.ts:1272-1293](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts)). The observed target file is already a normal `.jsonl` in another directory. Recovery cannot make a wrong directory lookup find it. We did not observe the metadata value at validation time, so a different persisted working directory remains a possible additional fault, not needed to explain the reproduced false negative.

## Consequences and limits

**Verified:** The false `exists:false` causes the renderer to detach the old session and start a new chat. Dev log lines 14256-14257 show the new registration displacing and aborting the old live query. This explains loss of parent context on that follow-up and why the old continuation would no longer arrive in the newly attached chat.

**Separate earlier behavior:** The wrong parent account and missing handoff rendering occurred before validation at 00:45:24. The budget stop was logged at 00:44:33 (line 14044); the parent-turn callback and push followed at lines 14047-14048. The monitor reported that the handoff had not been read within its timeout (line 14066). The SDK did stream further text/tool deltas to the webview at lines 14070-14071, while the transformer skipped a replayed user echo at lines 14063-14064 under its general replay rule ([sdk-message-transformer.ts:394-410](../../../libs/backend/agent-sdk/src/lib/sdk-message-transformer.ts)). Therefore the directory defect cannot cause the earlier parent wording or prove why a particular continuation was absent in the UI. It **can** terminate subsequent output when the follow-up triggers the new chat. The parent wording and replay/render classification need their own trace if still failing after the directory fix.

## Smallest fix and test

In `resolveSessionsDir`, derive the primary Claude project name with the Claude-compatible replacement of every non-ASCII-alphanumeric character by `-` (`/[^a-zA-Z0-9]/g`), while retaining a narrowly scoped fallback for older directory names if required. A basename guess must not stop after the first candidate when probing a known session ID: either remove that guess for validation or scan candidate directories for the exact `<sessionId>.jsonl` before reporting absence. Preserve the current metadata guard and lock around staged recovery.

Add a focused case to [session-rpc.handlers.spec.ts](../../../libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.spec.ts) with a Windows workspace containing `.claude-worktrees` and `.ptah`, a decoy `live-test-ws` directory sorted before the real one, and the UUID transcript only in the real Claude-encoded directory. Assert `session:validate` returns `exists:true` and that missing IDs still return false. A second case with a different metadata working directory would test that branch. No source edits, builds, application launches, process stops, or workspace-wide checks were performed for this investigation.

## Main branch and recent history

`git show main:libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts` contains the same `workspacePath.replace(/[:\\/]/g, '-')`, basename fallback, and `findSessionFile(... allowPartialMatch:true)` logic. `git diff main...HEAD` for the resolver and renderer sender is empty. `git log -p --since='14 days ago' -- session-rpc.handlers.ts` shows recent transcript staging and lock changes (notably `022ea4b9f`, `f7a34f037`, `6ac5baeea`) but no correction to the escaping or single-candidate fallback. The issue is therefore present on `main` as inspected here.

## Decisions

No implementation decision was made. Research prioritizes the resolver fix because the path mismatch and false-negative lookup were reproduced; changing session identity is unsupported by the observed IDs. This prioritization is reversible after a targeted validation test and another live trace.
