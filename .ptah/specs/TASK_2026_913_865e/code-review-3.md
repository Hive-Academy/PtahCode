# Independent code review 2

**Verdict: REVISE — 5/10.** Reviewed commits `2241f32d2`, `83c2ef714`, `33178cc35`, `9f39c41cf`, and `2aa969658` with their per-commit stats and path diffs. Read-only review; no tests or builds run.

## Findings

1. **Major — Approval cards offer actions for requests that cannot be answered.** `libs/frontend/machines-ui/src/lib/components/machines-view/machine-approvals.component.ts:41-48` creates every `ptah-remote-approval-block` without its `[mode]` or `[unavailableReason]` inputs. The block defaults to `mode = 'answerable'` and enables Allow once / Deny when `unavailableReason` is null (`remote-approval-block.component.ts:198,241-247`). The new `pendingApprovalRequestsByMachine` map (`machines-store.ts:172-180`) includes pending requests from cached/snapshot sessions and remains populated when a machine disconnects; `respondPermission` then refuses them as `watch-only` or `not-connected` (`machines-store.ts:599-609`). Thus the overview presents actionable approvals that the session pane correctly marks read-only, and clicks fail. **Smallest fix:** carry the session's mode/availability in `MachinePendingApproval` and pass the corresponding `[mode]` and `[unavailableReason]` to each block (using the same rules as `remote-session-pane.component.ts:190-194`); do not show cached requests as answerable.

2. **Major — The Reviews coverage tile counts scope notes as lenses.** `libs/frontend/review-runs-ui/src/lib/components/review-run-detail.component.ts:34-36,49-54,94-95` labels `run().coverage.length` as a number of lenses, renders each coverage string as a lens card, and compares it with the number of lens stage records. The persisted `coverage` field is the context/check coverage array (`review-query.repository.ts:44,69`): `context-stage.runner.ts:119-120` populates it with values such as `diff-complete`, `dependencies:...`, and check statuses. The existing detail fixture even uses `coverage: ['High-risk paths sampled']` (`review-run-detail.component.spec.ts:11`). A normal run therefore shows scope notes as lens names and can report a misleading `N of N lenses`. **Smallest fix:** label and render this field as coverage notes; derive lens counts/cards from `stages` where `name === 'lenses'`, or omit numerical lens coverage until the contract supplies a true selected/covered lens set.

3. **Minor — Session state and metadata are hidden from the row's accessible name.** `libs/frontend/machines-ui/src/lib/components/remote-session-list/remote-session-list.component.ts:221-255` makes the entire row a button, but `[attr.aria-label]="openLabel(row.session)"` at line 225 overrides the button's visible title, provider, age, and state. `openLabel()` (`:357-361`) names only the title and optional driver. Keyboard and screen reader users focused on the row cannot hear whether the session is Running, Interrupted, Idle, or Unknown, despite that state being visible. **Smallest fix:** include the state label and useful metadata in `openLabel()`, or remove the overriding `aria-label` and add visually hidden “Open session” text inside the button.
