## C21 opinion
Acceptable as a follow-up, not a defect that must change before merge. The list encodes a reviewed property of each provider's list — it hides models for reasons other than availability — and no registry field expresses that property today, so a flag would be new vocabulary on the entry rather than a mechanical move. The literal's failure mode is also the safe direction: a future provider added without updating the list gets the general catalog-driven rule, which is the default for every other provider, not a wrong special case. Recommended follow-up: a flag on the provider entry (for example `hidesUnavailableModels`) so the entry stays the single source, to be added the next time the list changes or when B5's rule moves to the other tier-resolution sites (RB-2).
