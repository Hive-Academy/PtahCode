## Findings

1. **Blocking** — `libs/backend/auth-providers/src/lib/quota/readers/claude-oauth-plan-usage.reader.ts:153`. The named path compares credential IDs to metadata at line 125 and response IDs to metadata at line 153. It never compares the response to the credential. If metadata proves the owner by email and organization name but omits an account or organization UUID, unequal IDs in the credential and response pass both checks. If neither the credential nor the response carries an ID, the named path also accepts the windows without any proof that the token belongs to the metadata owner. A mismatched token and metadata pair can therefore attribute default-account usage to the named account. For named targets, cross-check every supplied ID across all three sources, reject contradictions between aliases, and require an authenticated binding to the metadata owner before publishing windows. Use a provider-authenticated identity check where the OAuth payloads lack a binding, or return `account-unverified`. Keep ambient handling intact. ## Five logic questions

1. **Silent failure.** Expired credentials and OAuth errors look like the expected absence of a session. Profile-store failure can look like a complete empty roster.
2. **Unexpected user action.** Signing into the same account in two config directories and refreshing can cause one source's cached result or cooldown to determine the other's answer.
3. **Wrong answer from input data.** An incomplete metadata UUID set permits credential and response IDs to disagree without suppressing attributed usage.
4. **Dependency failure.** The reader classifies invalid payloads and HTTP failures, and aborts timed-out requests. The service drops those classifications for named usage, and the roster suppresses a failing profile source without flagging an incomplete result.
5. **Unspecified edge.** An older stored email-only identity needs a verified upgrade path when current Claude metadata adds an organization. A stored signed-in status also does not guarantee a usable access token. The reader currently depends on the CLI to refresh expired credentials.

## Decisions

- Treated read isolation as applying to cache and cooldown as well as flight selection. The discovery notes intentionally share settled readings by owner, but R2 requires reading the named source and R3 preserves ambient behavior. Source-specific read state is reversible and can coexist with a shared verified-owner ledger.
