# Code logic review

## Verdict

**FAIL (5/10).** Automatic recovery can compete with a local resume or restart work after the user closes the tab. The watchdog can discard an active SDK retry window, and a failed budget stop can give a later user stop the wrong author.

## Findings

1. **Major (C) — Recovery can race a local user resume or send into the user's session.** The driver coordinator reuses the process owner and tracks multiple drive attempts, so its lock allows two local activations. Both can pass liveness before asynchronous config resolution. If the user's SDK query is registered first, the adapter can return a second transformer over that query, which the resume helper hands to another broadcaster. There is also a simpler race when the second liveness check in `autoResumeIfInactive` can return `justResumed: false`, which `ensureSessionActiveForRewind` coerces to success. The recovery send uses an unrestricted peer enqueue, so a turn start or record replacement during message construction can still lead to an extra turn or a write into a stale queue. **Fix** by sharing a per-session activation gate with normal continue, propagating the actual resume outcome, and admitting the prompt only while the exact recovered record and stream are still current and idle. Exercise both the activation and enqueue races with barriers. Evidence in `libs/backend/rpc-handlers/src/lib/chat/session/session-driver-lock-coordinator.ts:146`, `:187`, `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:2938`, `:2993`, `:3080`, `:3288`, `libs/backend/agent-sdk/src/lib/sdk-agent-adapter.ts:1428`, `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-stream-pump.service.ts:488`.

2. **Major (C) — Closing the tab during the delay can restart the closed session.** The recovery timer retains only the session ID. Closing the orphaned tab dispatches `chat:abort` with source `tab-close`. Once watchdog teardown has removed the SDK record, that abort can succeed without ending a record. Recovery then finds the acknowledgement and resumes the tab's session. The existing stop generation is advanced by the abort, but the recovery path never checks it. **Fix** by capturing a cancellation or ownership generation when the watchdog end schedules recovery, invalidating it on a later explicit abort or close, and checking it at activation and prompt admission. Test watchdog end, teardown, tab close, then timer fire. Evidence in `libs/backend/cli-agent-runtime/src/lib/session-children/handoff-watchdog-recovery.ts:62`, `:103`, `libs/frontend/chat/src/lib/services/closed-tab-session-ender.service.ts:49`, `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:2742`, `:2751`, `:2967`, `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-control.service.ts:307`.

3. **Major (A) — A permission hold or unrelated background completion can discard the SDK retry window.** The extended window exists only as a timer argument. A hold clears an armed timer and an `api_retry` during a hold arms nothing. Release kicks with 180 s. A tracked root-owned keepalive task finishing also kicks the normal window even if the root API retry is still waiting. Either path can truncate the 629 s window exercised by the new spec. **Fix** by retaining the bounded retry deadline across holds and incidental activity, keeping the compaction dwell clamp, and clearing the retry deadline on root API progress, turn end, or teardown. Add fake-clock cases for a hold on each side of `api_retry` and a keepalive task completion during the retry. Evidence in `libs/backend/agent-sdk/src/lib/helpers/no-activity-watchdog.ts:77`, `:82`, `:88`, `:220`, `:249`, `:385`, `libs/backend/agent-sdk/src/lib/helpers/sdk-query-options-builder.ts:1388`.

4. **Major (C) — An acknowledgement miss can silently skip a known handoff successor.** A successful start stays committed after a failed ack write, with successor identity available from in-process state. A tab-only persisted ack also misses an SDK-ID end when the SDK alias update fails. Recovery consults only the durable lookup and returns silently on a miss. **Fix** by resolving committed in-process identity and the SDK alias when the store misses or fails. Report an unavailable resumable ID for a known successor and leave unknown sessions ineligible. Cover both a failed ack write and a tab-only ack with a real-SDK-ID callback. Evidence in `libs/backend/cli-agent-runtime/src/lib/session-children/session-handoff.service.ts:227`, `:826`, `:845`, `:1252`, `libs/backend/cli-agent-runtime/src/lib/session-children/session-handoff-ack.store.ts:256`, `libs/backend/cli-agent-runtime/src/lib/session-children/handoff-watchdog-recovery.ts:82`, `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-control.service.ts:361`.

5. **Major (C) — The recovery prompt reloads as an ordinary user message.** Live delivery supplies the intended peer metadata. The CLI transcript lacks the peer origin, and replay recognizes peer turns through a lane envelope. Recovery submits plain text, so replay emits the user row without the “Ptah recovery” label. **Fix** by persisting trusted recovery origin or introducing a replay-recognized recovery envelope. Test live and replay attribution, including a human message containing the same text. Evidence in `libs/backend/cli-agent-runtime/src/lib/session-children/handoff-watchdog-recovery.ts:31`, `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:2993`, `libs/backend/agent-sdk/src/lib/helpers/history/session-replay.service.ts:346`.

6. **Major (E) — A failed budget stop can mislabel a later user stop.** The monitor records a notice before calling the dispatcher and retains it when the call rejects. If the task remains active and the user stops it before the next budget attempt, the following `killed` event carries budget authorship. The completed-event path can also stamp unknown or missing statuses with that author. **Fix** by tracking stop ownership per session and task, invalidating failed attempts, and assigning an author to confirmed `stopped` or `killed` events. Account for terminal events arriving before the stop promise settles and test that order as well as failure followed by a user stop. Evidence in `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:1547`, `:1554`, `:1582`, `libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:654`, `:707`.

7. **Minor (A) — Safe-env launches lose an explicit process timeout.** For a nonblank process-only value, `firstByteTimeoutEnv` returns an empty map, while the sanitized output omits the key from its allowlist. The child falls back to its SDK default. The full unnamed main-chat env spreads the process environment and preserves the same setting there. **Fix** by including the resolved key in safe env, with provider value, process value, and 150 s default in that precedence order. Test the output of `buildSafeEnv` for a process-only value. Evidence in `libs/backend/agent-sdk/src/lib/helpers/build-safe-env.ts:46`, `:85`, `:102`, `libs/backend/cli-agent-runtime/src/lib/claude/claude-sdk-lane-options.ts:41`.

8. **Minor (D) — Failure cleanup can erase a newer stop cause on the same record.** A pending send-now interrupt can time out or reject after a cause-bearing interrupt has recorded a newer cause on the same query. The guard checks the record and teardown status, and `clearStopCause` removes the entry currently owning the identifier. The replacement-record test covers a different interleaving. **Fix** by using an entry token and clearing only the pending and current entries owned by the failed call. Test overlapping interrupts against the same record. Evidence in `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-control.service.ts:219`, `:232`, `:247`, `libs/backend/agent-sdk/src/lib/helpers/sdk-adapter-events.service.ts:131`, `:157`.

9. **Minor (E) — Normalized kills change workflow counts.** The monitor stores `stopped` directly, while the workflow rollup treats `killed` as failed and has no stopped bucket. A workflow consisting of one killed agent can now show mixed with zero completed and zero failed. **Fix** by preserving the existing aggregation for normalized SDK kills or adding a stopped count with an explicit aggregate status. Test the workflow monitor with an SDK kill. Evidence in `libs/frontend/chat-streaming/src/lib/agent-monitor.store.ts:2835`, `libs/frontend/chat/src/lib/components/organisms/agent-monitor-panel.grouping.ts:52`.

10. **Minor (E) — A reason on the second terminal event can be dropped.** With `skip_transcript: true`, the first `agent_completed` carries the budget author and an empty summary. The following `background_agent_stopped` carries the notice, but the store only enriches an entry missing its author. A known background entry can therefore retain the budget chip with no reason despite receiving one. **Fix** by letting a same-author update fill a missing reason and preserving the first terminal timestamp. Test the two events in emitted order with transcript suppression. Evidence in `libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:674`, `:852`, `:884`, `libs/frontend/chat-streaming/src/lib/background-agent.store.ts:448`, `:478`.

11. **Minor (E) — A budget label is lost when replay reconstructs the terminal event.** Historical `killed` normalizes to stopped but replay uses the raw SDK summary and has no persisted author. Reopening a transcript can therefore show the SDK's “stopped by user” text or a generic stopped chip. **Fix** by persisting verified stop metadata and reading it during replay, leaving historical entries without metadata unattributed. Evidence in `libs/backend/agent-sdk/src/lib/helpers/history/session-replay.service.ts:104`, `:275`, `:300`.

## Checked and fine

- **A.** The 150 s default gives the unnamed main-chat SDK headroom under the 180 s watchdog. Nonblank process and provider settings win on that path, with provider values last. The per-event retry duration is bounded and clamps to remaining controlled compaction dwell. An overdue tool or compaction re-arms after the accounted window has elapsed. A return to the normal window after actual root progress is appropriate. An explicit timeout at or above 180 s can still lose before the SDK announces a retry.
- **B.** The filter requires the exact synthetic model and nonempty, text-only placeholder content. An ordinary assistant reply with the same words or an entry with a tool block survives. Replay skips the marker before allocating a bubble and retains the open row and tool results through to the next visible user message or EOF. Message count preserves the same visible-user reset.
- **C.** Electron composes the handoff and chat host. With a complete acknowledgement, either callback ID finds the successor and activation uses its SDK ID. Both callback and canonical tab IDs are checked for child ownership. Concurrent duplicate callbacks converge on a single per-tab in-process claim. A different driver owner can block activation, the timer is unref'd, and async recovery rejections are logged. A fully live stream visible before recovery starts is skipped.
- **D.** The normal path records `send-now` before calling the SDK and records both aliases when available. The interrupted result and failure-hook paths read their copies, and normal turn transitions retire the old cause. The type, hook parser, Zod schema, execution schema, and bubble label handle the new value. The remaining closed lists containing `internal-abort` without `send-now` describe session ends.
- **E.** An ordinary user stop with no matching notice keeps the SDK summary and generic stopped chip. The store handles completion-hook and stop-event ordering. Raw watchdog and shell terminal handling still read the original SDK status.
