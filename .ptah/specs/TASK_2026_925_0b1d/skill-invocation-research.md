## 2. Delivery

Skills travel from bundled plugins to the Claude Agent SDK through a 7-stage pipeline with **three gates** that prevent non-core skills from reaching new or unconfigured workspaces:

1. **Bundled Plugin Staging (`ContentDownloadService` & `PluginLoaderService`)**:
   - `DEFAULT_PLUGIN_REGISTRY` in `libs/backend/agent-sdk/src/lib/helpers/plugin-loader.service.ts:314-403` defines 5 bundled plugins, but **only `ptah-core` has `isDefault: true`** (`line 323`).
   - `ptah-nx-saas` (`line 346`), `ptah-dotnet` (`line 370`), `ptah-angular` (`line 390`), and `ptah-react` (`line 400`) all set **`isDefault: false`**.
   - On Electron startup (`apps/ptah-electron/src/activation/plugin-activation.ts:183-189, 255-261`), a workspace without saved plugin state receives `DEFAULT_ENABLED_PLUGIN_IDS` (`['ptah-core']`). `stageBundledPluginsToDisk` (`plugin-activation.ts:352-415`) stages only enabled plugins to `~/.ptah/plugins/`.
2. **User-Layer Mirror (`UserLayerMirrorService`)**:
   - `UserLayerMirrorService.reconcileSkills` (`libs/backend/agent-generation/src/lib/services/user-layer/user-layer-mirror.service.ts:185-260`) copies `SKILL.md` directories from enabled overlay plugins into `~/.ptah/user/skills/<slug>` and writes `.ptah-origin.json` with `pluginId`.
3. **Gate 1 — `PluginOriginGate`**:
   - `PluginOriginGate.isAllowed` (`libs/backend/harness-sync/src/lib/manifest/plugin-origin-gate.ts:124-146`) checks `.ptah-origin.json` during manifest construction (`harness-manifest.builder.ts:520,574`). Even if `~/.ptah/user/skills/` contains skills from `ptah-nx-saas` or `ptah-angular` from another workspace, `PluginOriginGate` excludes them unless that plugin is enabled in the current workspace's `overlayPluginPaths`.
4. **Gate 2 — `SkillSyncGate` (blocks ALL skills in a new workspace)**:
   - `SkillSyncGate.resolve` (`libs/backend/harness-sync/src/lib/state/skill-sync-gate.ts:106-123`) reads `{ws}/.ptah/harness/state.json`. When `state.skillSyncMode` is absent (every new or unconfigured workspace), it derives `{ mode: 'selected', slugs: normalizeSlugs(this.ownedSkillSlugs(workspaceRoot)), derived: true }` (`lines 116-121`).
   - In a fresh workspace where `.claude/skills` has no Ptah-owned entries, `ownedSkillSlugs` returns `[]`.
   - `HarnessManifestBuilder.buildSkills` (`libs/backend/harness-sync/src/lib/manifest/harness-manifest.builder.ts:506-531, 561-564`) filters all candidate skills against `allowed = new Set([])`, producing **0 skill entries**.
5. **Target Materialization (`HarnessReconcilerService` & `ClaudeTarget`)**:
   - `HarnessReconcilerService` (`libs/backend/harness-sync/src/lib/reconciler/harness-reconciler.service.ts:212-345`) and `ClaudeTarget` (`libs/backend/harness-sync/src/lib/targets/claude-target.ts:121-210`) write only manifest-approved skills to `{ws}/.claude/skills`, `{ws}/.agents/skills`, `{ws}/.github/skills`, and `{ws}/.cursor/skills`.
6. **Gate 3 — `SdkQueryOptionsBuilder` & `CapabilityResolverService`**:
   - Neither `SdkQueryOptionsBuilder.build` (`libs/backend/agent-sdk/src/lib/helpers/sdk-query-options-builder.ts:1505-1648`) nor `PtahCliSpawnOptions.assembleSpawnOptions` (`libs/backend/cli-agent-runtime/src/lib/ptah-cli/helpers/ptah-cli-spawn-options.service.ts:8-16`) passes `plugins: [{ type: 'local', path }]` to the Claude Agent SDK (`Options`). Claude Code discovers skills strictly from disk via `settingSources`.
   - `SdkQueryOptionsBuilder.build` sets `settingSources: ['user', 'project', 'local']` for direct Anthropic sessions, or `['project', 'local']` when routed through a custom base URL / local proxy (`sdk-query-options-builder.ts:1443-1455, 1618`). Because Ptah does not sync skills to `~/.claude/skills` (only `{ws}/.claude/skills`), **Claude sees ONLY `{ws}/.claude/skills/<slug>/SKILL.md`**.
   - `CapabilityResolverService.resolve` (`libs/backend/cli-agent-runtime/src/lib/capabilities/capability-resolver.service.ts:170-191, 446-457`) computes `deniedSkills` from disabled plugins and `disabledSkillIds`, which `capabilityFlagsFor` (`libs/backend/agent-sdk/src/lib/harness/harness-policy-sync.ts:62-97`) and `buildFlagSettings` (`sdk-query-options-builder.ts:551-579`) inject into `--settings` as `permissions.deny: ["Skill(<name>)", ...]`. If policy resolution fails (`status: 'unverified'`), `capabilityIsolationOptions` (`harness-policy-sync.ts:116-124`) sets `{ strictMcpConfig: true, skills: [] }`, disabling all skills.

**Result for a new empty workspace**: Until the user explicitly sets skill selection (`harness:set-skill-selection`) or applies a harness config (`harness:apply`), `SkillSyncGate` resolves to `selected: []` and **zero skills exist in `{ws}/.claude/skills/`**. Even if `SkillSyncGate` is set to `all`, only `ptah-core` skills (`orchestration`, `agent-lanes`, `tribunal`, `ddd-architecture`, `humanize-library`, `ptah-surface-authoring`, `session-handoff`, `skill-creator`, `technical-content-writer`, `ui-ux-designer`) sync unless `ptah-nx-saas` / `ptah-angular` / `ptah-react` / `ptah-dotnet` are also enabled.

## 4. Subagents and CLI Lanes

### A. In-Process `Task` Subagents (`.claude/agents/*.md`)
- **Tool capability**: Every generated agent in `.claude/agents/*.md` includes `Skill` in its frontmatter `tools:` list (e.g., `backend-developer.md:4`, `frontend-developer.md:4`, `software-architect.md:4`, `technical-content-writer.md:4`). `ROLE_TOOL_POLICIES` in `libs/backend/agent-generation/src/lib/services/subagent-tool-allowlist.ts:39-105` grants `Skill` to all 14 roles.
- **Why subagents still never load skills**:
  1. **Anti-invocation rule in `_shared/tooling-precedence.md`**: `libs/backend/agent-generation/templates/agents/_shared/tooling-precedence.md:18-24` (rendered at lines 26-32 of all 14 `.claude/agents/*.md`) instructs:
     > *"When the task assigns none, this role selects from the host's catalogue only skills whose descriptions match the task and the repository's own evidence, and that this role is allowed to use. That selection is only the unassigned entry. **This role does not load a skill because the catalogue lists it, because this product's repository uses that stack, or because the role recognises the name.**"*
  2. **Sibling-code precedence over textbook skills**: `backend-developer.md:93-146`, `frontend-developer.md:97-155`, and `software-architect.md:122-153` instruct subagents to read 2–3 sibling files in the repo and follow established local patterns rather than loading a skill.
  3. **`orchestration` never assigns skills in `Task()` prompts**: `orchestration/references/agent-catalog.md:58-92` provides the `Task()` prompt templates for all 14 agents; none include a `Skills:` field or name any domain skill.
  4. **Agent generation drops `invocableSkills`**: Although `OrchestratorService` (`libs/backend/agent-generation/src/lib/services/orchestrator.service.ts:288,708`) passes `invocablePluginSkills` (`libs/backend/agent-generation/src/lib/services/invocable-plugin-skills.ts:20-44`) into `ContentGenerationService.fillDynamicSections` (`libs/backend/agent-generation/src/lib/services/content-generation.service.ts:632-648`), `buildAllSectionsPrompt` (`content-generation.service.ts:381-416`) demands that every bullet cite a concrete repository file path in backticks (`line 391`) and contains no section or instruction to emit skill names.
  5. **Name collision on `technical-content-writer`**: `ui-ux-designer.template.md:47,51` explicitly instructs the `ui-ux-designer` subagent to read the `ui-ux-designer` skill's `SKILL.md` and `references/`. ## 5. Setup Hub / New Project Flow

Tracing "Start a new project" from the Setup Hub UI to the first chat turn reveals a **critical disconnect between prompt generation and skill syncing**:

1. **UI Entry (`libs/frontend/onboarding`)**:
   - In `OnboardingHomeComponent` (`libs/frontend/onboarding/src/lib/home/onboarding-home.component.ts:346-352`), clicking "Start a new project" calls `flow.openNewProjectIntake()`, rendering `NewProjectIntakePageComponent` (`libs/frontend/onboarding/src/lib/proposal/new-project-intake.page.ts:386-412`).
   - Submitting the intake form calls `ProposalFlowStore.startNewProject(intake)` (`libs/frontend/onboarding/src/lib/proposal/proposal-flow.store.ts:242-304`), which invokes RPC `harness:start-new-project` (`line 254`) and then starts a chat session with `result.seedPrompt` (`lines 266-288`).
   - *(Secondary entry)*: Clicking `/initialize-workspace` (`onboarding-home.component.ts:358-365`) calls `harness:workflow-prompt` (`libs/backend/rpc-handlers/src/lib/harness/ai/harness-workflow-prompt.service.ts:37-59`), which sends `/initialize-workspace` (`.claude/commands/initialize-workspace.md:1-148`) to design `.claude/agents/*.md` via `ptah_harness_propose_config` — it does not invoke `saas-workspace-initializer` or `nx-workspace-architect`.
2. **Backend Handler (`HarnessRpcHandlers.registerStartNewProject`, `libs/backend/rpc-handlers/src/lib/handlers/harness-rpc.handlers.ts:844-938`)**:
   - Resolves the stack profile via `resolveStackProfileForPlatform(intake.platform)` (`line 854`). For default `node-ts`, `requiredPlugins` includes `ptah-nx-saas`, `skills.initializer = 'saas-workspace-initializer'`, `skills.architect = 'nx-workspace-architect'`, and `skills.domain = 'ddd-architecture'`.
   - Enables `ptah-nx-saas` in workspace plugin config (`saveWorkspacePluginConfig`, `lines 866-869`) and runs `await this.reconcileHarness('harness:start-new-project')` (`line 877`).
   - **THE BUG**: `registerStartNewProject` never updates `SkillSyncGate` (`{ws}/.ptah/harness/state.json`)! In an empty workspace, `SkillSyncGate.resolve` (`skill-sync-gate.ts:106-123`) returns `{ mode: 'selected', slugs: [], derived: true }`. Therefore, `reconcileHarness('harness:start-new-project')` copies **ZERO skills** into `{ws}/.claude/skills/`!
   - Immediately afterward, `resolveAvailableSkillIds()` (`harness-rpc.handlers.ts:810-815`) calls `workspaceContext.discoverAvailableSkills()` (`harness-workspace-context.service.ts:349-354`), which reads directly from `~/.ptah/plugins/ptah-nx-saas/skills` (NOT `{ws}/.claude/skills`). It reports `saas-workspace-initializer` and `nx-workspace-architect` as active!
   - `buildNewProjectSeedPrompt` (`libs/backend/rpc-handlers/src/lib/harness/harness-constants.ts:178-264`) then emits:
     - `1. Use the saas-workspace-initializer skill and run its Stage A.` (`line 194`)
     - `3. Once discovery is settled, invoke the ddd-architecture skill to name the bounded contexts, then the nx-workspace-architect skill to derive the library layout from them.` (`lines 245-247`)
   - When the chat session starts with that seed prompt, **none of `saas-workspace-initializer`, `ddd-architecture`, or `nx-workspace-architect` exist in `{ws}/.claude/skills/`**, so `Skill` tool calls for them fail or the model falls back to `orchestration`!

## 6. Description Quality

Evaluation of non-orchestration skill descriptions in `.claude/skills/*/SKILL.md` and `plugins/*/skills/*/SKILL.md`:

1. **`orchestration` monopolizes the trigger space**:
   - `orchestration/SKILL.md:3`: `'Default workflow for any engineering task (feature, bugfix, refactor, docs, research, devops, SaaS init, creative) — phased plan with user checkpoints on subagents or CLI lanes, including X plans, Y implements, Z reviews. Not for multi-vendor second opinions — use tribunal.'`
   - Combined with `PTAH_CORE_SYSTEM_PROMPT` (`ptah-core-prompt.ts:157-160`: *"CRITICAL: orchestration is the DEFAULT entry point for all engineering work... follow the orchestration workflow BEFORE writing code or planning directly"*), `orchestration` captures 100% of user prompts at turn 0.
2. **Over-suppressing negative clauses (`"Not for ..."`) and narrow jargon**:
   - `nestjs-backend-patterns/SKILL.md:3`: Framing as *"NestJS backend architecture for multi-tenant SaaS... Not for retries, events or dynamic modules — use resilient-nestjs-patterns"* causes agents working on single-tenant NestJS apps (like `ptah-license-server` endpoints or standard services/controllers) to skip it as "multi-tenant SaaS only".
   - `resilient-nestjs-patterns/SKILL.md:3`: *"Persistence, auth, RBAC and repositories are nestjs-backend-patterns. Webhook plumbing is webhook-architecture."* Narrowly triggers on "orchestrator service", "retries", "SSE", or "forRoot/forTesting".
   - `humanize-library/SKILL.md:3`: *"Use when asked to humanize, clean up, split large files or remove duplication at a path. Not for new features or bug fixes."* Users say "refactor this service" or "break up this god class", which routes to `orchestration`'s `REFACTORING` strategy (`strategies.md:122-151`) rather than `humanize-library`.
   - `saas-platform-patterns/SKILL.md:3` & `webhook-architecture/SKILL.md:3`: Mutually exclude each other (`"Not for webhook plumbing"`, `"Not for billing or subscription logic"`), whereas real billing tasks ("integrate Paddle billing") require both.
   - `angular-3d-scene-crafter/SKILL.md:3` & `angular-gsap-animation-crafter/SKILL.md:3`: Require `@hive-academy/angular-3d` / `@hive-academy/angular-gsap` in the description, never triggering on generic Three.js/GSAP requests unless that package is named.

## Root causes

1. **`PTAH_CORE_SYSTEM_PROMPT` enforces `orchestration` as a mandatory gate before any code or planning (`ptah-core-prompt.ts:155-202`)**:
   - The main agent is forbidden from writing code or planning directly (`lines 159-160, 185-190`) and must immediately classify the task and delegate to subagents or CLI lanes. Thus the main agent only ever loads `orchestration` (and `agent-lanes` when spawning CLI lanes).
2. **`orchestration` strategies (`FEATURE`, `BUGFIX`, `REFACTORING`, `DOCUMENTATION`, `DEVOPS`) never route to or assign domain skills (`orchestration/SKILL.md:41-50`, `orchestration/references/strategies.md:29-256`, `agent-catalog.md:58-92`)**:
   - Outside `SAAS_INIT` (`strategies.md:277-382`), zero strategies mention any domain/pattern skill. `REFACTORING` (`lines 122-151`) never mentions `humanize-library`; `DEVOPS` (`lines 208-255`) never mentions `nestjs-deployment`; `FEATURE` (`lines 29-88`) never instructs `software-architect`, `team-leader`, `backend-developer`, or `frontend-developer` to load stack skills.
3. **Subagent role templates forbid loading unassigned stack skills (`_shared/tooling-precedence.md:18-24`) and omit skill references (`frontend-developer.template.md`, `backend-developer.template.md`, `software-architect.template.md`, `devops-engineer.template.md`)**:
   - Every `.claude/agents/*.md` file (lines 29-30) explicitly tells the subagent *not* to load a skill just because the repository uses that stack, and its `Method` section instructs it to copy 2–3 sibling files instead (`backend-developer.md:93-146`, `frontend-developer.md:97-155`). Only `ui-ux-designer.md:57,61` instructs its role to load its matching skill.
4. **Triple-Gate Delivery Block prevents skills from reaching `{ws}/.claude/skills/` in new or unconfigured workspaces**:
   - **Gate A (`plugin-loader.service.ts:346,370,390,400`)**: `ptah-nx-saas`, `ptah-angular`, `ptah-dotnet`, and `ptah-react` have `isDefault: false` (`plugin-activation.ts:183-189`).
   - **Gate B (`skill-sync-gate.ts:106-123` & `harness-manifest.builder.ts:506-531`)**: Unconfigured workspaces default to `{ mode: 'selected', slugs: [] }`, syncing **zero skills** to `{ws}/.claude/skills/`.
   - **Gate C (`harness-rpc.handlers.ts:844-885`)**: `harness:start-new-project` enables `ptah-nx-saas` and generates a seed prompt naming `saas-workspace-initializer`, `ddd-architecture`, and `nx-workspace-architect`, but forgets to update `SkillSyncGate`, leaving `{ws}/.claude/skills/` empty when `reconcileHarness` runs!
5. **`technical-content-writer` subagent shadows the `technical-content-writer` skill (`.claude/agents/technical-content-writer.md:1-14`)**:
   - `orchestration` dispatches documentation/copy tasks to `Task(subagent_type="technical-content-writer")`. Unlike `ui-ux-designer.template.md:47,51`, `technical-content-writer.template.md` never instructs the subagent to load the `technical-content-writer` skill.
6. **Wizard agent generation (`content-generation.service.ts:381-416, 632-648`) ignores `invocablePluginSkills`**:
   - `buildAllSectionsPrompt` appends `## Available Plugin Skills` to `systemPrompt` (`lines 639-646`) but constrains all output bullets to repository file paths (`line 391`) with no prompt instruction to wire skills into the generated agent sections.

## Recommended fixes

1. **Fix `harness:start-new-project` skill sync gate (`libs/backend/rpc-handlers/src/lib/handlers/harness-rpc.handlers.ts:860-879`)**:
   - Before calling `this.reconcileHarness('harness:start-new-project')`, ensure the profile's skills (`profile.skills.initializer`, `profile.skills.architect`, `profile.skills.domain`, and all skills from `newlyEnabled` bundled plugins) are added to `SkillSyncGate` (or set `skillSyncGate` to `'all'` when initializing a new project) so `reconcileHarness` actually writes `saas-workspace-initializer`, `ddd-architecture`, and `nx-workspace-architect` to `{ws}/.claude/skills/`.
2. **Wire skill loading into agent templates (`libs/backend/agent-generation/templates/agents/*.template.md` & `.claude/agents/*.md`)**:
   - In `libs/backend/agent-generation/templates/agents/_shared/tooling-precedence.md:18-24`, replace the over-restrictive prohibition (*"does not load a skill because this product's repository uses that stack"*) with positive guidance: when no skill is explicitly assigned, load the domain/pattern skill(s) matching the task's stack and layer before designing or editing.
   - In `technical-content-writer.template.md`, add the same skill-loading mandate that `ui-ux-designer.template.md:47,51` has: load `technical-content-writer` (`SKILL.md` and `references/`).
   - In `frontend-developer.template.md`, `backend-developer.template.md`, `software-architect.template.md`, and `devops-engineer.template.md`, map stack cues to skills (e.g., Angular → `angular-frontend-patterns` / `angular-gsap-animation-crafter` / `angular-3d-scene-crafter`; React → `composition-patterns` / `react-best-practices` / `react-nx-patterns`; NestJS → `nestjs-backend-patterns` / `resilient-nestjs-patterns` / `webhook-architecture` / `saas-platform-patterns` / `nestjs-deployment`; Nx/DDD → `nx-workspace-architect` / `ddd-architecture`; refactoring → `humanize-library`).
3. **Add skill-routing rules to `orchestration` (`plugins/ptah-core/skills/orchestration/SKILL.md` & `references/strategies.md`, mirrored to `.claude/skills/orchestration/`)**:
   - Require `software-architect` and `team-leader` to include a `Required Skills:` line in every phase brief / `Task()` / `ptah_agent_spawn` prompt.
   - Reference `humanize-library` in `REFACTORING` (`strategies.md:122-151`) and `nestjs-deployment` in `DEVOPS` (`strategies.md:208-255`).
4. **Emit skill assignments during agent generation (`libs/backend/agent-generation/src/lib/services/content-generation.service.ts:381-416, 632-648`)**:
   - Update `buildAllSectionsPrompt` so `## Available Plugin Skills` instructs the generator to name matching skills from `invocableSkills` in the generated role instructions.
5. **Remove `execute-phase-gated-task` from `.claude/skills/` and clean up `impeccable` in `PTAH_LANE_POLICY` (`cli-adapter.utils.ts:428`)**:
   - Delete `.claude/skills/execute-phase-gated-task/` (already in `RETIRED_MANAGED_SKILL_SLUGS`) and replace `impeccable` in `cli-adapter.utils.ts:428` with an existing skill (`frontend-design`).

## Decisions

- Ranked root causes by runtime impact: (1) `PTAH_CORE_SYSTEM_PROMPT` + `orchestration` delegation funnel, (2) absence of skill routing in `orchestration` strategies and agent templates + `_shared/tooling-precedence.md` suppression, and (3) `SkillSyncGate` + `isDefault: false` blocking skill delivery in new workspaces.
- Treated `.claude/skills/execute-phase-gated-task` as retired based on `RETIRED_MANAGED_SKILL_SLUGS` in `user-layer-mirror.service.ts:61-65`.

## Unknowns

- Whether `SkillSyncGate`'s default `{ mode: 'selected', slugs: [] }` for unconfigured workspaces (`skill-sync-gate.ts:106-123`) should remain opt-in globally (requiring only `harness:start-new-project` to populate slugs) or default to syncing `ptah-core` skills in new workspaces.
