## Design

### Task index

Keep public `TaskIndexService` API. Coalesce per root/folder with 300 ms quiet period plus fixed 1 s maximum wait. Store bounded relevant-file fingerprints after successful published scans; at watcher flush compare affected folders and skip scan/write/push/timing log for no-op. Deletion is a change; equal mtime/size needs content comparison. Explicit writes/reindex force scan. Failed/offline writes never become published fingerprints. Add internal `task-index-rebuild-queue.ts`, `enqueue(root: string, run: () => Promise<RebuildResult>): Promise<RebuildResult>`, with global two-root cap, fair root queue, one trailing request/root, bounded queue and disposal. Preserve retry backoff. Aggregate path classes, queue wait/depth and slow stages without paths. Keep synchronous SQLite until measurements implicate it. Failure leaves dirty folders queued for retry. Acceptance: unchanged child events cause zero replaces; edits/deletes refresh within cap; bounded root concurrency.

### Git

Preserve `getGitInfo(workspacePath): Promise<GitInfoResult>` and root policy. Move existing TTL/generation/flight state into small internal `git-info-read-cache.ts` behind facade; do not add a second handler cache. Keep 2.5 s success TTL initially, bound entries to recent roots, never cache unavailable outcomes, preserve mutation/watch invalidation. Count cache hits, joins, invalidations, duration and roots without paths. `git:watchRoots` renewal cannot be cached away. In `SessionGitStatsStore`, treat valid push as fresh, gate forced reads by active visibility, collapse duplicate roots. In `ChangeSetStore`, reconcile active/visible sets or at turn end using fresh snapshots. In `GitRootWatchLeaseService`, unchanged normalized set must not rearm debounce; retain renewal/backoff/disposal. Failure retains last indicator plus unavailable state and explicit-read fallback. Acceptance: one pipeline for concurrent same-root reads; hidden tabs stop polling; mutation/push/lease refresh promptly.

### Resume

Preserve `chat:resume` reply, page/cursor, `adoptFollowUps`, `ptahUiFence`. Time each existing host stage. After account/folder checks, start independent `readForResume` and `getCliSessionsForRestore` concurrently; join before registry restoration/reply. Keep `awaitRecoveredOutput` before exposing CLI cards unless measured delay warrants a separate readiness contract. Explicit activation retains SDK path; ordinary switch remains lazy until send. Renderer keeps `session:load` before tab/fence and `chat:resume` before authoritative replay. Paint tab shell after load while resume runs, preserving targeted compaction content; measure load/resume/replay events/first paint. Check stale claims before state writes. Do not paint session-load messages as final transcript: JSONL events are authoritative (`chat-session.service.ts:2391-2395`). If JSONL dominates, optimize `ChatHistoryReadService` as measured follow-on. Failure retains folder distinction, read-only activation refusal, partial replay cleanup, follow-up adoption and fence ordering.

### Timing and identity

Add `chat-admission-timing.ts` internal helper `measure<T>(stage: Stage, operation: () => Promise<T>): Promise<T>` recording monotonic duration in `finally`. Emit one bounded summary for start/resume: capped finite ms, stage enum, result class, queue depth. Instrument account gate, MCP registration, prompt/runtime preparation, SDK adapter start and resume stages at await sites. Never include prompt, account, path, session ID, secret or raw error. Propagate failures. Electron `main.ts` logs `app.getVersion()`, channel, validated build commit via injected Logger after bootstrap; regular build metadata only through verified packaging pipeline, otherwise explicit `unknown`. Never spawn git at runtime. **DI/guards:** no injectable service, RPC method or public contract added, so `tokens.ts`, `registration.ts`, `container.smoke.spec.ts`, `expected-resolvable.ts`, `rpc-surface.spec.ts`, `surface-composition.spec.ts` need no edits; if scope changes, update affected registration/guards in that batch.

## Risks

- Equal-mtime edits/deletes can evade weak fingerprints; content check ambiguous cases and test delete/recreate.
- Global queue can starve roots; fair order and queue-wait timing. Synchronous SQLite may still stall; move only if stage evidence identifies it.
- Git TTL can show stale status between pushes; mutation invalidation/visibility return refresh. Lease renewal independent of visibility.
- Early shell must not show stale history; CLI checkpoint and follow-up routing settle before success.
- Source cannot explain installed 109 s gap until installed commit/version is known.
