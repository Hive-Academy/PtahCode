## Decisions

| Decision | Options and evidence | Reversible |
| --- | --- | --- |
| Reuse the persisted owner | The backend already enforces owner identity on state and resume requests. An additive DTO field keeps legacy unbound checkpoints readable. A host that omits the owner for a bound checkpoint can refuse retry visibly. | Yes |
| Keep the 200 most recent dismissal markers globally | A per-workspace cap grows with the number of workspaces. A global cap applies to both persisted and in-memory markers. A dismissal can age out after 200 newer markers. | Yes |
| Reuse the pinned legacy load RPC | Current hosts supply metadata without loading results. For older hosts the existing filename lookup provides the manifest identity and preserves the current load behavior, which can update the workspace’s analysis link. | Yes |
| Re-run discovery after overlapping Retry | The existing coalescer shares pending work. Waiting and then refreshing lets reconciliation qualify freshness against records inserted after the earlier request began. | Yes |
