**Plan deviations**:
- `listState` type: B5 (store) has not landed. `ReviewLaneListState = 'idle' | 'loading' | 'ready' | 'error'` is exported from `review-lane-options.ts` and matches the plan's union. A store literal union of the same members is assignable.
- `saveError` drives the duplicate row lines (`showDuplicates` on the pool). The plan gives the section `saveError` as the lanes error (`store.lanesSaveError`). Duplicate lines show only while that error is set, as in the prototype. The store clears it on the next draft edit (plan C10).
- The helpers keep "Lane default" and "Follow the pool" as the `NO_CHOICE = ''` select value and convert to `null` / no pin on emit. `ptah-select` treats a `null` value as "nothing selected", so `null` cannot be the option value. Lane and model ids never are empty (schema regex), so `''` cannot collide with a real id.
- `idle` renders the content with Status unknown (no listing) instead of a skeleton. Only `loading` shows the skeleton, so the section never sticks on a skeleton if nobody calls `loadLanes()`.
