## Verdict

**FAIL — 5/10.** The change lets a parent recover a child that created its task after start, but the fallback accepts unrelated tasks and can authorize a replacement checkout. It also expands the set of live coordinators that can share one worktree.

## Findings

1. **Major — `session-spawner.service.ts:725` — Bind the task to the target child.** A child starts without a recorded ID, creates task A, and ends. Its checkout also contains task B from the branch's base commit. The parent can attach against that child using B, and the new record is labeled B. An empty directory or regular file named B passes the same check. A symlink at B, `.ptah/specs`, or `.ptah` can make an entry outside the checkout satisfy it. Capture the task ID from an attributed task-creation event and verify the binding for attach. If filesystem evidence is also required, require a real directory under the canonical checkout's specs directory and a valid matching task record. Directory and containment checks alone still admit a stale task B.

2. **Major — `session-child.registry.ts:337` — Tie the child to the original checkout.** Parent A's unrecorded child ends and its registry entry remains. The user removes that worktree and deletes its branch. Parent B starts a new child with a recorded task on the same branch, which provisions the same deterministic path. Parent A can supply its old child ID and B's task ID. The stored path, current realpath and Git branch all match, and B's task directory passes the fallback. The ownership check authorizes the old child record while the start opens B's replacement checkout. Store and verify a checkout identity that changes on recreation, or invalidate the old record when its checkout is replaced. The recorded-ID path already relied on path identity, but it did not allow A's unrecorded target to authorize B's task.

3. **Major — `session-spawner.service.ts:717` — Reserve the worktree before admitting an unrecorded attach.** A parent can attach to a still-live unrecorded coordinator as soon as its task directory exists. Even after that coordinator ends, two requests targeting it can both provision and start if there are two free global slots. Each request can select a different existing task directory, so two live coordinators can write to the same checkout under different task IDs. Recording the ID on each new child leaves the original target eligible for both requests. The existing recorded-task spec already allows concurrent coordinators for the same task. The new path extends that behavior to unrecorded targets and different tasks from a single target. For this fallback, check for any live coordinator in the canonical worktree and claim a per-worktree reservation synchronously before provisioning. Release the claim on failure and hold it through live registration.

4. **Minor — `session-spawner.service.ts:725` — Recheck the target after the filesystem wait.** An attach can reach the new asynchronous lookup, then the parent can clear the eligible ended target before the lookup finishes. The attach still proceeds using the earlier registry result. The recorded path already carries a registry snapshot across asynchronous work. This fallback adds another wait after the registered path has been verified. Recheck target registration, owner and checkout when committing admission, and cover the case with a deferred filesystem result.

5. **Minor — `session-spawner.service.ts:684` — Report the check that actually failed.** If the caller supplies the wrong branch and that branch has no worktree, the new branch-specific diagnostic is bypassed. The response says the registered attach worktree no longer exists even though the target's checkout still exists. The new spec's identity `realpath` mock lets the request reach the branch check in this case. Validate the registered target's branch before resolving the requested branch's path. Distinguish a missing task directory from other lookup errors as well. For example, the new `access` rejection handler reports an inaccessible directory as missing.

6. **Minor — `session-spawner.service.spec.ts:604` — Verify the canonical prefix and use real filesystem cases.** The positive fallback tests would still pass if the check looked in the workspace root or another checkout, because the fixture accepts any path with the expected suffix. The mock also misses the difference between a directory, a file and an external symlink. Assert the full canonical path and add filesystem cases with the requested ID present only in a different checkout and with a task entry resolving outside the checkout. At the service boundary, exercise the unrecorded fallback with a valid proof but a different owner or checkout, and require the expected refusal code.

## Checked and fine
