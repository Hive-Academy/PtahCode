## Root cause(s)

1. **No current Electron lane-default persistence defect proven — code-backed, not app-confirmed.** The awaited write and reload use the same user/global key (`agent-rpc.handlers.ts:1085-1092`; `electron-workspace-provider.ts:94-105,216-236`; `file-settings-manager.ts:622-627`). Valid saved choices outrank legacy and built-in choices (`cli-lane-defaults-config.ts:43-51`; `cli-lane-policy-resolver.ts:78-97`). The proposed causes of legacy winning over a saved row, workspace shadowing, schema coercion, permission-only save, and the select ignoring its saved row are contradicted by this code. The exact failure boundary needs an affected installation's write response, immediate and post-restart read responses, and settings file. No source-backed unconditional Plan reset was found.
2. **Conditional legacy fallback — code-backed.** If the new Codex row is absent and an *explicit* legacy `read-only` remains, `agent:getConfig` reports Plan (`cli-lane-defaults-config.ts:43-51`). That would mean the new row was not durably saved or was removed; it is not precedence inversion. Built-in legacy is `danger-full-access` (`file-settings-keys.ts:351-352`).
3. **Potentially misleading separate display — code-backed, conditional.** The provider card's “Current CLI mode” badge uses fixed `cliPermissionNote`, not saved defaults (`cli-provider-card.component.ts:86-99`; `cli-matrix-rows.ts:399`; `cli-permission-notes.ts:120-126`). It may disagree with the selector. Codex's fixed badge is “Full auto” (`cli-permission-notes.ts:31-35`), so this alone cannot explain a universal Plan display.

The permitted focused Jest command for `file-settings-manager.spec.ts` was attempted. Jest warned it could not load the ES module `jest.config.ts` and produced no result before interruption. No test is claimed passed.

## Proposed minimal fix

1. **If a post-restart key loss is confirmed:** capture `agent:setConfig`, immediate `agent:getConfig`, post-restart `agent:getConfig`, and both keys in Electron `settings.json`. Fix the first failing boundary in `electron-workspace-provider.ts` or `file-settings-manager.ts` (:94-105/:216-236 and :622-627/:711-735 respectively). Add `libs/backend/platform-electron/src/implementations/electron-workspace.file-routing.spec.ts` case “persists non-Plan CLI defaults across provider reconstruction” and `libs/backend/rpc-handlers/src/lib/handlers/agent-config/cli-lane-defaults-config.spec.ts` case “saved Codex row outranks explicit read-only legacy after reload”. Do not change precedence speculatively.
2. **If the reported control is the separate badge:** change `cli-matrix-rows.ts` and `cli-provider-card.component.ts` to derive the displayed default from the saved pair or label the fixed badge as CLI capability. Add `cli-provider-card.component.spec.ts` case “saved default is distinguishable from fixed capability badge”.

## Decisions

- Electron is the priority host. Both lane keys are global file settings; two workspaces share them.
- The Settings lane-default selector is the likely subject because it directly exposes the four named choices. Chat Autopilot is a separate `config:*` path.
- No source file was changed; an unobserved failure is not presented as confirmed.
