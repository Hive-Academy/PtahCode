# Built-in tool denial in headless coding CLIs

Research date: 2026-11-14. “Headless” means a prompt or RPC/ACP run without a terminal permission dialog. A deny rule can block a call while still leaving the tool visible to the model; an excluded tool removes it from the model's choices. Vendor documentation is current online documentation unless a version is named. No agent session was started.

Codex has an important limit: the current [config reference](https://developers.openai.com/codex/config-reference) says `features.unified_exec` opt-outs are ignored, so disabling that feature is **not confirmed** as a shell denial. A vendor [issue](https://github.com/openai/codex/issues/60069) reports `include_apply_patch_tool=false` is now ignored; it must not be treated as a reliable edit denial. Sandbox selection restricts where commands run, not whether the built-in command tool is offered.

## Current adapters and smallest integration point

The [phase 2 handover, §3.1](phase2-handover.md) says Codex, Cursor, Copilot, OpenCode, Grok, and Antigravity filter only Ptah MCP tools through a lane token; Pi filters nothing. Current [status logic](../../../libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/lane-mcp-credentials.ts) marks non-Claude denials filtered only when every requested name begins `ptah_` (lines 39–61). Built-in names therefore remain `unfiltered`. Its token issue path (line 94) carries Ptah denials. This matches the handover.
