## Behavior
- No Antigravity print/prompt execution remains in these files. The CLI stage returns `cli-unavailable` with `source-unavailable` detail and never invokes the injected CLI reader, fallback runner, process executor or failure cache. Repeated reads still consult OAuth and local discovery.
- Final unsuccessful readings expose typed `sourceFailures` entries containing only source, existing reason code, cause and optional HTTP status. Causes distinguish missing token file, invalid grant, HTTP rejection, schema mismatch, timeout, missing local server and account mismatch. The injected Logger receives those same safe fields at debug level. Tokens, emails and raw responses are never included.
- An absent token plus absent local server returns an explicit unresolved reading (`service-unavailable`, empty windows, `windowSetEstablished: false`) with both causes. An opted-in CLI stage additionally records its explicit unavailable cause. CLI unavailability cannot overwrite the primary direct-source reason.
- Invalid grant remains `unsupported-auth` and stops subsequent sources. Account mismatch remains `account-unverified`; existing local account proof and active-store checks are retained. Complete OAuth windows still suppress local/CLI fallback.
- The chain cap is 11,000 ms. OAuth and local stages retain smaller 3,000 ms caps linked to the remaining chain budget and caller cancellation. The OAuth reader's standalone 10,000 ms cap also includes file loading and refresh retries; retries do not start a new timer or recursively reset the deadline. Stage controllers abort in cleanup. No CLI child is started. The shared outer 12,000 ms policy is unchanged.
