## Design

Add `libs/shared/src/lib/types/phase-contract.types.ts`, export it from `libs/shared/src/index.ts`, and add it to `index.zod-free.spec.ts`. It contains only types and an `as const` array; Zod stays in lane-routing. Existing carrier version stays 1 (`task-spec.contract.ts:19-22`).

```ts
export const PHASE_CONTRACT_VERSION = 1 as const;
export const PHASE_KINDS = ['plan','architecture','implement','review','document-review','research','tests','docs','visual-review','design','batch','completion'] as const;
export type PhaseKind = (typeof PHASE_KINDS)[number];
export interface PhaseDefinitionV1 {
  readonly version: 1;
  readonly kind: PhaseKind;
  readonly input: readonly string[];
  readonly deliverable: readonly string[];
  readonly verdict: readonly string[];
  readonly acceptanceStep: readonly string[];
  readonly requiredCapabilities: readonly string[];
  readonly toolProfile: { readonly disallowedTools: readonly string[]; readonly permission: 'allow' | 'deny' | 'prompt' };
  readonly discipline: { readonly method: string; readonly outputContract: string; readonly returnValue: string; readonly refusals: string; readonly escalationProtocol: string; readonly reviewerStance?: string };
}
```

The serialized form is one `phases/<kind>.md` file per kind, with YAML frontmatter matching the interface's scalar/list fields and Markdown headings `## Method`, `## Output contract`, `## Return value`, `## Refusals`, `## Escalation protocol`, and (for `review`, `document-review`, `visual-review`) `## Reviewer stance`. **No tracked role title appears in any `phases/*.md`.** This conveys the discipline without naming its former owner. Tool names use the SDK forms in `libs/backend/agent-generation/src/lib/services/subagent-tool-allowlist.ts:9-23`: exact name or server name, no bare `*` or partial wildcard. `disallowedTools` has the existing deny semantics. `permission` is a host-neutral intent: `allow` and `deny` map to the existing CLI permission decisions (`libs/shared/src/lib/types/agent-permission.types.ts:59-69`); `prompt` means the host's existing approval flow. Phase 2 must translate this to each executor and must not claim a CLI applies Claude-specific deny entries; Phase 1 only resolves the profile. No broad `allowed` list or new permission vocabulary.

Add `libs/backend/lane-routing/src/lib/contracts/phase-definition-resolver.ts` and export it from `libs/backend/lane-routing/src/index.ts`. Signature: `resolvePhaseDefinition(kind: PhaseKind, readDefinition: (kind: PhaseKind) => string): { text: string; toolProfile: PhaseDefinitionV1['toolProfile']; definition: PhaseDefinitionV1 }`. The caller supplies file content. Parse via `gray-matter` with `const MATTER_OPTIONS = { language: 'yaml' } as const` on **every** call (`libs/backend/task-specs/src/lib/task-frontmatter.ts:104`; `libs/backend/output-styles/src/lib/output-style-frontmatter.ts:27-40`), then strict Zod validation and heading extraction in the router. The workspace already has gray-matter; lane-routing has no package-local `package.json` (`libs/backend/lane-routing/project.json:1-7`).
