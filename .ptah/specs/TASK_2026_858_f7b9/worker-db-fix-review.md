# Review of 99f9901c7: worker main database

**Verdict: REVISE — 6/10.** The tier change fixes the successful startup path, but a failed open still leaves the worker advertising readiness, and the added test does not establish that a database was opened.

## Findings

1. **High — Database failure is invisible to readiness.** `activateThoth` catches an open or migration error, logs it as non-fatal, and leaves `sqliteConnection` null (`libs/backend/cli-engine/src/lib/bootstrap/thoth-runtime.ts:116-130`). `serveCommand` passes only the in-memory SQLite check to readiness (`libs/backend/worker-host/src/lib/commands/serve.ts:176-181`); that check opens `:memory:` (`serve.ts:62-69`), while readiness can still report ready when its checks pass (`libs/backend/worker-runtime/src/lib/readiness.ts:48-60,148`). The account store converts a closed connection to `unavailable-storage` (`libs/backend/auth-providers/src/lib/accounts/provider-account.store.ts:134-157`). **Change:** make the worker's main SQLite open/migration a required startup check, or add a readiness check using the resolved connection's `unavailable` state with a safe, actionable failure. Do not report ready when named-account admission cannot use its database. Also cover migration and permission failures in a worker test.

2. **Medium — The new assertion does not prove the fix.** The spec's container returns `false` for every `isRegistered` call and resolves every token to the same `sdk` stub (`libs/backend/worker-host/src/lib/commands/serve.spec.ts:93-108`). The assertion at `serve.spec.ts:161-165` would fail with `thoth: 'off'`, because the `activateThoth` lookup would not happen, but it passes without opening or migrating a database: `activateThoth` only calls `openAndMigrate` when that lookup is true (`libs/backend/cli-engine/src/lib/bootstrap/thoth-runtime.ts:116-123`). **Change:** provide a SQLite token mock whose `openAndMigrate` and `close` calls are asserted in order relative to listener startup and shutdown, or run a focused integration case with a temporary `PTAH_DB_PATH` and a fresh `chat:start` that reaches named-account admission.

3. **Medium — A real worker now shares the host's profile database.** `registerThothLibraries` calls `resolvePtahDbPath()` without worker-specific options (`libs/backend/cli-engine/src/lib/thoth/register-thoth-libraries.ts:56-62`), so the default is `~/.ptah/state/ptah.sqlite` when `NODE_ENV` is unset; development/test select their own files and `PTAH_DB_PATH` overrides all profiles (`libs/backend/persistence-sqlite/src/lib/db-path.ts:11-15,34-64`). `openAndMigrate` creates the parent and opens/migrates that file (`libs/backend/persistence-sqlite/src/lib/sqlite-connection.service.ts:195-255`); registration also creates `~/.ptah/models` (`register-thoth-libraries.ts:64-74`). A desktop app on the same machine and profile can therefore use the same database. WAL and a 5-second busy timeout permit normal concurrent access (`sqlite-connection.service.ts:96-103`), but concurrent writes/migrations can still wait or return busy. **Change:** document the shared-path behavior for worker operators, retain the profile and override semantics, and exercise concurrent desktop/worker access if same-machine operation is a supported deployment.

## Confirmed behavior

- **Startup order:** `withEngine` awaits `activateThoth` before invoking the callback (`libs/backend/cli-engine/src/lib/bootstrap/with-engine.ts:390-428`); the listener starts within that callback (`libs/backend/worker-host/src/lib/commands/serve.ts:338-365`). A successful open/migration therefore completes before the first remote `chat:start` can arrive.
- **Shutdown:** the serving callback stops the service on exit (`serve.ts:363-380`), then `withEngine` calls `disposeThoth(ctx.thothRefs)` in `finally` (`with-engine.ts:427-471`), which disposes the embedder client and closes SQLite (`thoth-runtime.ts:208-213`). The registration remains available after a failed open, but `ctx.thothRefs.sqliteConnection` is null in that case.
- **Embedder:** the oneshot tier resolves the registered client before returning (`thoth-runtime.ts:132-146`), but `EmbedderWorkerClient` constructs without spawning (`libs/backend/memory-curator/src/lib/embedder/embedder-worker-client.ts:84-99`). The worker thread is spawned on a request (`embedder-worker-client.ts:194-212`; `libs/backend/cli-engine/src/lib/thoth/cli-embedder-worker-factory.ts:27-36`). This change alone does not download a model or load ONNX. SQLite startup does attempt sqlite-vec loading (`sqlite-connection.service.ts:223-225`).
- **Scope of root cause:** the closed connection is a valid cause of `unavailable-storage` for named/default account selection, because the store reads `connection.db` (`provider-account.store.ts:134-157`). The claim that *every* fresh session fails is broader than the gate: explicit ambient selection exits before an account read (`libs/backend/rpc-handlers/src/lib/chat/session/chat-slash-command-router.service.ts:135-147`).
