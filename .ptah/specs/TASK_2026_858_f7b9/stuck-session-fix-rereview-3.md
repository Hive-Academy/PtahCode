# Stuck remote session fix final review

**Verdict: REVISE — 8/10.** The ownership token fixes F1, and the parent now preserves a transcript-specific error for a single bounded refresh. Concurrent attaches still have a shipped path to the generic client timeout.

## Blocking finding

1. **MEDIUM — A queued attach can still report a hung transcript as `MACHINE_UNREACHABLE`** (`libs/backend/worker-runtime/src/lib/transcript.ts:150-161,263-275`; `libs/worker-protocol/src/lib/frames.ts:48`; `libs/backend/remote-machines/src/lib/machines-rpc.handlers.ts:52-54`). Two concurrent attaches for one session enter the same `refreshing` chain. If both history reads hang, the first fails at about 20 s; the second starts its own 20 s read only then, while its client call timer has been running since its request began. At 30 s the second call rejects `CALL_TIMEOUT`, which `mapMachineError()` still maps to `MACHINE_UNREACHABLE`. `MachinesStore.openSession()` issues an attach without an in-flight guard (`libs/frontend/machines-ui/src/lib/services/machines-store.ts:330-348`), so this is reachable behavior. Bound the entire queued refresh against the caller's remaining timeout, or otherwise preserve the transcript-specific failure for queued callers; cover concurrent hung attaches through the parent mapping.

## Follow-up finding

2. **LOW — The serve test fake still has no pending-acquire model** (`libs/backend/worker-host/src/lib/commands/serve-sessions.spec.ts:87-97`; `libs/backend/platform-core/src/session-driver-lock/kernel-session-driver-lock.ts:90-98`). Its release now preserves entries on a nonce mismatch (`serve-sessions.spec.ts:100-105`), matching the kernel's behavior. Acquisition still resolves immediately, so this fake alone cannot exercise the kernel's shared pending promise. The dedicated transcript race spec covers the foreign pending case (`libs/backend/worker-runtime/src/lib/transcript.spec.ts:367-400`); this is test fidelity, with no observed production defect.

## Resolved findings and evidence

- **F1 resolved:** `Transcript` creates a fresh `randomUUID()` token under module-local `REFRESH_TOKEN` and releases only a held `refresh` entry whose copied owner carries that exact token (`libs/backend/worker-runtime/src/lib/transcript.ts:51-57,187-238`). `KernelSessionDriverLock` copies the owner on acquire and `held()` (`libs/backend/platform-core/src/session-driver-lock/kernel-session-driver-lock.ts:170-177,296-303`); `NullSessionDriverLock` does the same (`libs/backend/platform-core/src/session-driver-lock/null-session-driver-lock.ts:30-36,55-59`). Object spread retains enumerable symbol keys. The kernel's peer holder response uses `JSON.stringify`, which omits symbol-keyed fields (`kernel-session-driver-lock.ts:125-135`); the token remains in-process. A foreign pending refresh with colliding visible owner fields fails closed in the new spec.
- **F2 partly resolved:** The default read bound is now 20 s (`libs/backend/worker-runtime/src/lib/transcript.ts:43-49`), below the 30 s worker call limit. `TRANSCRIPT_UNAVAILABLE` maps to the new shared `MACHINE_TRANSCRIPT_UNAVAILABLE` code and fixed text (`libs/backend/remote-machines/src/lib/machines-rpc.handlers.ts:16-25,40-55`; `libs/shared/src/lib/types/rpc/rpc-error-codes.types.ts:78-79`). The renderer's session error path displays sanitized message text and does not require an exhaustive code match (`libs/frontend/machines-ui/src/lib/components/remote-session-list/remote-session-list.component.ts:415-419`); the store carries the code through (`libs/frontend/machines-ui/src/lib/services/machines-store.ts:98`). The queued case above remains blocking.
- **F3 resolved:** The serve fake deletes only the entry whose nonce matches, for both refresh and drive entries (`libs/backend/worker-host/src/lib/commands/serve-sessions.spec.ts:100-105`).
