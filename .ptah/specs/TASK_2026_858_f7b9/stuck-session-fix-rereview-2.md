# Stuck remote session fix third review

**Verdict: REVISE — 7/10.** The failed-turn classification and bounded refresh chain address the prior findings. The lock ownership check is still not a proof for a foreign pending acquire, and the timeout does not reach the parent as a transcript error in the default timing.

## Blocking findings

1. **HIGH — A foreign pending refresh can still be released** (`libs/backend/worker-runtime/src/lib/transcript.ts:176-215`). A pending acquisition has no `held()` entry, so its new nonce is absent from `before`. `KernelSessionDriverLock.acquire()` returns the pending promise to this caller, and the eventual entry can satisfy the owner comparison if that caller used the same worker owner fields and an `acquiredAt` value in the same millisecond. `new Date().toISOString()` is a millisecond timestamp, not a unique ownership token. In that case this attach calls `release()` on the foreign nonce at line 226. The new race specs give the foreign owner a different label and a fixed older timestamp, so they cannot catch this collision. The process-wide `refreshing` map correctly serializes `Transcript` instances in one module instance; the repository currently has no other production refresh acquire caller. The public lock still permits one, and the stated fail-closed ownership guarantee does not hold. Use a unique acquire token that the lock stores and returns, or a lock API that reports whether this call created the entry; cover a foreign pending acquire with colliding owner fields.

2. **MEDIUM — A hung read reaches the parent as a generic machine failure** (`libs/backend/worker-runtime/src/lib/transcript.ts:43,257-264`; `libs/worker-protocol/src/lib/frames.ts:48`; `libs/backend/remote-machines/src/lib/machines-rpc.handlers.ts:38-51`). The refresh read limit and worker client call limit are both 30,000 ms. The client's timer starts before the worker's history timer, so it can reject `CALL_TIMEOUT` before the worker sends `TRANSCRIPT_UNAVAILABLE`; `mapMachineError()` then converts either code to `MACHINE_UNREACHABLE`. The worker wire layer itself allows `TRANSCRIPT_UNAVAILABLE` (`connection.ts:398-421`), and the client preserves it when received (`worker-client.ts:477-484`), but the default timeout does not give that response room to arrive and the parent discards the distinction. Use a shorter refresh bound and map the transcript code to an actionable parent error; cover the parent attach failure path.

## Follow-up findings

3. **LOW — The serve test lock differs from kernel release semantics** (`libs/backend/worker-host/src/lib/commands/serve-sessions.spec.ts:100-104`). A release with an unmatched nonce deletes the drive entry and returns `released`; `KernelSessionDriverLock.release()` leaves an unmatched entry intact (`kernel-session-driver-lock.ts:224-231`). The fake also resolves acquisition synchronously and cannot model the kernel's shared pending promise (`kernel-session-driver-lock.ts:90-98`). Make the fake preserve a drive entry unless its nonce matches, and add a pending-acquire model where that behavior matters. This is a test fidelity issue, not an observed production regression.

- **F1:** Borrowed held drive locks are not released, and unproven states fail closed. The process-wide chain serializes refreshes across `Transcript` instances in the same module instance. The new owner stamp reduces accidental aliasing but does not prove ownership of a foreign pending refresh.
- **F2:** `session:status` validates both arrays; `idleEngineSession()` requires both to be present and empty. Failed turns with retained background tasks or session crons remain listed as running. The new specs cover both cases.

Snapshot, baseline, and mark reads remain outside this bound, consistent with the targeted refresh fix. The default parent-facing timeout behavior remains blocking above.
