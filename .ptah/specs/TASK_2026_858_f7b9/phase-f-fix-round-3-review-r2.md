## New findings

1. **Serious — Sanitized key collisions can turn an unknown raw event type into an accepted event.** `libs/frontend/machines-ui/src/lib/services/transcript-events.ts:139-153` checks only the sanitized copy; `displayBlockValue` removes bidi characters from keys and overwrites the prior normalized key at `libs/frontend/machines-ui/src/lib/utils/display-text.ts:92-101`. For example, an input shaped as `{id:'e',messageId:'m',timestamp:1,eventType:'unknown',delta:'x',blockIndex:0,['eventType\u202E']:'text_delta'}` has an explicitly unknown raw `eventType`, yet sanitizes to a valid `text_delta` and is returned instead of `null`. Likewise a mistyped raw `id` can be replaced by a valid `id\u202E`. The new test at `transcript-event-validators.spec.ts:474-478` explicitly accepts a well-typed collision, but does not test a bad raw discriminant replaced by a good one. This violates the acceptance rule that unknown event types and mistyped required raw fields are rejected. **Fix:** reject normalized-key collisions before constructing the sanitized object, at least for every checked field and discriminant; then validate the sanitized result. Add tests for an unknown raw `eventType` and a mistyped raw required field followed by colliding keys.
2. **Serious — A rejected approval can expose raw exception details in the UI.** `libs/frontend/machines-ui/src/lib/components/remote-session-view/remote-session-pane.component.ts:237-261` puts `rejection.message` (up to 200 displayed characters) into a `MachinesError` shown on the approval block. `displayText` strips unsafe display characters but does not redact tokens, paths, URLs, or provider response bodies. A transport or SDK rejection containing a credential in its message is therefore displayed verbatim; the test at `remote-session-pane.component.spec.ts:230-241` locks in detailed-message display. This conflicts with the supplied project rule to keep credentials and raw provider errors out of UI-facing contracts. **Fix:** show a fixed, actionable sentence for an unexpected rejected promise (or map a known safe error code); keep raw details in a protected diagnostic channel if needed. Test that a rejection message containing a secret is absent from the rendered block.
