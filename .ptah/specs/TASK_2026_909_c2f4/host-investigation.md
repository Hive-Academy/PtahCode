# Electron host RPC timeout investigation

## Findings

1. **`boot:getReadiness` (four timeouts).** Renderer default is 30,000 ms; only `options.timeout` or the chat admission set overrides it (`libs/frontend/core/src/lib/services/claude-rpc.service.ts:23-41,145-155,174-187`). `BootRpcHandlers` registers the method, whose callback reads synchronous readiness state without awaiting work (`libs/backend/rpc-handlers/src/lib/handlers/boot-rpc.handlers.ts:50-71,78-103`). The method is unconditional in the surface (`libs/backend/rpc-handlers/src/lib/host-profile/manifest.ts:201-208`), registered in `wire-runtime` before `IpcBridge.initialize()` (`apps/ptah-electron/src/activation/wire-runtime.ts:340-344`; `apps/ptah-electron/src/activation/bootstrap.ts:557-567`). **Inference:** late registration and slow handler await do not explain a timeout after renderer load; main-process or renderer event-loop delay and IPC delivery remain hypotheses. **Confidence:** high for code path, low for runtime cause.

2. **`file:pick` (one timeout).** Composer calls it without override (`libs/frontend/chat/src/lib/services/composer-attachments.service.ts:109`), inheriting 30 s (`claude-rpc.service.ts:23-24,145-155`). Host awaits `IFileDialog.openFiles`, then async `fs.stat` (`libs/backend/rpc-handlers/src/lib/handlers/file-rpc.handlers.ts:155-173`); Electron awaits `dialog.showOpenDialog` (`libs/backend/platform-electron/src/implementations/electron-file-dialog.ts:10-35`). A human can take longer than 30 s, so this timeout is a design bug even with a healthy host. Per-call override is `RpcCallOptions.timeout` (`claude-rpc.service.ts:39-41`). **Confidence:** high.

3. **`git:info` on removed worktree.** Handler awaits `GitRootResolver.resolve` before `GitInfoService.getGitInfo` (`libs/backend/rpc-handlers/src/lib/handlers/git-rpc.handlers.ts:217-235`). Probe checks the directory first, and confirmed absence returns `confirmed-not-worktree` (`libs/backend/rpc-handlers/src/lib/handlers/git-workspace-root.ts:80-94`); a near-workspace missing path yields a distinct missing-root error (`libs/backend/rpc-handlers/src/lib/handlers/git-root-resolver.ts:215-253`). Thus confirmed dead roots do not spawn `git status`. Probe failure can produce a bounded retryable error (`git-root-resolver.ts:183-199,288-295`). Live roots reach `getGitInfo`, with same-root single-flight and 2.5 s success cache, then async `git status` (`libs/backend/vscode-core/src/services/git-info.service.ts:974-1019`). **Confidence:** high for path; whether the logged root was confirmed absent is unknown.

4. **Git queue mismatch.** A process-wide gate caps git children at 4 by default, uses FIFO per workspace and round-robin across workspaces, and reserves an interactive slot (`libs/backend/vscode-core/src/utils/exec-git.ts:36-46,195-214`). Its short-call queue wait can be 60 s (`:54-61,757-773`), exceeding the renderer's 30 s. A live-root `git:info` can therefore time out before spawning. Confirmed dead-root requests should not starve live roots; round-robin also prevents one root monopolizing the gate. This is a plausible contributor, not proven for this session. **Confidence:** high for mismatch, medium for causal inference.

5. **`git:watchRoots` failure.** `GitWatchRpcHandlers` registers it and resolves roots (`libs/backend/rpc-handlers/src/lib/handlers/git-watch-rpc.handlers.ts:108-126`); different lease updates serialize behind a running renewal (`:160-165`). A deadline aborts resolution with `GIT_ROOT_PROBE_FAILED` (`:168-190`). Missing roots are rejected; probe failures preserve prior roots (`:128-132,278-291`); a registry exception logs and returns empty (`:296-323`). The renderer's `Object` log does not identify which branch occurred. **Confidence:** high for path, low for observed cause.

6. **`attention:getSnapshot` (one timeout).** `AttentionRpcHandlers` registers it (`libs/backend/rpc-handlers/src/lib/handlers/attention-rpc.handlers.ts:21-39`); synchronous `snapshot` validates params and iterates `coordinator.pendingNotices()` with no await (`:42-72`). It is unconditional in the surface (`libs/backend/rpc-handlers/src/lib/host-profile/manifest.ts:395-400`). **Inference:** delay lies outside awaited handler work; that does not prove a main-process stall. **Confidence:** high for path, low for cause.

7. **Common path.** Electron uses `ipcMain.on('rpc', async ...)` and directly awaits each `RpcHandler.handleMessage` before replying (`apps/ptah-electron/src/ipc/ipc-bridge.ts:532-533,584-603`); dispatcher directly awaits the selected callback (`libs/backend/vscode-core/src/messaging/rpc-handler.ts:210-241`). No serial RPC queue appears in either. **Hypothesis:** a main-process event-loop stall, renderer response processing stall, or IPC delivery delay could affect unrelated methods. Git's Windows process creation has documented synchronous cost, mitigated by executable resolution and child gate (`libs/backend/vscode-core/src/utils/exec-git.ts:480-503,563-575`), but no evidence proves a 30 s stall in this session. **Confidence:** high for no serial queue, low for common-cause attribution.

## Proposed fixes

1. Add a human-scale `timeout` override at `file:pick` in `libs/frontend/chat/src/lib/services/composer-attachments.service.ts`; update `libs/frontend/chat/src/lib/services/composer-attachments.service.spec.ts` (current call assertion at :116).
2. Align the interactive Git queue deadline with the renderer RPC budget in `libs/backend/vscode-core/src/utils/exec-git.ts` or thread an explicit deadline from `libs/backend/rpc-handlers/src/lib/handlers/git-rpc.handlers.ts` through `GitInfoService`; cover with `libs/backend/vscode-core/src/utils/exec-git.spec.ts` and `libs/backend/rpc-handlers/src/lib/handlers/git-rpc.handlers.spec.ts`. Select the exact budget after measuring queue latency.
3. Add correlation timing around `setupRpcHandler` in `apps/ptah-electron/src/ipc/ipc-bridge.ts` and `handleMessage` in `libs/backend/vscode-core/src/messaging/rpc-handler.ts`; cover dispatcher behavior in `libs/backend/vscode-core/src/messaging/rpc-handler.spec.ts`. Distinguish pre-dispatch, handler, and reply delay before changing host scheduling.

## Decisions

- Treat confirmed missing worktrees as terminal root errors, not a backlog source (`git-workspace-root.ts:80-94`; `git-root-resolver.ts:215-253`). Reversible: yes.
- Do not assign all unrelated timeouts to one cause without timing data; boot and attention callbacks are synchronous while IPC dispatch is not serial (`boot-rpc.handlers.ts:68-71`; `attention-rpc.handlers.ts:34-42`; `ipc-bridge.ts:532-603`). Reversible: yes.

## Not found

- No `execSync`, `spawnSync`, `readFileSync`, or `existsSync` loop in the traced `git:info` handler, resolver, `GitInfoService`, or `exec-git` path. Git execution uses async children and a process gate (`git-info.service.ts:3800-3817`; `exec-git.ts:757-773`). This does not rule out synchronous work elsewhere.
- No main-process event-loop trace, Git queue depth, or host receipt/reply timestamps in the supplied renderer evidence; runtime cause of the shared timeouts remains unconfirmed.
