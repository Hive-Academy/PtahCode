## New defects

1. **[MAJOR] On-mode System One figure lookup still returns `null` (0 samples) for all `ptah-cli` lanes, `cursor`/`opencode`, pre-v2 outcomes (`effort: null`), and native-resolved `lane-default` runs (incomplete F1 fix)**
   - **Location**:
     - `libs/backend/lane-routing/src/lib/matrix/outcome-figures.ts:41-61`
     - `libs/backend/lane-routing/src/lib/decision-model/decision-payload.ts:144-146`
     - `libs/backend/lane-routing/src/lib/pipeline/model-refine.ts:431-432`
     - `libs/backend/lane-routing/src/lib/pipeline/model-refine.spec.ts:161` (test blind spot)
   - **Defect**:
     - In `on` mode (`performanceRouting: true`, the default), `scoreChoice` (`libs/backend/lane-routing/src/lib/ranking/score.ts:214, 265`) always produces a concrete `ModelEffort` (`selected.effort`, defaulting to `policyEffort`), so `toOption()` (`libs/backend/lane-routing/src/lib/pipeline/phase-plan.ts:753`) always attaches a concrete `option.effort` (e.g., `'high'`, `'medium'`) to every offered lane option.
     - Meanwhile, `outcomeFiguresFrom` (`outcome-figures.ts:41-61`) stores each run strictly under `[laneId, taskKind, choiceModelOf(summary), sentEffortBucket(summary.effort)]` — without accumulating `(model, '*')` or dual-bucketing `LANE_DEFAULT_MODEL` runs with native `resolvedModel` into `'*'` (unlike `choice-evidence.ts:257-265`) — and its returned lookup (`:58-61`) performs only an exact match with no fallback to `ANY_EFFORT` (`'*'`).
     - As a result, `offeredFigures` (`model-refine.ts:432`) receives `null` for:
       1. Every `ptah-cli` lane (Ollama Code, Kimi, OpenRouter, etc.), whose runs always record `effort: null` (`agent-namespace.builder.ts:650` -> bucket `'*'`) while `option.effort` is `'high'`/`'medium'`/`'low'`/`'max'`;
       2. Every `cursor` and `opencode` lane (`effort: null` -> bucket `'*'`);
       3. Every pre-v2 historical outcome row migrated with `effort = NULL` (bucket `'*'`);
       4. Every `lane-default` option on Codex/Claude whose prior `lane-default` runs natively reported `resolvedModel` (`choiceModelOf` maps them to `resolvedModel`, leaving `[laneId, taskKind, '*', effort]` empty);
       5. Lanes whose past runs were scored at the `(model, '*')` level (e.g., runs at another effort or `max -> xhigh` fallback-mapped runs).
     - In addition, `buildDecisionPayload` (`decision-payload.ts:144-146`) queries only `figuresByChoice.get(figureGroup(option.laneId, model, option.effort)) ?? figuresByChoice.get(figureGroup(option.laneId))`, skipping `figureGroup(option.laneId, model, ANY_EFFORT)`. Even if `outcomes(...)` returned a `'*'` fallback figure, `buildDecisionPayload` would fail to match it, emitting `samples = 0` and dropping it from `state.pastOutcomes`.
     - The new test in `model-refine.spec.ts:161` did not catch this because it passed `{ ...lanes[1], model: LANE_DEFAULT_MODEL, effort: undefined }`, which cannot occur in `on` mode.
   - **Fix**:
     1. In `libs/backend/lane-routing/src/lib/matrix/outcome-figures.ts:41-61`, when `byModelEffort` is `true`, mirror `choice-evidence.ts:257-265`: accumulate each run into `(model, effort)` and (when `effort !== ANY_EFFORT`) `(model, '*')`, and when `summary.model === LANE_DEFAULT_MODEL` with a native `resolvedModel`, also accumulate into `('*', effort)` and `('*', '*')`. In the lookup (`:58-61`), fall back from `[laneId, taskKind, model, effort]` to `[laneId, taskKind, model, ANY_EFFORT]`.
     2. In `libs/backend/lane-routing/src/lib/decision-model/decision-payload.ts:144-146`, fall back in order:
        ```ts
        const byTask =
          figuresByChoice.get(figureGroup(option.laneId, model, option.effort)) ??
          figuresByChoice.get(figureGroup(option.laneId, model, ANY_EFFORT)) ??
          figuresByChoice.get(figureGroup(option.laneId));
        ```
     3. Keep off-mode (`byModelEffort: false`) behavior completely unchanged, and add tests in `outcome-figures.spec.ts` and `model-refine.spec.ts` covering `on`-mode options with concrete `effort` (e.g., `'high'`) against `ptah-cli` / pre-v2 (`effort: null`) rows and native-resolved `lane-default` rows.

2. **[MINOR] `scoreChoice` can promote an unprofiled listed model via an inherited family `'*'` `user` cell**
   - **Location**: `libs/backend/lane-routing/src/lib/ranking/score.ts:222` (interacting with `libs/backend/lane-routing/src/lib/matrix/capability-matrix.store.ts:485-496, 520-528`)
   - **Defect**: Relaxing `score.ts:222` to `if (pair.resolved.parts.evidence === 'prior' && pair.resolved.parts.priorSource !== 'user') continue;` does not check whether the `user` cell belongs to `model.id` itself (unlike legacy `promotedModel` at `score.ts:363`, which enforces `resolved.profileModel === listed.id`). When a listed model has no profile of its own, `resolveIndexed` (`capability-matrix.store.ts:485-496, 520-528`) falls back to `profileModel: '*'`. If a `user` cell exists on the family profile `'*'` (e.g., `80`) while `configuredModel` has its own lower profile (e.g., local evidence `35` or a lower `user` cell `40`), or if an effort-specific family `user` cell `('*', 'high')` beats `('*', policyEffort)`, an unprofiled listed model with zero runs inherits `priorSource: 'user'` from `'*'` and promotes over the baseline without any model-specific override or local evidence.
   - **Fix**: In `libs/backend/lane-routing/src/lib/ranking/score.ts:222`, restrict prior-only `user` promotion to explicit overrides on that model (or effort overrides on `fallback`):
     ```ts
     const explicitUserOverride =
       pair.resolved.parts.priorSource === 'user' &&
       (model === fallback || pair.resolved.profileModel === model.id);
     if (pair.resolved.parts.evidence === 'prior' && !explicitUserOverride) continue;
     ```
     Add a unit test in `score-choice.spec.ts` verifying an unprofiled listed model does not promote solely from a family `'*'` `user` cell over a lower-scoring `configuredModel`.
