## Findings and decisions

1. **D1 fixed live.** The noncooperative initial agent had three denied Reads and a matching `Subagent stopped` line in under one second. No `Gate stop skipped` early-return log appeared for this agent. Its SDK transcript stopped advancing; the background scenario also stopped through the same route. This is direct evidence that the SDK hook session-key correction reaches the monitor state.
2. **D2 fixed live.** Each original case, plus the background retry, has exactly one matching `.handoff.md` record. The original foreground and retry cases followed normal `SubagentStop`; the original background and noncooperative cases followed forced stop. No original-case `Normal exit skipped` or `Gate stop skipped` log appeared. The new `Normal exit skipped: notes gate missing` lines 47446, 48761 and 49198 concern later replacement agents that finished without a budget warning; `subagent-budget-monitor.ts:839` explains that early return. They do not explain the first background case's missing redaction marker.
3. **D3 works for agent-written notes but remains conditional on a Write.** The foreground and sequential background retry show in-place redaction with surrounding notes preserved. In the first background chat, the three-denial stop preceded any notes Write. `subagent-budget-monitor.ts:1646-1649` attempts redaction of the monitor-owned notes path on forced stop, but the file did not yet contain the fake value; `subagent-handoff-files.ts:145-200` returns without a replacement when that file is absent. The later parent-authored consolidated file is outside that path and retained the fake placeholder. This is a coverage and workflow gap for abruptly stopped background agents, not evidence that the agent-written redactor failed. The decision to count scenario 2(d) as failed is reversible if its acceptance criterion excludes the marker when the original agent never wrote notes.
4. **S1 fixed live.** The noncooperative forced stop delivered one full handoff through the queue and a short failure attribution. The UI still displayed one older background agent as running after its parent finished, while its SDK JSONL had stopped updating; this appears to be stale UI state and did not create a replacement beyond the four-call cap.
