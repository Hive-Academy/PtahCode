### Five logic questions

1. **How does this fail silently?** The loopback address looks like a daemon target on paper, but the custom path serializes a valid request without `keep_alive`. See finding 1.
2. **What user action produces unexpected behavior?** Clearing the saved timeout on this custom target does not enable the 60 s daemon cold-load budget. F3's 15 s setting changes the POST's abort budget. See findings 1 and 6.
3. **What input produces a wrong answer?** Treating retry log rows or a wider log window as distinct questions in the same 26 calls can inflate the per-call token estimate. See finding 4.
4. **What happens when a dependency fails?** A failed daemon residency probe yields unknown residency and keeps the warm budget. A timed-out POST is classified separately from a received HTTP error. Invalid JSON or a schema mismatch returns `bad-output`. See `libs/backend/lane-routing/src/lib/decision-model/system-one.residency.ts:54–64` and `libs/backend/lane-routing/src/lib/decision-model/system-one.client.ts:203–237,253–278,289–297`.
5. **What is missing from the requirements?** F2 needs a deadline that also accounts for fallback and queueing. To validate F1's mechanism, the research needs evidence of server-side rendering or traces that attribute prefill tokens to individual questions. See findings 2 and 3.
